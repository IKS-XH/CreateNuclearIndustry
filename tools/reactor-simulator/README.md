# 反应堆 HTML 数值模拟器

这是一个完全离线、无构建链、无第三方依赖的列级数值实验台。它用于比较堆芯布局、尺寸、控制棒、冷/热端口和损伤参数对发热、燃耗、冷却、余热、损伤与融毁倒计时的影响。

它不是 Minecraft、Create 或 NeoForge 的运行时实现。工具中的可变尺寸只服务于 P2 以后和 P1 数值调优的可重复实验；当前 P1 游戏内反应堆仍固定为 `5×5×5`。网页输入不会写回 `P1ServerConfig`，也不会扫描游戏世界或执行导入文件中的脚本。

> **同步状态（2026-08-19）：** `P1-SIMWEB-08` 目标合同已同步到模块化实现、测试、场景、JSON/CSV 导出和离线单文件 HTML；验收记录见 `build/reports/p1/P1-SIMWEB-08.md`。

## 打开

浏览器可能禁止 `file://` 页面加载 ES module，因此推荐在项目根目录启动本地静态服务器：

```text
python -m http.server 8000
```

然后打开：

```text
http://localhost:8000/tools/reactor-simulator/
```

也可以直接用任何不注入脚本的静态文件服务器托管本目录。页面没有网络请求、CDN、遥测或前端框架。

完成验收后也可直接打开 `reactor-simulator-single.html`；该文件内嵌 HTML、CSS 和全部 JavaScript，不需要服务器、网络或同目录依赖。

## 测试

在本目录执行 Node 内置测试：

```text
npm test
```

测试不需要 Minecraft、Gradle、浏览器或网络。它覆盖尺寸/布局校验、四向邻接、控制棒、超频收敛、燃耗、高度同比、端口守恒、冷却剂总容量、损伤、余热传播、卡死和融毁状态机。

## 计算约定

每个横截面位置只能是 `fuel`、`control_rod` 或 `empty`。空列是有意义的阻断：它不持有状态、不发热、不冷却、不损伤，也切断四向反馈、控制和余热传播。邻接只使用北、南、东、西，矩阵按 `z` 行、`x` 列保存。

每 tick 严格按上一个快照读取：

1. 燃料读取相邻控制棒的平均有效插入深度，使用 `(1 - meanDepth)^controlResponseExponent` 作为功率门控；该门控同时作用于孤立燃料和直接相邻燃料反馈簇。
2. 直接相邻的有效燃料形成同步反馈簇，从 `1.0` 开始最多迭代 `256` 轮；变化不超过 `0.000000001` 才算收敛。控制棒不进入燃料间反馈信号，但其深度会门控该簇最终发热与燃耗。
3. 列发热和燃耗乘以 `2 - integrity`；完整度归零时只把倍率封顶为 `2.0`，只要燃料尚未耗尽且正常控制没有把裂变功率压至零，该列仍继续发热、燃耗、冷却结算和失效传播。只有燃料耗尽才从下一 tick 起停止新裂变热、燃耗和失效传播，缓存余热仍按常规冷却账本消散。
4. 反应堆冷却剂总容量是派生值：`(空列数量 + 控制棒列数量) × 反应堆有效高度 × 1000 mB`。初始快照以冷却剂填满该容量，随后分别维护内存中的冷却剂和热冷却剂；两者之和永远不超过总容量。
5. 冷端与热端分别按“合法且互不重复的端口数量 × 单端口上限”汇总，不设置全堆流量上限；冷却转换量受两侧实际输入/接收、逐端口汇总上限、内存冷却剂和可用热量/吸热量共同限制。网页中的端口数量位于“几何与初始状态”，`actualColdIn` 与 `actualHotOut` 仍可在参数区作为独立实验上限调低；默认值为 `10000000.0`，避免把端口数量固定截在 `200.0 mB/t`。热端输出不足时，转换后的热冷却剂会留在内存中；冷端输入不足时，则优先消耗已有冷却剂。因而 `coldIn` 与 `hotOut` 是外部端口实际流量，不要求每个 tick 相等，但冷/热内存池按守恒账本更新。
6. 冷却按当 tick 发热权重分配，再结算净热负荷、完整度损伤和传播。传播使用传播前快照，控制棒收到热量后不会继续传播。
7. SCRAM 只有在布局中至少存在一个控制棒列时才可建立。无控制棒列时请求必须被禁用或拒绝，不能改变发热、燃耗或融毁状态；有棒时可移动棒插入到底并锁定，解除后恢复请求前深度，卡死棒保持原位，插棒后仍有裂变产热才显示“不完整停堆”。已应用布局中的控制棒深度可以在运行中实时调整，模拟不会因此进入未应用状态。
8. 当前 tick 传播触达至少 `meltdownTriggerFraction` 的有效燃料列时创建倒计时；倒计时只增加。已经有效建立的 SCRAM 且该 tick 有有效冷却时可以暂停，不能回退；无控制棒列时被拒绝的请求不能暂停；所有列修复到 `1.0` 才能重置。

燃料库存是 `fuelCapacityPerBlock × internalHeight` 的每列有效高度份等价容量。`burnHoursPerBlock=3`、高度为 1、孤立满功率、无超频时的基础燃耗锚点为 `1 / (3×3600×20)` 份/tick。

## 已知限制

- 不模拟 Create 流体 capability、管道网络、区块加载、红石世界事件、玩家权限、NBT、Ponder、维修物品事务、实际方块扫描、锅炉、汽轮机、辐射或应力输出。
- 网页中的冷却剂端口使用可配置的本 tick 实际冷端输入和热端接收容量；没有方位、距离或管网拓扑模型。
- 冷却剂总容量是按列数和有效高度计算的反应堆内存抽象；初始快照默认为满冷却剂，不能替代 Create 流体 capability、管道库存或外部储罐。
- 控制棒深度是列级独立数值；控制棒组件的渲染、方块实体和游戏内交互不在范围内。
- 传播只表达当前 tick 现场触达，不保存独立传播标记；这是为了保持与服务端设计的快照语义一致。
- 导入会校验 schema、版本、几何、矩阵、深度和快照形状；未知 JSON 字段忽略，缺失可选字段采用默认值。任何失败都不会改变当前页面场景。
- `P1-SIMWEB-08` 完成后，旧场景中的遗留全堆流量键只能作为未知字段被安全忽略；新导出必须省略该字段，并递增规则版本。
