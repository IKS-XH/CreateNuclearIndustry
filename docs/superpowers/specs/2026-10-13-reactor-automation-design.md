# 反应堆自动化接口与烈焰人管理员：首批设计

2026-10-13。状态：用户已明确“采用整份设计稿与推荐参数”，本稿的参数、配方及联锁接法已冻结；对应实施计划已审阅并授权开工，现已交[同级候选4757f27](../../reviews/2026-10-13/reactor-automation-01/CANDIDATE.md)。内部实现、审查和自动证据已登记，当前待集中客户端验收，未合main。

## 1. 已确认的目标和范围

用户希望减少超大反应堆逐棒操作的负担，已选择先完成工业管网，再接反应堆自动控制。本次明确：新增堆壳结构方块“反应堆自动化接口”，烈焰人燃烧室必须通过该接口任职管理员；首批采用统一调棒、恒定发热功率和故障停堆，负载跟随后续接入。用户进一步明确：操作控件必须在烈焰人燃烧室上，不能放在被燃烧室遮挡的接口上。

首批成功标准：玩家安装一只燃烧室即可集中操作整堆，管理员能将新生裂变发热稳定在设定的HU/t附近；缺燃料、冷却短缺或控制失效时退出自动调节并保持停堆请求，故障消退不会自行提棒。现有结构尺寸、裂变/超频、燃耗、卡死、余热及独立红石急停规则保持其边界。

## 2. 安装、任职和交互

### 结构与唯一绑定

- 新增 `reactor_automation_port`，中文名“反应堆自动化接口”。它替代旧准备稿中未实现的 `reactor_control_port` 概念，首批不另外制造管理台。
- 接口替换侧壁非棱边、非角点的一块外壳，外表面朝向炉外。顶面燃料口/驱动器、底面和框架规则保持。
- 每座反应堆可以没有接口；安装时最多一个，多余接口给出成型诊断，避免控制争抢。它不替代唯一仪表端口，也不改变冷热端口和棒列要求。
- Create烈焰人燃烧室直接放在接口炉外侧的相邻一格。燃烧室不计入反应堆外尺寸，不要求远程工具逐棒绑定。
- 接口从现有成型映射取得仪表所有者和全部控制棒列。一只燃烧室只能任职一座反应堆；歧义、未成型或未加载时不取得控制权，不强制加载区块。
- 普通燃烧即可值班，沿用Create原燃料时长和补料交互，不额外扣燃料或要求超级加热。正常燃烧末段FADING与KINDLED均有效，SEETHING也有效但不提供额外控制能力；无燃料的SMOULDERING、空燃烧室NONE不能自动值班。创造燃烧室按实际有效燃烧状态处理。

### 燃烧室上的操作

所有新增世界内控件和管理员护目镜信息均显示在燃烧室的可见表面，仅绑定有效接口时显示；不打开独立GUI。燃料耗尽后仍能查看故障和选择停堆，不能因熄火让操作入口消失；运行调节和复位另校验有效值班。普通喂燃料、机械臂补料及未接入接口燃烧室的Create行为保持。

| 控件 | 含义 |
| --- | --- |
| 模式 | 手动、恒定功率、停堆；默认停堆 |
| 全堆插深 | 手动模式下设为0～100%，一次给所有可动棒相同目标；0%完全提出，100%完全插入 |
| 目标发热 | 恒定功率模式的绝对目标，单位HU/t，默认0；普通滚轮1HU、加速档10/100HU |
| 确认复位 | 独立的Create世界内确认操作；故障恢复后确认一次，返回停堆模式，随后由玩家明确启动 |

逐棒滑块仍保留。在恒定功率模式，逐棒控件只读并显示“管理员控制”；切到手动后恢复逐棒操作。管理员模式切换或全堆命令使旧拖动会话失效，禁止较早的玩家提交覆盖新的控制命令。手动模式只在玩家确认全堆插深时统一写入，随后逐棒修整不会被后台不断重置。

护目镜简洁显示：任职/模式、目标与实际发热、平均实际插深、冷液和热液占比、受控燃料列/总燃料列、卡死棒数、冷却实际结算量和最近调节/停堆原因。现有图标留白合同沿用；完整异常原因可在相关驱动器或仪表处查看，不堆叠成长浮窗。

## 3. 恒定功率调节

目标是新生裂变发热HU/t，余热单独监测，不把缓存热量再次计成发热，也不生成虚构的摄氏温度。首批不读取或绑定锅炉、汽轮机和动力网，不把未来负载跟随的安装要求提前加给恒定功率模式。

管理员使用仪表端口最后一次成功的服务端结算样本与权威快照，默认每10tick决定一次目标，显示用40tick平均值。保护检查每tick执行，不能等待平均窗口才识别故障。

1. 从当前燃料、实际配置、完整度和超频布局计算当前全堆可达范围。使用原纯裂变计算器评估统一棒深，预测只读临时状态，不扣燃料、不结算世界、不改原发热公式或向上取整规则。
2. 在整数百分比棒深中寻找不超过目标的最近可达发热。控制响应指数和并联超频可能使深度—功率曲线非线性，禁止直接把“50%功率”写成“50%插深”。没有完全相等的档位时显示实际可达结果。
3. 正常升功率每次最多提出1个百分点，正常降功率每次最多插入5个百分点；误差在max(1HU/t，目标的2%)内保持目标，避免整数热量引起来回调棒。
4. 达到请求后不继续追求小于离散棒深分辨率的误差。燃料耗尽、组件变化或损伤使可达范围改变时重新评估；目标高于可达上限时显示“已达上限”，不虚增发热。
5. 目标0进入全插入/停堆过程；无控制覆盖或卡死造成的剩余裂变发热必须明确显示，不能用一个总功率字段强行归零。

当前 `ControlRodStateTransitions.applyServerTick` 会在下一tick将可动棒实际深度直接设置到目标，并无独立棒速参数。首批只限制管理员连续下发的目标步长；不改变手动棒运动、原SCRAM瞬时插入或美术插值，也不把后台调节周期描述成已存在的物理棒速。

## 4. 启动、冷却保护与故障保持

### 启动条件

从停堆进入恒定功率前：结构完整且成员已加载；燃烧室有效值班；全部已装有效燃料列有邻接控制棒；没有卡死棒；全部可动棒处于全插入安全基准；冷液至少占共享容量25%，热液不高于75%；冷却吸热配置为正；仪表样本有效；安全红石线路已接通。

未受控燃料列装料即最高功率的现有规则保持。管理员拒绝自动启动并指出位置；若运行中出现未受控列或卡死，插入其余可动棒并报告“无法完全停堆”，不能操纵不存在或卡死的棒。

### 保护依据

监测实际冷/热库存变化、每列有效未排出热量、损伤及正式冷却结算。逐列有效热量使用 `cachedHeatHu - quantizedHeatRemainderHu` 的既有语义，排除整数mB量化产生的安全余数；不把端口额定流量当成管网实际流量。

- 冷液低于15%、热液超过85%，或任一燃料列有效热量达到现行损伤阈值的50%：预警，禁止继续提棒，按降功率步长插棒。
- 现有损伤阈值已达到、出现新的列损伤、冷液不足以承担下一tick的已知热量需求、热液超过95%、卡死/未受控列、融毁倒计时启动、燃烧室熄火或移除、接口/仪表/关键成员失联：立即进入故障保持，不等待正常调节间隔。
- 阈值为0时，任何超过数值误差的有效热负荷按红区处理，避免除零；不修改原热工阈值和事故模型。
- 全插入时实际转化量可能为0，不能因此拒绝所有启动或陷入“必须先有满流量才能提棒”的死锁。启动以真实库存和有效样本检查，逐步提棒，并持续检查热量与库存趋势。
- 停堆不停止外部泵、不清空库存、不消除余热；管理员只控制可动棒和提供安全信号。

### 可布线的失效安全

沿用“最终SCRAM进入仪表端口红石输入”的合同。任职燃烧室提供运行许可红石输出：健康且允许运行时15，停堆、故障、失联或移除时0；玩家经红石火把反相等常闭接法接入仪表端口，失去许可触发高电平SCRAM。未任职燃烧室的红石行为保持原生。

首次取得管理员控制权时在停堆态建立全插入安全基准。管理员手动或恒定功率运行前都要求有效值班与联锁：验证停堆态仪表确实收到高电平，发许可后在限定时间内检查解除；不符合时停在“安全线路未接通/被其他急停保持”。未安装管理员的原逐棒手动操作不新增这一安装要求。独立玩家急停的高电平优先于管理员所有模式。

现有SCRAM下降沿会恢复保存的旧棒目标。新增管理员交接必须原子建立全插入恢复基准并撤销旧拖动；管理员故障保持期间，解除外部信号不能恢复旧提棒目标。只有玩家确认复位、健康条件稳定100tick后才允许清保持，返回停堆模式；再次选择运行才逐步提棒。没有管理员持权时的独立玩家SCRAM保存/恢复规则保持。

接口/燃烧室拆除、卸载、保存重进或结构代际改变均不能自动恢复先前的管理员运行模式；设定值可保留，控制权恢复先进入停堆/故障保持。失联安全信号和保持由仍加载的结构所有者/接口协调；恢复后先建立安全基准，不使用旧世界或旧代际许可，不强载或读取缺失区块。详细tick顺序在实施卡中明确，验收必须覆盖信号消失后的反弹提棒风险。

## 5. 已冻结配置与制造成本

以下为用户已批准的默认值；结构/燃烧室/安全信号规则不能通过把周期设为0而绕过。

| 服务端配置项 | 推荐默认值 | 含义 |
| --- | --- | --- |
| `adjustIntervalTicks` | 10tick | 正常调节间隔，0.5秒 |
| `displayAverageWindowTicks` | 40tick | 显示平滑窗口，2秒；不延迟保护 |
| `maxLiftPercentPerAdjustment` | 1个百分点 | 每次正常提出上限 |
| `maxInsertPercentPerAdjustment` | 5个百分点 | 每次正常插入上限 |
| `powerDeadbandFraction` | 0.02 | 功率死区比例，另有1HU最小量化死区 |
| `maxTargetHeatHuPerTick` | 1000000HU/t | 世界控件可设目标上限，真实可达功率另受布局与配置限制 |
| `startupColdFraction` | 0.25 | 启动/复位最低冷液比例 |
| `startupMaxHotFraction` | 0.75 | 启动/复位最高热液比例 |
| `warningColdFraction` | 0.15 | 冷液预警比例 |
| `warningHotFraction` | 0.85 | 热液预警比例 |
| `tripHotFraction` | 0.95 | 热液故障保持比例 |
| `warningHeatThresholdFraction` | 0.50 | 相对原逐列损伤热负荷阈值的预警比例 |
| `resetStableTicks` | 100tick | 健康条件持续5秒才能人工复位 |
| `controlLeaseTicks` | 20tick | 已加载世界中控制心跳最长租期；已知拆除/熄火即时撤销，不等待租期 |
| `armingTimeoutTicks` | 40tick | 建立安全线路运行状态的最长等待，超时保持停堆 |

配置应检查比例顺序、非负目标、正周期与步长；客户端操作不能突破服务端上下限。实际发热上限保持现有反应堆计算，没有另加全堆物理功率上限。

```text
钢板   电子管     钢板
精密构件 工业传感器 精密构件
钢板   反应堆外壳 钢板
```

总计4钢板、2精密构件、1工业传感器、1电子管、1反应堆外壳，全部已有材料。烈焰人燃烧室单独放置和补料，不消耗进接口合成。

## 6. 实现边界与阶段

反应堆权威状态仍归仪表端口。新增服务端管理员入口验证结构所有者、接口、燃烧室、代际、控制租约、SCRAM和卡死，再一次提交整组棒目标；不伪造玩家或调用有交互距离约束的滑块包接口。模式和设定由接口保存，燃烧室控件只是当前绑定的世界内操作入口，避免在Create燃烧室上复制一套反应堆状态。

通过仅对有效任职燃烧室启用的Create接入提供控件、护目镜与许可红石；未任职、被拆除及解绑后都恢复原行为。真实权威控制使用当前正式结算数据，不能依赖客户端美术L1/L2租约或显示包。复位、输入权限和拖动冲突在服务器验证。

批准后实施按依赖组织：先结构接入/任职与服务端权限，再统一手动控制与安全交接，再恒定功率调节与保护，最后组合验证和集中人工验收。这里只是分工顺序，不先交一个无法安全退出的自动运行版本。

负载跟随后续独立设计：绑定锅炉与汽轮机，结合应力真实负载、压力、蒸汽库存和30%汽轮机门槛；同一动力网和双轴输出去重。旧准备稿的所有输出轴/温压仪表绑定要求仅属于该后续阶段。首批不接管理员动画专项、自动换料、修复、管网压力、事故世界效果、显示链接或旧存档迁移。

## 7. 必要验证与人工验收

- 纯控制用例：非线性反应/超频和向上取整、离散深度死区、升降步长、目标不可达、配置边界、量化余热不误停、零流量冷启动、故障保持与人工复位。
- 服务端真实小堆：可选接口/唯一限制、燃烧室任职、全堆调棒、玩家拖动竞争、燃料停止值班、卡死/未受控列、许可线路实际触发仪表SCRAM、下降沿不反弹。
- 生命周期代表：燃烧室或接口拆除、跨区块失联及恢复、同版本保存重进、代际变化，均不自动提棒且不强载。
- 客户端集中检查：控件确在燃烧室可见表面、喂燃料正常、目标HU和实际发热、逐棒锁定/交接、预警及复位可理解，护目镜图标不遮字。

按治理5.1仅运行定向检查、一次必要增量打包及一轮独立组合审查；同源证据复用，不重跑已验管网、渲染、美术和设备教学，也不要求再手搭16³才证明基本算法。新增接口素材需与美术负责人按既有职责协调，自动检查不能代替新世界操作和视觉验收。
