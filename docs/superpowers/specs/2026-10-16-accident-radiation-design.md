# 事故与辐射系统设计

2026-10-16，主逻辑PM整理。用户已选择“采用整稿与推荐值”，本文的玩法、参数与成本一并冻结；当前进度和独立人工门只在[STATUS](../../STATUS.md)维护。本文是已批准设计，不是已实现功能说明；第一批按[辐射基础实施计划](../plans/2026-10-16-radiation-foundation-01.md)推进。

## 1. 目的与已确认边界

让安全运行、换料和废物封存有可读的风险与收益，事故可处理、基地可恢复。首批围绕反应堆融毁、放射性组件、事故残骸、玩家防护与现有封存链形成闭环。

用户已确认：

1. 默认事故为局部破坏＋辐射污染，保留抢修与重建余地。
2. 辐射只来自实际物料/残骸；移走或屏蔽源后现场强度下降，不另设永久区块污染。
3. 全新燃料不放射，只有工作过的组件及乏燃料有辐射；铀原料、贫化铀材料/装备不作为首批辐射源。事故残骸继承其中已用燃料的辐射。
4. 玩家剂量逐渐积累，先预警，再出现症状和伤害；脱离后自动恢复，首批不要求制药治疗。
5. 已使用的组件在融毁中报废，每组件对应1份事故废料，保存在可回收残骸中。回收后沿现有屏蔽装配台、固化基材、铅桶、干式贮存架封存。
6. 原版掉落状态的裸露已用组件/核废料不自然消失，也不被火、岩浆、仙人掌或爆炸销毁；创造模式和管理员可清除。

屏蔽合同：铅桶削减95%向外辐射，完整贮存架完全屏蔽内部桶，普通箱子不额外屏蔽，完整反应堆外壳对外屏蔽内部源。用户修正后的新燃料/原料源范围及本稿屏蔽参数均已确认，不视为代码已实现。

首批辐射结算对象为玩家。动物、作物、食物污染和生物变异留待后续；现有主管理员、热工、管网压力和DU装备性能保持各自合同。贫化铀候选的手测仍独立，不追认通过。

## 2. 当前代码与接入点

- 已有失冷损伤、传热、融毁覆盖率/倒计时和危险拆除事件。默认覆盖阈值0.20、倒计时900 tick保持；当前事件仅发布，不破坏世界或生成辐射。
- `ReactorMeltdownEvent`携带服务端世界、结构坐标和只读快照，原因分倒计时完成/危险拆除。新事故执行器接此入口，不能另造随机事故判定。
- 端口真实ItemStack拥有组件库存；`FuelColumnState`保存整数燃耗与小数余量。因此已使用判定不能只看整数损伤。
- 现有桶完整封装一件冷却乏燃料，贮存架默认16槽；它们尚无剂量功能。现有`radiation_sensor`只是零件，不是手持仪表。

这些内容以本轮实际源码核对为准，历史固定5³夹具和旧事故产物草案不约束本次新设计。

## 3. 燃料使用历史与辐射源

### 3.1 使用历史

服务端在组件首次实际参与裂变/燃耗的结算中设置“已使用”标记，哪怕尚不足1点整数耐久。仅装入、成型、接冷却剂、打开GUI或承受邻列传热都不算使用。

标记随真实组件保存、取出、机械臂搬运和再次装入保留；正常停机、修复结构、重进世界不能清除。标记属于组件而不是燃料列，换入全新组件不继承上一件的使用历史。组件仍用原燃料ID和原燃耗规则，可继续发热；玩家提示为“已使用燃料组件”，不把它显示成全新燃料。生成乏燃料时保留其放射性身份。

状态只由一次服务端权威结算写入，不在ItemStack、快照和辐射索引中建立三份独立燃料库存；索引只缓存可重建的源信息。不研究旧版本存档迁移。

### 3.2 首轮源强

使用游戏单位D（剂量），场强为D/s，不标注现实医学剂量。以下是单份物料在1格以内、未屏蔽时的参考值：

| 来源 | 源强 |
| --- | --- |
| 全新组件、铀原料、贫化铀粉/锭/块/装备 | 0 |
| 尚可继续使用的已用燃料组件 | 1 D/s |
| 冷却乏燃料组件 | 2 D/s |
| 一份事故废料及承载它的融毁残骸 | 4 D/s |

堆叠和多份载荷按真实数量相加；空桶和空残骸不凭物品名称产生辐射。一个真实载荷只计一次，封装后的内部组件不能再被当成第二个裸露源叠加。

源到玩家的距离为d，距离系数为`1 / max(1, d²)`；默认只查询32格内的源。同一位置物品或玩家自身携带按1格以内处理。先应用容器/路径屏蔽，再累加得到场强，默认上限10 D/s，最后应用穿戴防护得到玩家吸收强度。上限在穿戴计算前，防护仍有实际收益。

### 3.3 屏蔽

| 位置或措施 | 向外辐射比例 |
| --- | --- |
| 普通箱子、木桶、潜影盒、普通背包 | 内部真实载荷原强度，不增加屏蔽 |
| 合法铅屏蔽封装桶 | 内部载荷的5% |
| 完整干式贮存架内的合法封装桶 | 0 |
| 完整有效反应堆外壳 | 对外为0；堆内不视为安全区 |
| 射线路径穿过一格屏蔽混凝土、反应堆外壳或观察窗 | 剩余场强乘0.05，多层相乘 |

桶和贮存架乘数只施加于其真实内部载荷。普通容器中的封装桶保留自身95%屏蔽，但普通容器不再额外减一次。空载荷不放射；校验失败但仍含放射性物料的载荷不能被当成空桶获得零辐射，未满足合法封装条件就不享受屏蔽。破坏架/桶时载荷真实转移，不能既留旧源又产生新源。

完整结构对外屏蔽读取已知边界的外壳完整性缓存，外壳实际出现破口后取消；不能单因停机、缺燃料或堆内融毁就把仍完好的包容外壳当作破口。事故任务保留边界，重新补全外壳也可恢复对外屏蔽，堆内源依旧危险。只有相关方块变更使缓存失效，不每tick或每秒扫描外壳。普通屏蔽墙读取明确的屏蔽方块标签与有限路径检测。高危物流可以用防护服、桶或另建屏蔽房间，不通过禁止普通箱子收纳来强制玩法。

## 4. 玩家剂量与防护

### 4.1 剂量与症状

服务端每20 tick结算一次，剂量默认限制在0～100 D。吸收强度大于0.01 D/s时累积；低于或等于该安全阈值连续5秒后，每秒恢复1 D。重新暴露会结束恢复等待。离线暂停，不用现实时间扣剂量。

| 累计剂量 | 表现 |
| --- | --- |
| 0～不足25 D | 仪表正常显示；出现实际暴露时给一次提示 |
| 25～不足50 D | 明显预警，不扣生命 |
| 50～不足80 D | 虚弱I、缓慢I |
| 80～100 D | 保留上述症状，每2秒造成1点生命值伤害（半颗心） |

症状由真实剂量派生，牛奶不清除剂量；离开危险区后随剂量下降解除。用短时效果刷新症状，不能误删其他来源的药水效果。辐射伤害不由普通护甲防御值抵消，穿戴防护先减少吸收。死亡默认清空玩家剂量，物料辐射保持；创造/旁观不累计伤害剂量，仪表仍显示真实场强，便于管理和测试。

### 4.2 防护装备推荐

新增四件防辐射服，沿用皮甲的基础防御、耐久和皮革修复，首批借用原版皮甲外观。每件按原版皮甲布局添加1块铅板有序合成，共24皮革＋4铅板制作全套，不设滤芯、供电或持续耗材。

| 部位 | 削减吸收强度 |
| --- | --- |
| 头部 | 25个百分点 |
| 胸部 | 30个百分点 |
| 腿部 | 25个百分点 |
| 脚部 | 15个百分点 |
| 全套 | 合计95%，仍吸收5% |

削减按部位相加并限幅，不能通过重复持有或把装备放背包叠加。普通皮甲、DU装备和其他原版护甲不自动获得防护。防护服不屏蔽玩家携带物对旁人的放射，不作为移动屏蔽容器。

### 4.3 测量与提示

用1辐射传感器＋1黄铜外壳＋1玻璃板有序制作手持辐射计。主手或副手持有时，显示“场强D/s、累计剂量D、当前吸收D/s”，采样间隔1秒；可用副手仪表、主手工具清理。提示与计数音按强度节流，阈值预警不依赖一直手持仪表。不新增独立GUI。

燃料、废料和封装桶的物品提示说明使用/屏蔽状态，架护目镜说明外部屏蔽。仪表组件的正式命名/显示均使用玩家措辞，不暴露注册字段或开发状态。

## 5. 融毁、事故残骸与清理

### 5.1 局部破坏边界

事故沿现有事件进入，一次事故立即撤销该反应堆的运行/自动控制权限，停止继续结算原堆功率；燃料、工质、热量随后进入唯一事故账本。不是清空仪表后再从残留端口重新猜产物。

- 堆内已用组件全部报废，每组件1份`accident_fuel_waste`；这包含事故时仍有剩余燃料的已用组件。原来已经是乏燃料的单件载荷也只转换一次。
- 每个对应燃料列底部生成可回收的`reactor_corium`残骸，持有该列一份废料；不按棒的高度复制组件数量。不创建一份载荷同时又保留原端口组件。
- 从未运行过的组件不变成放射性废料，按原件返还。返还位置和分批输出归事故任务管理，不让大量掉落物同tick爆出。
- 已报废列的棒体/相关机构损坏；外壳与紧邻建筑局部破裂。外伸至原结构边界外最多2格，外壳及外部建筑合计最多破坏32格；堆内处理另受最大结构体积约束。基岩等不可破坏方块不改。
- 近距冲击最多8点生命值伤害（4颗心），作用范围同局部破裂范围并随距离衰减；每名玩家在一次事故中至多结算一次直接冲击，不按16³体积无限放大或随分批动作重复扣血。
- **事故时机内冷热工质全部作为事故损失扣除，已有热量记作事故释放/耗散；只产生有限喷放表现，不生成可回收世界流体。** 用户整稿批准已包含这项损失成本。
- 世界动作默认每tick最多64项，按固定计划分批进行，不调用大范围原版爆炸来扫描、连锁破坏或产生海量掉落物。

邻近独立反应堆不直接强制触发融毁；若它的结构或冷却确实被破坏，则继续按它自己的现有热工与事故条件判断。

### 5.2 事故废料封存

残骸采掘返还其中真实事故废料，清理者在接近和回收过程中承受辐射，可穿防护服操作。残骸移除、物品产生、封装三个阶段保持载荷数量，不重复计源。

新增一条屏蔽装配台封装配方：1事故废料＋1现有固化基材＋1空铅屏蔽桶→1封装桶，沿用现有12800工作量。复用`sealed_spent_fuel_cask`身份和载荷结构，容器校验允许“一个乏燃料组件”或“一个事故废料”，不接受任意物品、混装或空载荷。玩家名称可统一为“封装核废料桶”。已有乏燃料封装配方、原料数量和贮存架容量不变。

尚有燃料的已用组件仍按原换料规则使用，不把它纳入不可逆固化配方；维修搬运可穿防护服或在屏蔽空间完成。首批不做从废料回收可用燃料的再处理。

### 5.3 丢弃与管理边界

已确认保护：原版掉落状态的已用组件/乏燃料/事故废料不自然消失，不被火与岩浆烧毁；封装载荷也不能随外壳烧毁而无账消失。仍可正常拾取、转移和进入原版/Create物流。

同时保护这些原版掉落载荷免受仙人掌和爆炸销毁，避免普通伤害成为同样的废物删除捷径；该边界已随整稿批准。虚空、管理员命令、创造删除及第三方虚空设备另列明确支持边界，不承诺拦截任意模组的物品删除。

## 6. 服务端、持久化与性能

### 6.1 源索引与容器

每维度维护按区块定位的辐射源索引，源更新由载荷/结构/容器变更、实体移动和区块生命周期驱动；近玩家低频校验补足普通库存变更。检测半径和每tick工作量有硬上限，不因16³反应堆运行而全世界或全堆逐tick扫描。

首批必须覆盖玩家库存/掉落物、反应堆组件端口、残骸、封装桶/架，以及原版常规容器和Create基础传送带/置物台/机械臂/设备库存。原版嵌套容器和本模组封装载荷不能被当作免费屏蔽，也不能重复读取同一组件。无界嵌套、第三方私有背包/远程仓库等应单列支持清单；实现前确认可读库存入口和预算，不凭“支持任意IItemHandler”宣称完成全部兼容。

完整反应堆对外屏蔽和贮存架屏蔽直接使用有效状态缓存；燃料物理端口与堆源不可双算。射线仅查询相关源及明确屏蔽方块，结构/屏蔽变更使相关缓存失效。不强载区块，玩家不在场时不结算玩家剂量。

### 6.2 事故任务

事故账本独立于即将损坏的仪表端口，至少保存事故身份、结构边界、原始载荷、工质/热量账、目标动作及已完成进度。先建立可恢复任务再施加世界效果；目标替换、载荷移动和返还均可重入。

重复tick、区块卸载、正常保存重进、重复事件和中途停服后不能重复生成废料或重复扣库存。任务跨区块时只处理当前可用部分，未加载部分保留等待；不能为完成事故而强载世界。当前配置修改不重写已排定事故的产物和扣账规则。

新组件标记、玩家剂量和事故进度由服务端持久化；客户端只接收附近提示/必要数值。正常保存加载是本批必要验收，不扩展为旧版本迁移研究。

## 8. 实施批次与验收出口

### 第一批：辐射基础与封存防护

燃料使用标记、源/剂量结算、普通物流和容器、桶/架/外壳/屏蔽墙、防护服与辐射计。直接用现有已用组件和乏燃料验证，不依赖先制造事故。
