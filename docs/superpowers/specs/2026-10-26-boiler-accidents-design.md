# 锅炉多泄压阀与事故冻结设计

2026-10-26。用户已确认整组推荐初值，并选择“危险拆除直接触发事故”；本稿为当前冻结合同，不再重问已确认参数。基准main `8ac21d2e`；实际读取应用minecraft-modding/testing技能，锁定MC1.21.1、Java21、NeoForge21.1.219、Create6.0.10-280、Ponder1.0.82、Flywheel1.0.6。

## 用户已经确定的方向

- 同一锅炉允许多个泄压阀，每个阀有独立排汽速率上限；正上方有方块遮挡时该阀不能排汽。
- 锅炉事故分干烧和超压两种。持续干烧损毁炉内换热器或再加热段。
- 允许短时、小倍率超压；超过瞬时阈值，或超过耐压时间，向随机方向爆炸，损坏方块并伤害周围生物。爆炸范围取决于超压数值。
- 普通/超临界两份库存共享汽容量、纯过滤汽口及现有进出流量规则沿用，不借锅炉事故实现工业管网压力系统。

## 当前源码核对

`BoilerStructure.Form`仅存一个valve，顶面非棱角位置只接受首个，且成型要求至少一个。控制器已经逐tick核阀正上方是否已加载且为空气；目前排汽总额度为汽区格数×32mB/t，而非固定单阀额度。

`BoilerState.demand/reheat/tick`在阀被堵时按90%开阀压力限制继续加热/汽化；水汽都没有时也停止收热，水壁与蒸汽只被加热至现有SC目标温度。炉压由真实两池mB×汽温求和计算，没有显示100%的硬截断，但这些热工限制会阻止正常持续供热形成期望的超压/干烧事故。仅添加事故计时器不能使事故自然发生。

按批准方案将“无条件堵阀/空炉停热”改为事故规则管理：热液按真实可接收HU继续加热炉壁或已有蒸汽，在满汽/堵阀时允许真实付热的继续过热升压；红石停热、热液不足、冷液堵塞仍停止新收热，已存余热不凭空删除。额外温度/压力必须来自已付HU，不能给库存加免费汽量、改写汽种或抬高账面压力。

## 已确认初值与规则

| 项目 | 推荐值/行为 |
| --- | --- |
| 阀数量/位置 | 顶面非边框位置至少1个，数量仅受合法位置限制；各阀独立检查上方1格，只有已加载空气算畅通，未加载不强载 |
| 单阀上限 | 512mB/t；畅通阀额度相加，堵阀只损失本阀能力，不按汽容积放大 |
| 启闭压力 | 保留90%开、80%关迟滞；泄压排到关阀线即停止，不泄成真空 |
| 物料/额度 | 普通/SC按现有实际库存比例扣真实mB/HU，按阀分别记录实际排出量，同tick反复调用不刷新额度 |
| 额定耐压 | 当前归一炉压1.0作为100%额定；护目镜显示可超过100%，出汽下限控件仍0～100%，不是目标压力 |
| 干烧定义 | 炉内水量为0且炉壁温度不低于既有沸点；仅有热液库存但炉体冷却不计危险，停止新热后仍处于高温的余热继续计时 |
| 干烧后果 | 连续400加载tick（20秒）后，随机损毁1个现存炉内换热器或再加热段，不掉完整设备；结构失效撤销供热/交易，原其它设备及唯一库存不被任意清空 |
| 干烧恢复 | 补水或冷却至沸点以下解除干烧计时；已毁部件须实际更换，不自动修复。其当前物料/热量归属沿已验账本，避免损毁一件复制/丢整炉库存 |
| 轻度超压 | 炉压高于100%而低于150%时，累计超压加载tick；到200tick（10秒）触发爆裂 |
| 重度超压 | 炉压达到150%立即触发爆裂，判定在当tick正常出汽/泄压后进行；足额泄压能在同tick避免事故 |
| 耐压恢复 | 暂回100%以下先暂停计时，降至95%及以下持续40加载tick（2秒）才清零，避免临界波动每次重置容忍期 |
| 方向 | 随机选上/下/东/西/南/北中的一面，一场事故只选一次并保存，沿该面向外定向喷爆，不对整个球形范围无差别破坏 |
| 范围 | 令r=实际炉压/额定耐压，半径R=clamp(2+4×(r−1),2,6)格；r=1.5时4格，r≥2时6格，体积不再额外乘倍率 |
| 伤害 | 喷爆方向内按距离衰减，最高16HP、每生物每次事故只结算一次；指向外壳须形成破口，方块按既有抗性/保护边界处理，不摧毁不可破坏块 |
| 事故后的工质 | 真正爆裂时原炉水/双汽/冷热工质损失并停止运行；只发生干烧局部损坏不照搬整炉清空。锅炉事故不生成核废料、熔融物或辐射源 |

相邻供热部件或其它设备受实际爆裂损坏后，走各自真实失效路径，不为锅炉事故另造核事故或直接清其库存。方向/强度/已处理收据先保存后分批动作；断服重进不重抽方向/重新伤害或生成第二次爆炸。世界破坏有界、仅处理已加载位置，不强载；复用既有事故的保护、物品守恒和每维度共享动作预算原则，具体接线在冻结后的实施卡列明，不默认已有反应堆账本可直接承载锅炉。

上述流量、阈值、时长、恢复线、半径/倍率和伤害上限进入锅炉事故配置，跨字段校验和运行时单位明确。现有每格汽区泄压量配置由固定单阀量替代；首发前不研究旧版本迁移。锅炉结构缓存/渲染快照改为阀集合，正常tick只检查已缓存阀口与必要事故状态，不逐tick重扫16³。

## 危险拆除（用户选择直接触发事故）

玩家在已经超压或正在干烧时手动拆控制器或锅炉结构成员，立即触发其实际危险对应的事故，不等自然计时结束。超压优先执行定向爆裂；仅干烧时立即执行干烧换热部件损毁，不额外制造无压爆炸。普通挖掘和潜行扳手两条路径均纳入，仍须在第三方最终取消/权限检查后提交；被保护取消的拆除不得先扣库存或触发事故。

事故提交先单次冻结原炉的状态/原因及收据，再撤销旧能力和运行权限；事故本身的授权破坏不递归触发第二场。控制器可携带数据的现有掉落与新事故不能各保留一份库存；只干烧局部损毁不任意清空整炉物料，具体取件/携带提交顺序沿现有真实账本处理。正常工况拆除规则保持，不把正常热炉一概判为危险。

## 拟分批顺序

实施时先做多阀/固定流量/逐阀遮挡，保留90%/80%迟滞及普通出汽行为，再做真实继续收热、干烧/超压判定及定向爆裂。每批唯一执行者与一次组合窄审，测试按改动风险选已有JUnit及必要真实锅炉用例；原3项主线既有JUnit失败单列，不能隐藏或借此改无关热工算法。新批次携带已保存世界；两步技术验证后集中交付候选，不人为增加重复人工门，用户手测前不提升main正式包。

关键用例包含两阀合流/单阀堵塞/全堵、空气与非空气遮挡、同tick额度与真实HU、水空但冷/高温无水/补水、轻超压恢复/持续超时/瞬时越线、方向保存/保护取消/实体单次伤害、共享预算及正常保存续接；手测集中观察，不为旧存档或未变整线再开完整矩阵。
