## 5. P1 固定规则

以下规则已冻结，执行任务时不得重新解释：

- 首发反应堆固定为 `5×5×5`；不实现可变面积和高度。
- 所有玩家拥有相同交互能力；不加入权限、身份、所有权或玩家绑定。
- `reactor_instrument_port` 是唯一权威状态方块；红石输入只从它触发 SCRAM。
- `control_rod_drive` 不接受红石调节，只接受玩家 Create 风格滑块；烈焰人管理员属于后置功能。
- 反应堆成型后控制棒默认完全插入。
- 高电平持续 SCRAM 只在至少存在一个控制棒列时成立：所有可移动控制棒插入并锁定，低电平恢复进入 SCRAM 前的目标深度。无控制棒列时拒绝请求、不保存恢复值、不建立 SCRAM 状态且不能暂停融毁倒计时；有棒时请求成立，插棒后仍有裂变产热则报告 `SCRAM_INCOMPLETE`。
- 直接相邻燃料的反馈超频只提供有界倍率，并与该列控制棒抑制强度相乘；部分插棒连续降低反馈簇，完全插棒使被覆盖列的新生裂变热和燃耗归零。反馈信号必须读取邻列已经受控制棒门控的有效强度，停止列不能继续提供反馈。
- 每个燃料列独立保存完整度、缓存热量和燃料组件状态；完整度越低，发热和燃耗按相同比例增加；完整度归零时倍率为 2.0，且只要组件尚有耐久并未被控制棒正常压至零裂变功率，该列继续发热、燃耗和向外传播。组件耗尽后才停止该列裂变发热、燃耗和失效传播。
- 损伤只由有效热负荷产生；冷却足够时，即使超频也不降低完整度。
- 热量只沿四向相邻传播；不保存传播标记。燃料列和控制棒列使用相同传播系数，冷却可以阻止传播。
- 控制棒列完整度归零后卡死，保持实际插入比例并继续抑制相邻燃料列，但不向外传播损伤。
- 传播覆盖 `20%` 有效燃料列时建立融毁倒计时；控制棒列不计入分母。
- SCRAM 和有效冷却只能暂停融毁倒计时，不能回退进度；所有燃料列和控制棒列修复完整后才重置融毁状态。
- 完全停机且余热进入安全区后才能破坏性重新成型，清空整个结构 NBT；运行、融毁倒计时和暂停融毁倒计时中拆除任意组件立即融毁。
- 合金钢板右键维修：每次消耗 1 个；目标列必须停止放热；每次恢复 `0.25 / internalHeight`；维修消耗和恢复量不配置化。
- 护目镜动态遥测由服务端最后一个成功完成的反应堆 tick 派生并分层显示：仪表端口只显示冷/热冷却剂当前库存、全堆裂变发热量和实际冷却剂转化速率；换料端口显示其绑定燃料列的完整度与裂变发热量；控制棒驱动器显示其绑定控制棒列的完整度。完整遥测模型仍可包含全部逐列字段，但客户端不得自行重算或扫描结构。
- 全堆与单列“发热量”统一指最后一个已结算 tick 的新生裂变热，单位为 `HU/t`，不把列缓存余热重复计入发热；“冷却剂转化速率”指该 tick 实际由冷态转为热态的数量，单位为 `mB/t`。
- 冷端口的最终输入验收必须经过真实 Create 储罐、获得动力的机械泵和流体管道，不得只用测试代码直接调用 `IFluidHandler.fill` 代替管网集成证据。
- P1 不实现冷却剂净化器、受污染冷却剂、工业仪表、独立 SCRAM 联锁器、锅炉、汽轮机、应力输出、可变反应堆、完整燃料生产线和烈焰人管理员。

### P1-CONTROL-05：让控制棒门控反馈超频燃料列

**状态：已完成。** 项目经理复验 195 项 JUnit、53 个 required GameTest 和 30 项模拟器 Node 测试，用户完成客户端人工验收；验收报告见 `docs/archive/P1-CONTROL-05.md`。
**前置：** P1-CONTROL-03、P1-CONTROL-04、P1-THERMAL-01、P1-SIMWEB-08。
**已确认复现：** 固定 `5×5×5` 堆芯平面按三行 `F-C-F` 布置，即中间纵向三列为控制棒、左右共六列为燃料。左右两组燃料各自四向相邻形成反馈簇；正式 Java 实现进入超频分支后丢弃 `controlledIntensity`，导致三根控制棒无论由玩家手动提交 `100%`，还是由仪表端口高电平 SCRAM 插入到底，六列新生裂变热和燃耗都不能归零。该现象已经通过客户端逐列/全堆新生裂变遥测确认，不是缓存余热。
**唯一目标：** 让正式 Java 裂变计算、SCRAM 判定和 HTML 模拟器统一执行“控制棒局部抑制 × 有界反馈倍率”，使反馈超频保留高功率风险但不能绕过完全插入的相邻控制棒。
**冻结公式：** 对每个有效燃料列先按四向相邻控制棒平均实际深度计算 `controlledIntensity`；反馈迭代从该值开始。每轮的邻列 `signal` 只累加上一轮已经受控制棒门控的有效热强度；本列最终热/燃耗强度分别为 `controlledIntensity × heatFeedbackMultiplier` 与 `controlledIntensity × burnFeedbackMultiplier`。无相邻控制棒时 `controlledIntensity = 1`，因此无棒反馈簇和中心空列八燃料平衡锚点保持原值；`controlledIntensity = 0` 时该列新生裂变热、燃耗及其反馈信号都必须为零。
**SCRAM 语义：** 至少存在一个控制棒列时仍可建立 SCRAM。若所有有效燃料列都被完全插入的可动控制棒覆盖，反馈簇也必须停堆并返回成功；只有未被任何控制棒覆盖的有效燃料列，或控制棒卡死在未完全插入位置而保留裂变时，才返回 `SCRAM_INCOMPLETE`。缓存余热和热冷却剂转化不参与该判定。
**允许修改：** `ReactorFissionCalculator` 及其直接结果/诊断适配、`ControlRodScramService` 的必要判定或文本、相关 JUnit/GameTest；`tools/reactor-simulator/` 中精确布局测试、警告文本、README、场景和离线单文件同步；`build/reports/p1/P1-CONTROL-05.md`。不得修改注册 ID、方块/物品资源、流体 capability、冷却/损伤/传播/融毁公式、配置字段或默认数值、快照 NBT 版本、核心文档、活动计划或 Git 历史。
