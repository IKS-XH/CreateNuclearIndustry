## 5. P1 固定规则

以下规则已冻结，执行任务时不得重新解释：

- 首发反应堆固定为 `5×5×5`；不实现可变面积和高度。
- 所有玩家拥有相同交互能力；不加入权限、身份、所有权或玩家绑定。
- `reactor_instrument_port` 是唯一权威状态方块；红石输入只从它触发 SCRAM。
- `control_rod_drive` 不接受红石调节，只接受玩家 Create 风格滑块；烈焰人管理员属于后置功能。
- 反应堆成型后控制棒默认完全插入。
- 高电平持续 SCRAM 只在至少存在一个控制棒列时成立：所有可移动控制棒插入并锁定，低电平恢复进入 SCRAM 前的目标深度。无控制棒列时拒绝请求、不保存恢复值、不建立 SCRAM 状态且不能暂停融毁倒计时；有棒时请求成立，插棒后仍有裂变产热则报告 `SCRAM_INCOMPLETE`。
- 直接相邻燃料的反馈超频只提供有界倍率，并与该列控制棒抑制强度相乘；部分插棒连续降低反馈簇，完全插棒使被覆盖列的新生裂变热和燃耗归零。反馈信号必须读取邻列已经受控制棒门控的有效强度，停止列不能继续提供反馈。
- 每个燃料列独立保存完整度、缓存热量和燃料组件状态；损伤程度线性提高发热与燃耗倍率，燃耗倍率增长更快。完整度归零默认产热 2.0 倍、燃耗 3.0 倍，两个终点可配置且须有限并满足 `1 < 产热终点 < 燃耗终点`。只要组件尚有耐久并未被控制棒正常压至零裂变功率，该列继续发热、燃耗和向外传播。组件耗尽后才停止该列裂变发热、燃耗和失效传播。
- 损伤只由有效热负荷产生；冷却足够时，即使超频也不降低完整度。
- 热量只沿四向相邻传播；不保存传播标记。燃料列和控制棒列使用相同传播系数，冷却可以阻止传播。
- 控制棒列完整度归零后卡死，保持实际插入比例并继续抑制相邻燃料列，但不向外传播损伤。
- 传播覆盖 `20%` 有效燃料列时建立融毁倒计时；控制棒列不计入分母。
- SCRAM 和有效冷却只能暂停融毁倒计时，不能回退进度；所有燃料列和控制棒列修复完整后才重置融毁状态。
- 完全停机且余热进入安全区后才能破坏性重新成型，清空整个结构 NBT；运行、融毁倒计时和暂停融毁倒计时中拆除任意组件立即融毁。
- 合金钢板右键维修：每次消耗 1 个；目标列必须停止放热；每次恢复 `0.25 / internalHeight`；维修消耗和恢复量不配置化。
- 护目镜动态遥测由服务端最后一个成功完成的反应堆 tick 派生并分层显示：仪表端口只显示冷/热冷却剂当前库存、全堆裂变发热量和实际冷却剂转化速率；换料端口显示其绑定燃料列的完整度与裂变发热量；控制棒驱动器显示其绑定控制棒列的完整度。完整遥测模型仍可包含全部逐列字段，但客户端不得自行重算或扫描结构。
- 全堆与单列“发热量”统一指最后一个已结算 tick 的新生裂变热，单位为 `HU/t`，不把列缓存余热重复计入发热；“冷却剂转化速率”指该 tick 实际由冷态转为热态的数量，单位为 `mB/t`。
- 冷端口的最终输入验收必须经过真实 Create 储罐、获得动力的机械泵和流体管道，不得只用测试代码直接调用 `IFluidHandler.fill` 代替管网集成证据。
- P1 不实现冷却剂净化器、受污染冷却剂、工业仪表、独立 SCRAM 联锁器、锅炉、汽轮机、应力输出、可变反应堆、完整燃料生产线和烈焰人管理员。

### P1-THERMAL-01：消除整数 mB 热量余数造成的虚假损伤

**状态：已完成。** 项目经理复验 192 项 JUnit、52 个 required GameTest，用户完成客户端人工验收；验收报告见 `docs/archive/P1-THERMAL-01.md`。

**问题复现：** 正式流体库存和转化量只能保存整数 `mB`。默认每 `1 mB` 吸收 `0.5 HU`，适配器会把不足 `0.5 HU` 的热量留在燃料列缓存；默认损伤阈值仅为 `0.25 HU`，因此 `(0.25, 0.5)` 范围的量化余数会在冷态库存和有效吞吐都充足时扣除完整度。失效列还可能把该余数当作传播源。
**唯一目标：** 区分“真实冷却能力不足”与“整数流体量化余数”，保证只有真实未被冷却覆盖的热负荷才能造成完整度损伤、传播或融毁覆盖，同时保持热量和整数流体库存守恒。
**必须满足：**

### P1-MAINT-03：实现停机破坏性重组成型

**前置：** P1-MAINT-02。

**唯一目标：** 将 `ReactorFullShutdownAssessment` 接入真实服务端 `BlockEvent.BreakEvent`，让完全停机反应堆可以通过一次可回滚的破坏性事务拆除并重新成型，同时保证危险拆除继续走 `P1-MAINT-01` 的唯一事件占位入口，余热或无效状态不能绕过安全门。
**明确的玩家触发：** 对某个当前有效缓存结构，破坏属于该结构的 `reactor_casing`、`reactor_window`、`reactor_cold_port`、`reactor_hot_port`、`reactor_refueling_port`、`reactor_fuel_rod` 或 `control_rod_drive`，即表示玩家选择启动破坏性重组；无需新增物品、GUI 或二次确认。破坏该结构自己的 `reactor_instrument_port` 是唯一例外：完全停机时按仪表维护处理，允许原拆除但不调用重置，仍在原位的换料端口物品必须保留。一个世界位置如果同时是另一有效结构的非仪表组件，仍按另一结构的规则独立处理，不能借“仪表例外”跳过其所有权。
**单个所有者决策表：** 必须先确认服务端、事件未取消、缓存结构有效、方块仍存在，并且事件方块 ID 与该结构缓存槽位一致。当前新生裂变热大于 `1.0E-12`，或 `meltdownCountdownStarted == true`（含运行、SCRAM/冷却暂停、已完成和已发布）时属于危险路径：复用 `P1-MAINT-01` 提交/去重规则，不取消原事件，也不执行安全重置。`ReactorFullShutdownAssessment.fullyStopped() == true` 时，仪表端口例外直接放行，其他七类组件执行破坏性重置。判定输入无效，或不属于危险路径但因计划燃耗、活动余热等未达到完全停机时，取消原 `BreakEvent`，不发布事故事件、不清空任何状态，并向玩家发送本地化的“尚未完全停机”动作栏提示。
