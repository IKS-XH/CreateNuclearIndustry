## 1. 已确认范围

- 直接把既有核换热器放在Create工作盆正下方，继续使用后热液入口、前冷液出口和同向直列共享液体库存，无新设备、无GUI。
- 支持原生普通加热与超级加热配方。工作盆压片及不需加热的搅拌照常运行，不人为增加加热要求。
- 热源仅为热复合冷却剂；冷热液体积1:1。普通蒸汽冷凝独立保留，换热器不接收超临界蒸汽，不以蒸汽给工作盆供热。
- 空盆、缺料、无有效动力和输出堵塞不能成为持续耗热负载；配方过滤、输入/输出、容器剩余物和概率产物沿用Create。
- 保持既有Create锅炉和高压锅炉热工；本项不新增配方、美术重绘、锅炉机制或其他设备教学。

## 2. 已确认规则与锅炉平衡

| 项目 | 推荐值或规则 |
| :--- | :--- |
| 普通加热费用 | 每批普通锅炉供热40tick的等效费用：`basinHeatedEquivalentTicks × huPerLevel`，默认40HU |
| 超级加热费用 | 每批超级锅炉供热40tick的等效费用：`basinSuperheatedEquivalentTicks × 2 × huPerLevel`，默认80HU |
| 不需加热的配方 | 不收核热费用；包括Create原生盆压片 |
| 热液用量 | 沿用现行HU/mB密度，默认0.5HU/mB；40/80HU对应80/160mB热液转成等量冷液 |
| 启动门槛 | 具有本批足额热储备才启动，无额外固定预热时间；候选配方有原料、动力和输出空间才允许充热 |
| 低流量 | 等待积热，不凭空发放热级；供热流量影响批次间等待时间 |
| 充热速度 | 不突破既有换热器额定转换速率；默认最高18HU/t，不把锅炉18级直接当配方热级 |
| 成本与加工速度 | 同一配方每批费用固定，提高搅拌转速只缩短原生加工时间 |
| 暂停和失败 | 只在产出成功时结算费用；停转、堵塞和原生预检失败不重复收费，预检失败不消耗原料 |
| 中途断热 | 足额已转换热储备可完成本批；热储备不足则不产出，恢复供热后重新尝试，沿用原生搅拌周期，不另设进度GUI |
| 待机余热 | 盆负载不按锅炉每tick耗费或倒计时散去已转换HU；仅存本批需求及整数转换尾差，待机不继续转换热液 |

锅炉负载的既有余热窗口不变。盆移除、换热器拆除、核热/冷凝模式互斥、区块不tick和直列失效均不得残留可查询热源；拆机不创造热液退款。当前版本正常保存加载应保存真实HU，不研究旧存档迁移。

费用进入现有`create_nuclear_industry-heat-exchanger.toml`：`basinHeatedEquivalentTicks=40`、`basinSuperheatedEquivalentTicks=40`，分别表示对应热级的等效供热tick数。原生`BoilerHeaters.blazeBurner`对普通/超级燃烧室返回1/2，现有账本每级每tick扣`huPerLevel`；因此默认40/80HU相当于同热级持续供热2秒（20TPS），并保持两种用途的2:1价格关系。此处是批次价格的核算基准，不声称搅拌器加工固定2秒；实际加工速度与费用相互独立。

配置范围和储热上限一致校验，费用非有限/非正或超过储热上限则停用对应供热并提示，不静默免费加工。热液密度、流量和罐量继续使用既有配置，不新增重复配置源。`huPerLevel`调整会同步影响锅炉级别费用和工作盆批费；`heatLevel`继续限制充热功率而不改变每批价格，`bufferTicks`继续定义既有储热容量，不用于自动改价。

## 3. 最小接入与结算合同

Create工作盆不是从`BoilerHeater`注册表读热，而是读取盆底方块的`HeatLevel`。普通`HEATED`与`SUPERHEATED`属于配方条件，分别对应普通热和`SEETHING`，不能拿锅炉数值等级直接替代。

实现优先复用原生`BasinRecipe.match/apply`。仅在本设备的短作用域需求探测中忽略热条件，保持配方过滤、全部输入和输出预检；离开作用域后恢复真实已付热判断。探测不改世界方块热级、不修改配方对象、不转换冷却剂或扣HU。原生概率产物匹配使用其自身随机取样，不把原生随机行为误称为热账本写入。

工作盆需求充热与成功扣费都必须落在同一台服务端换热账本中，不另建独立热池。每台只处理其正上方盆，直列可共享液体但各台分别记真实HU，不借其他台已付热重复使用。已归属高压锅炉的换热器不得再给盆供热；同一台正上方是盆或Create储罐，不能同时给两者计费。

真正执行加工时应在原生实际提交前预留本批费用，原生提交成功后确认扣账，失败释放未消费预留；连续加工每批各自结算。费用不足、无有效动力或源无效须在原生提取输入前拒绝。热查询缓存不得把探测热或上一批热当成下一批已付款，重入及同tick重复查询不能增加费用或产物。

若锁定Create源码无法以最小Hook满足上述事务边界，执行者须报告具体阻塞，由PM定向整改；不得自行改为按放盆收费、免费常亮或复制配方引擎。
