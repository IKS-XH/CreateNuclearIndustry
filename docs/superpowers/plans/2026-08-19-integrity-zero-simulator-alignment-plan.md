## 1. 目标与前置

将离线 HTML 反应堆模拟器同步到两组已冻结设定。第一，`fuelColumnIntegrity = 0` 不会自行停止燃料列裂变发热、燃耗或失效传播；只要燃料组件仍有耐久，并且控制棒没有按正常规则把该列裂变功率压至零，列继续以 `damageMultiplier = 2.0` 结算发热、燃耗、冷却、缓存热量和四向传播。燃料组件耗尽后，该列裂变发热、燃耗和失效传播均停止；已有缓存余热只通过常规冷却账本消散，不再制造新传播损伤。第二，冷却剂默认吸热改为 `0.5 HU/mB`、每端口上限改为 `128 mB/t`、损伤速率改为 `0.0000005 / (tick·HU/t)`，并彻底删除全堆冷却剂流量上限；多个合法端口只按逐端口上限、实际流量和冷热两侧瓶颈汇总。

**前置：** `P1-SIM-09` 已完成并由项目经理验收；`P1-BALANCE-01` 已完成并由项目经理验收。不得从 HTML 模拟器反向猜测或修改游戏内规则。

## 3. 原子任务

### P1-SIMWEB-08

**唯一目标：** 同步 HTML 模拟器的零完整度语义、冷却剂吞吐合同和 P1 默认平衡数值，使其与 `P1-SIM-09`、`P1-BALANCE-01` 一致。

**必须满足：**

1. 有燃料的 `integrity = 0` 列继续使用 2.0 倍损伤反馈，不得因完整度零而被从有效燃料、冷却分配或燃耗结算中排除。
2. 该失效且未耗尽的燃料列以当 tick 完整快照中的当前总热量（裂变发热加缓存余热）沿四向传播；目标冷却可阻断，控制棒列仍为传播终点，空列/对角线仍不传播。
3. 组件耗尽后，裂变发热、燃耗和失效传播均为零；不得把缓存余热再次转为新的传播损伤。正常满插控制棒使裂变热归零的原有语义不得破坏。
4. 更新页面列详情、警告和 `README.md`，明确“完整度 0 = 2.0 倍失效运行，不等于耗尽或停堆”。不得显示“归零倍率 0”。
5. 将默认值更新为 `coolantAbsorptionHuPerMb = 0.5`、`coolantMaxFlowPerPort = 128`、`fuelColumnDamageRate = 0.0000005`；`baseHeatPerFuel = 1.0`、损伤阈值 `0.25`、反馈参数和其他冻结默认值保持不变。
6. 删除配置表单、运行时计算、瓶颈列表、README、导出 JSON 和 CSV 中的 `coolantTotalFlowCap`。端口理论能力按互不重复的冷/热端口分别求和；实际转换量仍取冷热两侧实际能力、可用热量、内部库存和背压的最小值。不得用 `200`、`256` 或其他隐藏常量重新实现全堆截断。
7. 递增导出中的 `RULE_VERSION`；导入旧版本 JSON 时必须安全忽略 `coolantTotalFlowCap`，不得让旧值影响计算；新导出必须省略该字段，且不得执行导入数据中的脚本。
8. 更新或新增 Node 测试和代表性场景；既有冷端受限、热端受限、控制棒隔离、空列隔离、传播暂停融毁和安全超频场景不得无故删除。

**验收：**

- `npm test` 全部通过，且至少新增下列断言：
  - 完整度 0、燃料未耗尽：发热和燃耗均等于同布局完整度 1 的 2.0 倍（控制/超频条件相同）；
  - 完整度 0、燃料未耗尽：四向传播能触达相邻燃料列并可满足融毁覆盖阈值；
  - 燃料耗尽：发热、燃耗、失效传播均为 0，缓存余热不产生新的目标损伤；
  - 完整插棒：即使完整度为 0 且仍有燃料，裂变发热和燃耗仍为 0；
  - 新默认值精确匹配 P1 合同，配置字段和新导出中不存在 `coolantTotalFlowCap`；
  - 三组冷热端口在实际流量、发热和库存允许时具有 `384 mB/t` 理论能力；冷热端不对称时取较小侧，重复端口不重复结算；
  - 导入含旧 `coolantTotalFlowCap` 的导出时安全忽略该字段，导出新版本和 CSV 规则版本字段均可验证；
  - 固定 `5×5×5`、中心空列、周围 8 燃料列默认总发热约 `99.87469 HU/t`、需求约 `199.74938 mB/t`，一组 `128 mB/t` 冷热端口不足，两组 `256 mB/t` 足够；单组端口下首列约在 `803 ticks` 归零，不得出现十几 tick 失效。
- 在浏览器人工复验两个 5×5×5 场景：(1) 选择一列设为完整度 0 且保留燃料，确认其显示为失效运行、2.0 倍反馈并可持续传播；随后将其燃料设为耗尽，确认发热/燃耗/失效传播停止；(2) 中心空列、周围 8 燃料列时，分别切换一组、两组和三组冷热端口，确认瓶颈从 `128` 提升到 `256`、`384 mB/t`，且界面不再出现“全堆流量上限”。
