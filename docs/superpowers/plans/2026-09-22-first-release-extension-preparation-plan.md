### 2.2 D-02 已确认：保留制粉，对接通用材料标签

用户于 2026-09-23 确认保留制粉工序，并要求对应 NeoForge 辞典中的现有矿物粉。按当前版本落实为 `c:*` 数据包物品标签：

- 登记 `create_nuclear_industry:lapis_dust`，制粉原料使用 `c:gems/lapis`；粉末加入 `c:dusts/lapis` 并汇入 `c:dusts`。冷却剂输入读取具体矿物粉标签，接受其他模组加入同标签的等价材料。产物固定为本模组青金石粉，不依赖第三方材料模组。

- Create 已有 `c:dusts/obsidian`，成员为 `create:powdered_obsidian`；后续依赖审计须明确现有产物复用和同标签替代，不能把“缺少本模组物品”误写成“生态无此材料”。本次不擅自删除已登记的 `obsidian_dust`。
- 验收须包含真实配方匹配：本模组粉末、外部等价标签成员成功，未制粉青金石/蓝色染料/错误粉末拒绝；标签追加不覆盖其他提供者，无第三方模组时正常加载且路线可达。可用隔离测试数据包模拟外部成员，但不得将其称为实际第三方模组联调。

## 3. 热端和动力闭环的接口合同

| 边界 | 已确认行为 / 单位 | 验证重点 |
| :--- | :--- | :--- |
| 反应堆→换热器 | 热复合冷却剂以 `mB` 输送；换热后返冷态；反应堆已有热量采用 `HU`、流量采用 `mB/t` | 同一份工质只扣一次；不要把流体温度属性直接当作可重复领取的能量 |
| 换热器→专用锅炉 | 热量与品质同时传递，只有核热模式提供 `NUCLEAR_SUPERCRITICAL`；普通热为 `CONVENTIONAL_HEATED` | 品质不可随数量相加升级；混合供热只按核热实际覆盖份额产超临界蒸汽 |
| 换热器→Create | 策划默认锅炉热值 18/9，可配置；配方分别读取超级/普通加热；余热窗口内保留核热级，结束后停热 | 数值锅炉热值与配方热级分别验证；18/9 不能未经换算直接等同 `HU/t`；验证空载、断供、刷新和卸载 |
| 锅炉→汽轮机 | 给水、热量、蒸汽生成与库存分别计账；超临界蒸汽走二级耐压输送 | 缺水与排汽堵塞原因区分；普通热循环不能增加超临界库存 |
| 汽轮机→轴网 | 只输出 Create 应力容量 `SU`；多个主轴分配同一总量；RPM 遵守 Create 限制 | 同网合流不重复算总容量，拆网/并网/卸载时不残留旧容量 |
| 汽轮机/蒸汽供热→冷凝 | 两处均输出同一个 `steam`；冷凝到 `minecraft:water`，不再结算 SU | 无冷源或出水受阻时不吞蒸汽、不积累冷凝空载损坏；回收比例须配置与守恒验证 |
| 三设备→事故系统 | 运行状态稳定后统一冻结事故触发、保护、产物、世界效果和性能预算；复用 P1 事件入口 | 不把具体事故重新加入 P1 前置；辐射/污染后置，剩余 Ponder 在事故行为验收后制作 |

技术路线建议：复用现有“纯状态计算→服务端事务提交→客户端只读显示”的分层方式；先以纯账本验证守恒，再接真实 Create 负载。每个库存/状态只有一个持久化所有者，能力的模拟请求不消费或产出，执行前复核接收空间，阻塞/卸载不能丢物质。这里是任务验收方向，具体 Java 类型、接口签名、NBT 字段和写集须在探针结论后由项目经理另行冻结。
