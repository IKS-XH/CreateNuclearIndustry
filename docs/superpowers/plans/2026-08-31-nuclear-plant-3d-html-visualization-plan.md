**计划状态：** 待执行；独立视觉工具，不阻塞当前 P1 功能主线
**计划维护者：** 项目经理（Codex）

**目标项目：** 《机械动力：核工业》

**权威依据：** `docs/project.md`、`docs/content-catalog.md`、`docs/implementation-roadmap.md`；现有反应堆数值工具只作为 P1 反应堆状态参考，不是整座机组的视觉或热力学权威

## 1. 目标与产品定位

实现一个可由本地静态服务器打开的三维 HTML 页面，默认直接展示一座正在稳定运行的 Create 风格核动力机械站。页面至少包括：

- 固定 `5×5×5` 实验反应堆；
- 核热模式换热器与一回路冷热复合冷却剂管线；
- 专用高压锅炉、给水口、换热段、蒸汽口和安全阀；
- 固定尺寸超临界汽轮机、进汽段、高压/低压段、排汽段、轴承端和主轴输出；
- 冷凝模式换热器、回水管线、给水泵、主冷却泵、阀门及必要的 Create 轴系/齿轮视觉；
- 冷态复合冷却剂、热复合冷却剂、水、超临界蒸汽、普通蒸汽和旋转应力的清晰流向；
- 与设备状态对应的持续运行动画、启动/停机过渡和典型故障表现。

该工具用于：

1. 讨论整座机组的外观、比例、布局、管线和动画语言；
2. 为以后 Minecraft 方块模型、Blockbench/Flywheel 动画、Ponder 演示和宣传画面提供可评审的空间参考；
3. 帮助玩家理解主回路、蒸汽回路和 Create 应力输出之间的关系。

它不是当前 P1 游戏实现，不得因为网页中出现锅炉、汽轮机或完整蒸汽闭环，就把这些内容标记为已经注册、完成或通过游戏验收。

## 3. 技术路线

### 3.1 推荐实现

- 使用 Three.js 的固定版本作为 WebGL 场景层，版本通过 `package-lock.json` 锁定；运行时不得依赖 CDN。
- 通过本地静态服务器打开；交付目录在完成依赖安装或执行资源准备命令后，不需要联网即可运行。
- HTML、CSS 和 JavaScript 使用 ES module；不引入 React、Vue、完整游戏引擎或服务端数据库。
- 设备使用“Minecraft 方块尺度 + Create 机械细节”的混合模型：静态外壳优先用程序化方块几何，转子、叶轮、阀杆、泵轮和控制棒等运动部件可使用独立低多边形模型。
- 正式模型交换格式优先使用 glTF/GLB；源文件可使用 Blockbench `bbmodel`，但浏览器不得在每帧解析 Minecraft 方块模型 JSON。
- 纹理使用 PNG、2 的幂尺寸、NearestFilter 和像素化 UV；不得用照片写实 PBR 素材改变当前美术方向。
- 状态计算与渲染分离：状态层只输出标准化的机组状态，场景层只消费状态并插值动画，不能把数值规则散落在模型代码中。

### 3.2 第三方依赖门

`PLANT3D-00` 必须先验证 Three.js 模块、OrbitControls、GLTFLoader、本地静态服务器和测试环境。只有该探针通过后才允许进入正式页面。推荐把固定版本依赖保留在 `package.json`/`package-lock.json`，通过受控脚本把浏览器所需模块复制到工具自己的 `vendor/`；最终页面不得直接引用 `node_modules` 绝对路径或公网地址。

若 Three.js 在当前环境不可用，执行者必须报告具体错误和替代方案，不得擅自改成 Canvas 伪 3D、远程托管引擎或不可审计的单文件混淆产物。

## 4. 场景与设备合同

### 4.1 默认机组拓扑

```text
冷复合冷却剂 → 主冷却泵 → 实验反应堆 → 热复合冷却剂
      ↑                                  ↓
      └──────── 核热模式换热器 ←─────────┘
                         ↓ 核热
回水 → 给水泵 → 专用高压锅炉 → 超临界蒸汽 → 超临界汽轮机
 ↑                                                ├→ Create 主轴/齿轮箱/SU 负载
 └──── 冷凝模式换热器 ← 普通 steam ←─────────────┘
```

同一个 `nuclear_heat_exchanger` 注册身份可以在场景中出现多个实例，但每个实例同一时刻只能处于一个模式。默认机组至少放置一个核热模式实例和一个冷凝模式实例，不得画成一台换热器同时执行互相冲突的模式。

### 4.2 比例与空间

- 以一个 Minecraft 方块为一个场景单位，所有设备、管道、轴和人物参照物共享同一比例。
- 实验反应堆严格表现为外尺寸 `5×5×5`。
- 汽轮机按现有概念表现为 6～8 格长的分段结构；默认演示尺寸必须写入场景 JSON，并标记为视觉提案，不得冒充已冻结游戏结构合同。
- 锅炉首版尺寸尚未冻结；默认演示尺寸同样放在场景 JSON，不写死在模型代码中。
- 页面应保留维护通道、阀门操作空间和清晰管线路径，不能把设备紧贴成一团以至于无法理解回路。

### 4.3 设备视觉与动画

| 设备 | 必须可见的结构 | 正常运行动画 | 危险/停机动画边界 |
| --- | --- | --- | --- |
| 实验反应堆 | 外壳、观察窗、换料端口、控制棒驱动器、冷/热端口、仪表端口 | 控制棒驱动轴缓慢调整；观察窗中有冷却剂流动和蓝色脉冲；外壳保持稳定工业状态 | SCRAM 时控制棒快速插入；过热时只提高警示色、蒸汽/脉冲频率，不用廉价随机爆炸 |
| 核换热器 | 热侧/冷侧接口、模式标识、换热核心 | 核热模式显示热复合冷却剂降温回流；冷凝模式显示蒸汽凝结和回水 | 无负载或无冷源时流动停止并显示明确状态，不继续伪造转化 |
| 高压锅炉 | 外壳、观察窗、给水口、换热段、蒸汽口、安全阀、控制器 | 视窗液位、气泡、温度光和稳定出汽随负荷变化 | 给水不足显示干烧红光；出汽受阻显示压力与阀门喷汽；二者视觉必须不同 |
| 超临界汽轮机 | 进汽段、高压段、低压段、连续转子、轴承端、排汽端、调速器、制动器、主轴端 | 转子、叶轮、输出轴、齿轮和飞轮按 RPM 连续旋转；正常满载是稳定机械运动 | 超速才提高尖啸视觉、轴承火花和制动表现；停机转子按惯性逐渐降速 |
| 泵/阀/管道 | 主冷却泵、给水泵、阀门、不同工质管路 | 泵轮与轴旋转；流向粒子或纹理沿管路移动；阀杆角度反映开度 | 关闭、反向或断流时动画停止，不允许流向标记穿过关闭阀门 |

### 4.4 工质视觉编码

颜色不能是唯一信息，必须同时使用中文名称、箭头/粒子方向和不同线型或粒子形状：

- 冷复合冷却剂：冷色、稳定脉冲；
- 热复合冷却剂：暖色、较强热辉光；
- 水/回水：清晰液体流动；
- 超临界蒸汽：高能、高压方向标记，与普通蒸汽外观区分；
- 普通 `steam`：较柔和蒸汽流；
- Create 应力：旋转轴、齿轮和负载方向，不画成电缆、电火花或 FE/RF 能量束。

## 5. 状态模型与交互

### 5.1 标准化运行状态

状态模型至少包含：

```text
timeScale
reactorPower01
controlRodDepth01
primaryCoolantFlow01
heatExchangerLoad01
boilerWaterLevel01
boilerPressure01
steamFlow01
turbineRpm01
shaftLoad01
condenserFlow01
alarmState
scramActive
```

所有 `01` 字段限制在 `[0,1]`；视觉层只读取这些值。默认版本不尝试建立完整商用机组热力学模拟，不得凭网页动画冻结尚未确定的锅炉效率、蒸汽产率或汽轮机 SU 数值。

后续若接入现有 `tools/reactor-simulator/` 的导出结果，必须通过独立只读适配器完成；不得让三维工具直接修改旧模拟器或游戏核心文档。

### 5.2 必须提供的预设

1. `startup`：泵先启动、反应堆升功率、锅炉预热、汽轮机升速、主轴接载；
2. `steady`：默认首屏，整座机组稳定运行；
3. `scram`：反应堆控制棒插入，裂变功率下降，但冷却泵继续运行，锅炉和汽轮机按惯性衰减；
4. `loss_of_coolant`：一回路流量下降，反应堆预警，换热和产汽逐步降低；
5. `feedwater_loss`：锅炉给水不足并出现干烧表现；
6. `steam_blockage`：锅炉压力升高、安全阀动作、蒸汽旁通；
7. `turbine_trip`：进汽关闭、制动器动作、转子逐渐降速；
8. `load_rejection`：外部应力负载突然消失，汽轮机短时超速后调速/制动介入。

每个预设必须是确定性时间线，同一初始状态与时间产生同一输出，方便截图复现和测试。

### 5.3 页面交互

- 鼠标/触控旋转、平移和缩放；提供“恢复总览”按钮。
- 点击或键盘选择设备后，只显示一条紧凑的设备名称、当前状态和流向说明，不构造大面积仪表盘。
- 提供播放/暂停、`0.25×/1×/2×` 时间速度和预设选择。
- 提供“外壳透明”“管线高亮”“设备标签”三个独立开关。
- 默认首屏立即进入 `steady`，相机使用可读的斜俯视总览；设备不能被 UI 遮住。
- `prefers-reduced-motion` 生效时停止连续旋转、粒子和镜头自动运动，但用静态箭头、标签和状态线保留信息。

**必须满足：** 进汽、高压段、低压段、连续转子、轴承、排汽、调速、制动和多个主轴端可辨识；RPM 驱动叶轮和主轴，停机具有惯性，超速才出现火花/制动；不得显示 FE/RF、电缆或发电机。
**验收：** 转速插值、暂停、负载切除、超速、制动和降速测试通过；高速采用简化/模糊策略而不是无限提高几何更新频率。

`PLANT3D-03` 至 `PLANT3D-06` 在 `PLANT3D-02` 骨架冻结后可以并行，但每个执行者只能修改自己的独占写集。`fluid-network.js` 的共同接口必须在 `PLANT3D-01` 冻结；发生冲突时停止并交由项目经理处理。

### PLANT3D-07：装配整座机组与闭合管路

**前置：** PLANT3D-03、04、05、06。
**唯一目标：** 把设备、泵、阀、管道、冷凝回水和 Create 轴系装配成默认运行核电站。

**验收：** 场景合同测试验证每条逻辑连接都有对应可见路径；人工旋转一周检查遮挡、穿模、比例和标签。

### PLANT3D-08：接入预设、设备说明与无障碍降级

**前置：** PLANT3D-07。
**唯一目标：** 让八个状态预设完整驱动整座机组，并提供最小必要交互。
**必须满足：** 默认稳态自动运行；播放/暂停/倍速、预设、透明外壳、管线高亮、标签和恢复总览可用；选中设备只显示紧凑说明；键盘和触控可完成核心操作；减少动态时仍能读懂流向和状态。
**验收：** 预设切换无状态残留；SCRAM 后泵继续而反应堆功率下降；锅炉/汽轮机故障只影响合理链路；界面没有英文硬编码或每帧文本抖动。

### PLANT3D-09：完成性能、资源和浏览器验收

**前置：** PLANT3D-08。
**唯一目标：** 在不牺牲信息可读性的前提下完成性能与资源收口。
**性能门：** 默认场景建议不超过 250,000 三角形、200 draw calls 和 64 MiB 解压纹理；桌面中端 GPU 在 1080p 目标 60 FPS，集成显卡在 720p 目标不低于 30 FPS；若实际环境无法量化其中一项，报告必须记录设备、浏览器和可复现观察。
**资源门：** 所有路径存在、PNG 尺寸合规、模型无缺失纹理、第三方许可证齐全、无 CDN/远程请求、无来源不明资产。
**浏览器门：** 当前稳定版 Chrome/Edge 与 Firefox 至少各完成一次；WebGL 不可用、页面失焦、窗口缩放和减少动态模式均可安全降级。
**交付：** `PLANT3D-09.md`、性能记录和固定视角截图。

### PLANT3D-10：生成离线交付与人工验收包

## 8. 验收清单

最终验收必须同时满足：

- 打开页面后无需配置即可看到完整、正在运行的主机组；
- 四类主要设备都能从轮廓和运动方式识别，不依赖文字猜测；
- 一回路、蒸汽回路、冷凝回水和 Create 轴系的方向正确且闭合；
- 反应堆固定 `5×5×5`，锅炉与汽轮机演示尺寸没有被写成游戏权威；
- 正常、启动、SCRAM、失冷、失水、堵汽、汽轮机跳闸和甩负载表现符合现有项目因果链；
- 没有净化器、受污染冷却剂、工业仪表、独立 SCRAM 联锁器、FE/RF 输出或热乏燃料池；
- 视觉沿用 Minecraft 像素尺度和 Create 黄铜、铜、铆钉、舷窗、齿轮与可动机械语言；
- 页面离线可运行、无控制台错误、无缺失资源、无不明许可证、无核心文档或游戏源码改动；
- 所有执行者遵守中文注释、专属写集和 Git 禁令。

## 9. 项目经理验收与归档职责

每个任务完成后，项目经理负责：

1. 核对改动只在允许写集；
2. 审查报告与测试是否真实覆盖任务合同；
3. 恢复测试生成日志和任务外临时文件；
4. 决定通过、退回整改或暂停等待视觉决策；
5. 只有项目经理或用户可以更新本计划状态、归档报告和执行 Git 提交；
6. `PLANT3D-10` 通过用户人工验收后，将本计划移入 `docs/archive/`，并在归档索引中记录它是视觉概念工具，不是游戏实现完成证据。

## 10. 当前不阻塞骨架、但需后续视觉确认的项目

- 专用高压锅炉的最终游戏尺寸、端口位置和观察窗比例；
- 固定首发汽轮机采用 6、7 还是 8 格长度，以及高压/低压段比例；
- 核换热器最终是单方块外形还是小型多方块外壳；
- 是否在默认场景加入控制室、厂房、冷却塔或人物；这些不是四类主设备和回路验收的前置；
- 三维工具的概念模型是否直接转为未来 Blockbench/Flywheel 资产。默认答案为“不直接转用”，只有经过模型尺寸、UV、许可证和游戏性能专项验收后才能进入模组资源目录。
