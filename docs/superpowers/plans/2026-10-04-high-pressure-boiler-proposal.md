# 首台专用高压锅炉：核热产汽方案

**最新状态（2026-10-04）：** 锅炉01A～01D、强化钢板最终配方、换热器定向共享直列与01E翻译全部现行人工门通过，候选`0cb75fc`已合入main，见[最终验收](../../reviews/2026-10-04/boiler-01d/ACCEPTANCE.md)。本页维护现行已确认合同；未来可变尺寸及其他后置玩法不记为已实现。

本页维护现行批准合同，旧3×3×4证据留在01A归档。首期仅核热、Create原生管道/泵/储罐输送超临界蒸汽，辅助热及二级耐压限制继续延期。工作盆加热后移，后续为汽轮机、冷凝回水；不将这些后续项计为本批已批准实现。

## 1. 本批可玩的结果

```text
现有反应堆热端 → Create管路 → 核换热器 → 等量冷液返回反应堆
                                  ↓ 向上交付实际支付的核热
Create给水 → 专用高压锅炉 → 超临界蒸汽 → Create管路/储罐
                                            ↓ 后续一批
                                      超临界汽轮机 → SU与普通蒸汽
                                                       ↓ 后续一批
                                               核换热器冷凝 → 给水
```

首台实现核热产超临界蒸汽、可观察的水/汽库存、预热、压力提示、安全阀及完整制造。汽轮机尚未完成时，可以把蒸汽实际送入储罐，独立验收锅炉与管网。

**用户已确认的首期范围：**

1. **首期超临界蒸汽允许走Create原生管道、泵与储罐。** 原有二级耐压输送限制延期到管道等级专项，本批不新造一套管网、泵或储罐；普通蒸汽后续也沿用原生物流。蒸汽仍无生存桶，不放置为世界液体，不可送入原版蒸汽引擎取得第二份动力。后续启用耐压限制前须另定旧管路迁移方案。
2. **首台只接核热。** 烈焰人辅助热源、低温“湿蒸汽”曲线与普通热产汽随锅炉扩展再做。该批不添加湿蒸汽ID或隐藏品质，不把普通热叠加为核热。具体事故、破裂和损伤仍按既定统一事故阶段实现；本批先实现安全停产、明确泄压与守恒。

## 2. 结构与接口

当前批次外尺寸为已确认的**宽5×深5×高5**，98个壳体位置、内部3×3×3为空气。所有棱边及角点只能为普通锅炉外壳。

**后期扩展要求（2026-10-04，含最新容量补充）：** 用户明确锅炉与反应堆都要支持限定范围内自由选择长宽高的完整长方体，并确认锅炉内部水/汽容量随成型规模变化。5×5×5、三格端口排、当前层位和中央定位是首台实现范围，现行各16000mB不作为所有尺寸通用容量。可变尺寸任务须按实际边界推广结构扫描与接口规则，再确认尺寸上下限、容量的体积口径/系数/上下限、产能缩放及旧存档迁移；结构缩小时的超额库存处理单独明确。扩容只增加容量上限，不放大已有水、蒸汽或储热，端口数量本身不增加容量。下表现行固定结构及容量仍为已验收实现，本次只更新规划。

| 部件 | 数量 / 位置 / 职责 |
| :--- | :--- |
| 锅炉外壳 | 填满其余壳体位置，纯结构块 |
| 观察窗 | 可选，替换侧面非棱边普通外壳，世界中透明；使用已有铅玻璃 |
| 控制器 | 恰好1个，正面中列、由下向上第2层；朝向确定整机边界，保存唯一水/汽/暖炉状态 |
| 给水口 | 1～11个，四侧由下向上第2层，每侧三个非棱边位置，排除控制器；只输入水 |
| 蒸汽口 | 1～12个，四侧由下向上第4层，每侧三个非棱边位置；只向外主动输出超临界蒸汽 |
| 核换热段 | 底面中央3×3放1～9个，含正中心；每段正下方另置核换热器，底面其余位置为普通外壳 |
| 安全阀 | 恰好1个，顶面正中央，上方一格须为空气才能排汽；其余顶面为外壳 |

第2层控制器面可放2个给水口，其余三面各3个；第4层各面均可放3个蒸汽口。控制器仍占某侧中央位置，棱边仍只允许外壳。所有端口只在对外法线面提供能力，能力代理控制器共享罐，不按端口数量增容。[01C](./2026-10-04-ext-b-boiler-01c.md)取消整炉总流量额度，每口独立256mB/t；多口可增加输送能力，不增加供热决定的产汽量。缺少外部换热器只意味着对应换热段没有输入热；锅炉壳体仍可成型并提示缺热。

最低搭建为93普通外壳＋控制器/给水口/蒸汽口/换热段/安全阀各1；外部另放1台核换热器。满配9个底面换热段时，相应替换8个普通外壳，外部使用9台核换热器。

九台按[换热器01D](./2026-10-04-heat-exchanger-chain-proposal.md)布置为三条独立直列，每列三台同向首尾相连，每列入口收热液、出口返冷液，组内共享库存而各自供热。中央机可使用所属列的库存。旧3×3×4须由玩家重搭，控制器库存保留；不自动搬世界方块或管路。

蒸汽口主动向邻接罐和Create普通管道出汽，无需外部动力泵；驱动距离复用原生可配置泵距，默认16格。同一个汽口的主动与外部泵抽取共用该口256mB/t额度，各汽口额度独立；内部压力按Create压力/2对应流率换算，不冒称机械RPM或真实压力。01C实施前的d10e1af仍是旧整炉限流，勿将新合同当作旧候选实际行为。

- 扳手右键控制器检查/重扫结构，失败指出缺失位置或阻塞原因，不打开GUI。
- 给控制器红石高电平停止收热和产汽；仍可给水、抽汽，已成型安全阀保持保护。
- 护目镜显示成型状态、给水/蒸汽量、暖炉进度、当前HU/t、实际mB/t、压力百分比、累计排放及停机原因。压力是游戏库存指标，不显示伪精确MPa。
- 外观沿用钢灰外壳、铜换热件、黄铜紧固件与可辨识接口；安全阀和可见换热件独立分件，预留动画。当前制作可用的SVG/JSON资源，不加入完整运行动画或连接纹理专项。

## 3. 热量、流量与暖炉

| 参数 | 推荐首轮值 |
| :--- | :--- |
| 换热段额定接收 | 每段最高18HU/t；9段最高162HU/t，不因控制器查询次数重复收热 |
| 热液换算 | 沿用默认0.5HU/mB；每台换热器最高36mB/t，热转冷始终等量；9台合计最高324mB/t |
| 给水与产汽 | 就绪后每1mB水＋1HU可交付核热→1mB超临界蒸汽；首期固定身份换算，不随流体温度或热源配置重估存量，不模拟真实蒸汽体积膨胀 |
| 额定产汽 | 一段18mB/t（360mB/s）；九段162mB/t（3240mB/s），前提是实际热量、给水和出口均足够；按20TPS换算 |
| 共享库存 | 水16000mB、超临界蒸汽16000mB |
| 对外能力上限 | 每个给水口和每个蒸汽口独立最高256mB/t，取消整炉总上限；01D最多11进12出对应理论2816/3072mB/t，仍受共享库存/容量及原生泵自身限制，产汽上限仍为162mB/t |
| 首次暖炉 | 3600HU×结构内换热段数量；热量全部用于炉体升温，不再用于产汽。全部段以额定热量连续到账时需200tick，约10秒；不把换热器自身启动时间算成零 |
| 保温与冷却 | 运行中已就绪炉体不额外收固定维持费；连续没有实际接收热量时，每tick散去0.9HU×换热段数的炉体热量。余温低于或等于25%时退出就绪，下次需补到100% |
| 断热后 | 仅能使用换热器已经付费且仍在原40tick窗口内的余热；锅炉暖炉热量不能再用来产汽。无新的可用热量就无新的蒸汽，不用库存压力虚构产汽 |

默认下，单段首次暖炉会把7200mB热冷却剂变回等量冷液；九段为64800mB，都是循环液而非净消耗。上述暖炉值按**结构中的换热段数**计算，不按本tick工作的换热器数跳变，因此只接通部分热源时升温较慢。

满温停收热约150秒后降至25%，重新升温保留剩余炉体热量；从25%按额定热量补满约7.5秒，未重新就绪前不产汽。这里只使用世界game tick：服务器完全退出期间没有世界tick，不按现实钟补算冷却；发生世界时间回退时不增加任何余温或蒸汽，保守清除无法证明有效的暖炉热量。

专用锅炉直接按实际HU需求收热，不把Create锅炉的18级热值当作18mB凭空结算。现有原生锅炉自适应9/18行为保持；同一换热器同一时刻只能把热量交给顶部的一个实际负载。其源账本扣除多少，锅炉最多得到多少，不能重复存入两个设备。

只有结构有效、控制器未停机、至少有1mB给水且蒸汽罐有空间时才请求暖炉或加工热量。已就绪且水/汽空间不足时按能完成的最小事务限量请求；没有可完成事务时停止收热。小于1mB产汽所需的热量尾数单独保存且有界，不以整数截断复制能量。流量/容量配置变更不能重估已存蒸汽或暖炉热量凭空增能；首期不提供修改蒸汽每mB携能的开关，后续若修改该身份换算须先定存量兼容方案。

暖炉状态、加工热量尾数与蒸汽携能各有用途，必须分别记账。后续汽轮机取得的做功预算与排汽携能之和不得超过本批每mB超临界蒸汽已支付的1HU；SU换算系数和普通蒸汽剩余携能在汽轮机批次单独确认，本批不据此宣称目标机组输出已实现。

## 4. 堵塞、泄压和保存

- 压力显示值＝蒸汽库存/16000mB。蒸汽达到90%时自动打开安全阀，降至80%时关闭，排放上限256mB/t；排放有蒸汽表现和累计mB提示，明确属于主动损失，不能算作冷凝回收。
- **当前实现边界：** 已有库存压力提示与泄压，但没有温压决定蒸汽品质的计算。首期只接受核热，暖炉完成且有水和热量就直接产超临界蒸汽；普通热源产普通蒸汽、汽轮机排汽与冷凝仍待后续任务。Create管道的输送压力只控制流速，与此处库存压力不是同一数值。
- 安全阀上方不通畅时不吞蒸汽，显示排放受阻；蒸汽满罐则停止产汽和收热。本批不因堵塞炸炉，也不删去库存绕过堵塞。
- 缺水、无热、产汽出口受阻、排放受阻、红石停产和结构不完整分别显示。停产不把热液直接变成冷液；已支付余热按原规则散去。
- 区块不活动期间不推进产汽；恢复时按世界tick经过的时间扣减停收热期间的炉体余温。保存/读档不补热、不重置冷却期限，不重新生成已排放蒸汽。
- 拆除结构件后关闭所有端口事务、停止收热，库存保留在控制器。重建同一结构恢复库存，改变换热段数量只重新校验/限缩暖炉容量，不按新容量比例放大原有HU。
- 控制器扳手收起或普通破坏只掉一个携带库存/状态的控制器，放回须重新验型后才能工作；不复制到各端口或其他外壳，不模拟物品形态的产汽。流体仍只能经端口取放，不增加手持蒸汽桶。

正常回路未触发排放时，水与蒸汽按1:1记账；若安全阀打开，护目镜明确显示排放损失。这与已修复的一回路冷却剂无故减少不同：冷却剂闭环仍要求冷热总量严格守恒。
