# 乏燃料基础封存：轻量修订方案

**状态：** 用户2026-10-06明确“好，就这样吧”，轻量修订全部确认，取代先前未批准的高成本方案。[STORE-01实施卡](./2026-10-06-ext-a-store-01.md)接续执行；实际启动及验证状态以实施卡账本为准。

**目标：** 为反应堆耗尽后产生的枯竭铀燃料组件提供成本适中的完整生存去向，符合[首发准备计划D-03a](./2026-09-22-first-release-extension-preparation-plan.md#24-d-03a-已确认适中投入侧重流程与产线建设)的定位。玻璃基材、铅桶和贮存仍保留；两次装配合成一次灌封装桶，取消首发灌封中间物品及钢框架前置。本次确认覆盖该工序调整。

## 1. 当前基线与边界

- 热端闭环已经[联合验收并合入main](../../reviews/2026-10-05/condense-01/ACCEPTANCE.md)，准备基线`cc0804d`。Minecraft 1.21.1、Java 21、NeoForge 21.1.219、Create 6.0.10-280、Ponder 1.0.82、Flywheel 1.0.6均不变。
- 现有冷却乏燃料`cooled_spent_fuel_assembly`为单件物品，未保存温度或衰变热。现有屏蔽装配台为2×2×2、无GUI，底部动力，顶部投料、侧面投料/出料；只有新燃料四料配方。
- 已具备石英粉、铅板、钢板、密封环、屏蔽混凝土。补玻璃碎料、固化基材、铅屏蔽桶、已封装乏燃料桶及贮存架即可；尚未注册的钢框架和灌封中间件不进入本批。
- 本批实现当前版本的库存与保存恢复。热乏燃料、乏燃料池、再处理、辐射、污染、封装老化与旧存档迁移不属于本批；“已封存”表示物品处于规定封装/贮存位置，不宣称已经实现辐射屏蔽算法。

## 2. 推荐配方与运行参数

除有序布局另列的配方外，工作台配方均为无序。全部无副产物；原料使用已成立的公共材料标签，正式乏燃料和封装件使用自身身份并校验状态。数量写入数据配方，不另造一份硬编码数量合同。

| 输入 | 工序 | 输出 | 推荐参数 |
| :--- | :--- | :--- | :--- |
| 1无色玻璃块 | Create磨石；粉碎轮沿原生回退 | 1玻璃碎料`glass_dust` | `processing_time=100`，不覆盖其他玻璃配方 |
| 1玻璃碎料＋1石英粉＋1黏土球 | 工作盆普通加热搅拌 | 4玻璃固化基材`vitrification_medium` | `processing_time=100`；超级加热也允许，无额外奖励 |
| 4铅板＋1钢板＋1密封环 | 工作台有序 | 4铅屏蔽桶`lead_shielding_cask` | 2026-10-06用户改为有序，布局见STORE-01 R1；数量不变 |
| 1枯竭铀燃料组件＋1玻璃固化基材＋1铅屏蔽桶 | 屏蔽装配台，一次灌封装桶 | 1已封装乏燃料桶`sealed_spent_fuel_cask` | 12800 RPM·tick，64RPM参考10秒 |
| 1屏蔽混凝土＋2钢板 | 工作台无序 | 1干式贮存架`dry_storage_rack` | 直接造架，不新增钢框架制造工序 |

封装装配沿用现有最低32RPM、正反转同效、每tick按绝对转速计工且封顶256、应力4SU/RPM；停转、低速、过载和满输出暂停并保留有效进度。只有完成整批才同时扣料、产生一件输出。新装配工时从数据配方读取，不要求额外加热、流体或消耗品。

铅桶和贮存架均采用工作台制造。现有新燃料配方仍为8芯块＋4包壳＋2焊料＋1钢格架→1组件，25600 RPM·tick，不改变其成本或设备制造方式。

与第一版相比，处理4个枯竭组件的直接封装投入如下，不含架子及上游材料折算：

| 项目 | 第一版推荐 | 本版推荐 |
| :--- | :--- | :--- |
| 固化基材 | 16件 | 4件 |
| 空桶制作：铅板／钢板／密封环 | 24／8／4 | 4／1／1 |
| 封装装配累计耗时，64RPM | 160秒 | 40秒 |
| 连续自动封装所需装配台 | 两台串联 | 一台 |

上述设备数只比较封装段；玩家仍可分批复用燃料制造装配台，不强制另外制造一台。固化基材的一次搅拌可供4个组件使用，一次工作台制桶也供4个组件；单件封存的持续投料为1基材＋1空桶。

## 3. 装配台如何选择工序

| 接入方式 | 玩家体验与实现代价 | 结论 |
| :--- | :--- | :--- |
| 首种材料自动确定工序，清空后切换 | 四槽保持原有规模，自动线易过滤，不能混入其他工序材料 | **推荐** |
| 四槽混放，随时搜索任意完整配方 | 混入几种材料容易占满四槽，半批物料互相堵塞 | 本轮不采用 |
| 新设封装专机 | 增加设备成本、模型与教学，却重复屏蔽装配台职责 | 保留现有已确认设备路线 |

推荐方案的具体行为：

- 四个输入槽继续承担一批材料，侧面仍有唯一单件输出槽；各外表面接口和现有人工退料方式不变。
- 第一件合法原料确定当前工序：四种新燃料原料→制造；枯竭组件、固化基材或空铅桶→封存。其他工序材料原样拒收。
- 输入、输出和进度全部清空后解除工序选择；玩家可在同一台机器分批切换，连续封存只需一台装配台。不新增菜单、过滤槽或专用模式工具。
- 活动工序、配方身份、完整输入/输出物品栈和有效进度由主控在服务端唯一持有，副方块与JEI仅查询。多面同时访问和`SIMULATE`不得重复扣料、重复出料或改变工序。
- 退料导致不足一批、配方重载后失效时清除对应进度；不得把旧工序进度带到另一配方。新增封存配方须在JEI显示三种材料数量、设备和64RPM参考耗时，不能显示不存在的第四种输入。

## 4. 封装状态与库存守恒

- 枯竭组件和封装桶均不可堆叠；每个封装桶恰好代表一个原始枯竭组件。空铅桶和普通材料按普通物品堆叠。
- 封装后的物品保存原始组件的完整单件记录，不嵌套灌封库存。材料属于已消耗成本，不作为可重复提取的附属库存。
- 形态由正式物品身份表示，组件记录必须有效且恰好一件；非法载荷拒收并提示原因。封装桶保留原始组件数据，不增添温度、衰变热、燃料寿命或放射性数值。
- 不允许直接把新燃料装桶，也不提供拆桶、反向配方、熔炼或销毁成材料的正常处理路线。贮存架取出的仍是同一封装桶，不恢复可用燃料。
- 包含原始组件的记录是该封装物品的内容，并非另一份可访问的物品库存；配方完成、搬运、拆机和掉落都必须保持单位数量守恒。

## 5. 干式贮存架

推荐先做**占满一格的独立设备、默认16个单件库存槽**，无需动力或成型。外观为钢制封闭柜架＋屏蔽混凝土底座，正面四个储藏区按占用比例显示状态，不把四个可见储藏区误当成四个库存槽；实际桶数由护目镜显示。四向放置，正面对玩家；沿用已认可SVG素材风格，建模与碰撞一致，不使用生图模型。门体与静态柜架分离，保留未来搬运动画接入点。

- 手持有效封装桶右击放入一件；空手右击取出一件，玩家背包无空间时保持库存。取出顺序固定为最后一个占用槽。
- 顶部和四侧均可通过原版/Create漏斗输入或取出完整封装桶，底部可取出；只接收已封装乏燃料桶，不要求每桶独立外部接口。过滤由外接黄铜漏斗承担。
- 已存桶由方块实体唯一持久化；空架、未装架的封装桶与架内贮存是不同位置状态，不生成额外“安全桶”注册ID。
- 工程师护目镜显示已用/可用桶位及“已封装乏燃料贮存”，采用现有统一缩进避免遮字。普通右击不打开GUI。
- 正常拆除或扳手收取时，贮存架与所存封装桶各自掉落一次；不把桶同时写入架子掉落物，创造模式拆除也须保全已存桶。满架拒收，不丢物、不重复掉落。
- 默认容量16，SERVER配置`spentFuelStorage.rackSlots`可设1～16；当前版本修改容量不会删除已存桶，超过新容量的已有槽只许取出，不再接收新桶。配方数量和加工时间由JSON管理，配置与配方均不能被功能代码再次锁死。
