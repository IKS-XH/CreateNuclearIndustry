# 乏燃料基础封存：首轮实施方案

**状态：** 2026-10-05用户要求开始准备；本文新增数量、耗时、容量和交互为PM推荐，待用户集中确认。尚未派发实现，不代表功能已存在。

**目标：** 为反应堆耗尽后产生的枯竭铀燃料组件提供完整生存去向：制备玻璃固化基材→屏蔽装配台灌封→铅桶封装→干式贮存架。工序与首发范围沿用[首发准备计划D-01](./2026-09-22-first-release-extension-preparation-plan.md#21-d-01-已确认先制备后处理)，本次只冻结剩余细节。

## 1. 当前基线与边界

- 热端闭环已经[联合验收并合入main](../../reviews/2026-10-05/condense-01/ACCEPTANCE.md)，准备基线`cc0804d`。Minecraft 1.21.1、Java 21、NeoForge 21.1.219、Create 6.0.10-280、Ponder 1.0.82、Flywheel 1.0.6均不变。
- 现有冷却乏燃料`cooled_spent_fuel_assembly`为单件物品，未保存温度或衰变热。现有屏蔽装配台为2×2×2、无GUI，底部动力，顶部投料、侧面投料/出料；只有新燃料四料配方。
- 已具备石英粉、铅板、钢板、钢杆、密封环、屏蔽混凝土。玻璃碎料、固化基材、钢框架、铅屏蔽桶、两种封装件及贮存架尚未注册，需要本批补齐。
- 本批实现当前版本的库存与保存恢复。热乏燃料、乏燃料池、再处理、辐射、污染、封装老化与旧存档迁移不属于本批；“已封存”表示物品处于规定封装/贮存位置，不宣称已经实现辐射屏蔽算法。

## 2. 推荐配方与运行参数

除有序布局另列的配方外，工作台配方均为无序。全部无副产物；原料使用已成立的公共材料标签，正式乏燃料和封装件使用自身身份并校验状态。数量写入数据配方，不另造一份硬编码数量合同。

| 输入 | 工序 | 输出 | 推荐参数 |
| :--- | :--- | :--- | :--- |
| 1无色玻璃块 | Create磨石；粉碎轮沿原生回退 | 1玻璃碎料`glass_dust` | `processing_time=100`，不覆盖其他玻璃配方 |
| 1玻璃碎料＋1石英粉＋1黏土球 | 工作盆普通加热搅拌 | 4玻璃固化基材`vitrification_medium` | `processing_time=100`；超级加热也允许，无额外奖励 |
| 4钢板＋4钢杆 | 工作台3×3 | 4钢框架`steel_frame` | `PRP/R R/PRP`，P钢板、R钢杆 |
| 6铅板＋2钢板＋1密封环 | 工作台3×3 | 1铅屏蔽桶`lead_shielding_cask` | `LPL/LRL/LPL`，L铅板、P钢板、R密封环 |
| 1枯竭铀燃料组件＋4玻璃固化基材 | 屏蔽装配台 | 1灌封乏燃料件`encapsulated_spent_fuel` | 25600 RPM·tick，64RPM参考20秒 |
| 1灌封乏燃料件＋1铅屏蔽桶 | 屏蔽装配台 | 1已封装乏燃料桶`sealed_spent_fuel_cask` | 25600 RPM·tick，64RPM参考20秒 |
| 4屏蔽混凝土＋5钢框架 | 工作台3×3 | 1干式贮存架`dry_storage_rack` | `FCF/CFC/FCF`，F钢框架、C屏蔽混凝土 |

两道装配均沿用现有最低32RPM、正反转同效、每tick按绝对转速计工且封顶256、应力4SU/RPM；停转、低速、过载和满输出暂停并保留有效进度。只有完成整批才同时扣料、产生一件输出。新装配工时从数据配方读取，不要求额外加热、流体或消耗品。

钢框架和铅桶优先工作台制造，落实用户对后续配方谨慎使用序列装配的要求。现有新燃料配方仍为8芯块＋4包壳＋2焊料＋1钢格架→1组件，25600 RPM·tick，不改变其成本或设备制造方式。

## 3. 装配台如何选择工序

| 接入方式 | 玩家体验与实现代价 | 结论 |
| :--- | :--- | :--- |
| 首种材料自动确定工序，清空后切换 | 四槽保持原有规模，自动线易过滤，不能混入其他工序材料 | **推荐** |
| 四槽混放，随时搜索任意完整配方 | 混入几种材料容易占满四槽，半批物料互相堵塞 | 本轮不采用 |
| 新设封装专机 | 增加设备成本、模型与教学，却重复屏蔽装配台职责 | 保留现有已确认设备路线 |

推荐方案的具体行为：

- 四个输入槽继续承担一批材料，侧面仍有唯一单件输出槽；各外表面接口和现有人工退料方式不变。
- 第一件合法原料确定当前工序：四种新燃料原料→制造；枯竭组件或固化基材→灌封；灌封件或空铅桶→封装。其他工序材料原样拒收。
- 输入、输出和进度全部清空后解除工序选择；玩家可在同一台机器分批切换，也可用两台串联完成自动灌封和装桶。不新增菜单、过滤槽或专用模式工具。
- 活动工序、配方身份、完整输入/输出物品栈和有效进度由主控在服务端唯一持有，副方块与JEI仅查询。多面同时访问和`SIMULATE`不得重复扣料、重复出料或改变工序。
- 退料导致不足一批、配方重载后失效时清除对应进度；不得把旧工序进度带到另一配方。新增两种配方须在JEI显示材料数量、设备和64RPM参考耗时，不能显示不存在的四种输入。

## 4. 封装状态与库存守恒

- 三种含乏燃料形态均不可堆叠；每个灌封件、封装桶恰好代表一个原始枯竭组件。空铅桶和普通材料按普通物品堆叠。
- 转换后的物品保存对应原始组件的完整单件记录，装桶时转移该记录，不再嵌套第二份灌封库存。材料属于已消耗成本，不作为可重复提取的附属库存。
- 形态由正式物品身份表示，组件记录必须有效且恰好一件；非法载荷拒收并提示原因。灌封件与封装桶保留原始组件数据，不增添温度、衰变热、燃料寿命或放射性数值。
- 不允许直接把新燃料装桶，也不提供拆桶、反向配方、熔炼或销毁成材料的正常处理路线。贮存架取出的仍是同一封装桶，不恢复可用燃料。
- 包含原始组件的记录是该封装物品的内容，并非另一份可访问的物品库存；配方完成、搬运、拆机和掉落都必须保持单位数量守恒。

## 5. 干式贮存架

推荐先做**占满一格的独立设备、默认4个单件桶位**，无需动力或成型。外观为钢框架＋屏蔽混凝土底座，正面2×2圆筒桶位；空满状态可区分，四向放置，正面对玩家。沿用已认可SVG素材风格，建模与碰撞一致，不使用生图模型。动件与静态框架分离，保留未来搬运动画接入点。

- 手持有效封装桶右击放入一件；空手右击取出一件，玩家背包无空间时保持库存。取出顺序固定为最后一个占用槽。
- 顶部和四侧均可通过原版/Create漏斗输入或取出完整封装桶，底部可取出；只接收已封装乏燃料桶，不要求每桶独立外部接口。过滤由外接黄铜漏斗承担。
- 已存桶由方块实体唯一持久化；空架、未装架的封装桶与架内贮存是不同位置状态，不生成额外“安全桶”注册ID。
- 工程师护目镜显示已用/可用桶位及“已封装乏燃料贮存”，采用现有统一缩进避免遮字。普通右击不打开GUI。
- 正常拆除或扳手收取时，贮存架与所存封装桶各自掉落一次；不把桶同时写入架子掉落物，创造模式拆除也须保全已存桶。满架拒收，不丢物、不重复掉落。
- 默认容量4，SERVER配置`spentFuelStorage.rackSlots`可设1～4；当前版本修改容量不会删除已存桶，超过新容量的已有槽只许取出，不再接收新桶。配方数量和加工时间由JSON管理，配置与配方均不能被功能代码再次锁死。
