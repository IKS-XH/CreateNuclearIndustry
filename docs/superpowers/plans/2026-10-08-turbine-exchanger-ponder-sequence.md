# 汽轮机与换热器：后续功能和思索排期

**状态（2026-10-08）：** 用户已明确后续顺序。本文件记录排期与范围，不代替具体实现卡，不提前关闭任何人工验收门。
**维护者：** 用户任命的现任项目经理；实现由执行者承担，PM负责计划、审查、验收与Git。

## 已确认安排

1. 先完成汽轮机思索。沿上轮建议围绕搭建、通汽与动力输出、流量与效率准备情景，讲解现有三档规模、核心先行辅助包壳、双轴共享应力及启动门槛；不修改汽轮机机制。
2. 汽轮机思索完成并通过本台播放门后，优先补齐换热器的工作盆供热功能：复用既有换热器，允许其代替烈焰人燃烧室成为Create工作盆的热源，不另造只负责适配的设备。
3. 工作盆供热功能实现并通过集中手测后，为换热器制作分情景思索，分别介绍它的不同用途。蒸汽冷凝回水属于既有换热器功能，不作为独立设备教学插入第二步之前。

该安排替代此前“工作盆继续后置”和“汽轮机后单独接冷凝设备教学”的排期。反应堆可变结构、辅助热、二级耐压、事故/辐射及动画等其他主线仍不自动接续；首发前不研究旧存档兼容。

## 换热器功能边界

- 用户随后明确取消换热器输入超临界蒸汽的功能。原“超临界蒸汽→蒸汽并供热”规划撤销，不实现入口、专属配置或教学；只接受热复合冷却剂进行核热换热、普通 `steam` 进行冷凝回水。现有实现已拒收超临界蒸汽，不影响汽轮机入口或锅炉双汽库存。

- 已有独立核热供Create锅炉、定向冷热循环与同向直列共享库存；已有高压锅炉底部内置换热器；已有蒸汽冷凝回水。
- 新增范围仅为工作盆热源接入。无GUI，冷热液体积1:1、服务端唯一热账本与查询无副作用继续适用，不改变已验收锅炉/汽轮机的热工与效率参数。
- 原[工作盆接入核查](./2026-10-04-heat-exchanger-basin-preparation.md)恢复为第二步的技术准备入口。此前普通/超级加热兼容方向保留；每盆耗热、启动门槛、低流量热级、有效加工判定及中途断热语义仍须依据锁定Create源码形成完整方案，集中确认未决取舍后才能派发功能实现。
- 空盆、缺料、停转、输出堵塞不应持续耗热；不得为绕过热条件匹配而免费供热、只按放盆耗热或复制另一套不一致的配方引擎。
- 工作盆耗热及新增运行参数按既有用户要求进入配置，不直接复用锅炉18级数值作为配方热级或耗热单位。

## 换热器思索建议分场景

以下是教学划分建议，具体镜头、模板与文案在功能定稿后整理，不提前演示未实现行为：

| 情景 | 聚焦内容 |
| :--- | :--- |
| 独立供热与冷热循环 | 热液入口、冷液出口、同向直列以及给Create锅炉供热 |
| 高压锅炉内置换热 | 换热器作为底部结构、与再加热段形成有效热力回路；简短衔接已验收锅炉教学 |
| 工作盆加热 | 工作盆与换热器的摆放、冷热液回路和实际加工热级 |
| 蒸汽冷凝回水 | 蒸汽输入与回水、顶部冷源、冷源消耗及独立回水管路 |

文案保持短句，只讲设备特有操作与规则，删除开发措辞和Create基础常识。同一时刻只显示一段正文；主要端口和去向放在可见侧。不单独追加重复的停机/排查页。
