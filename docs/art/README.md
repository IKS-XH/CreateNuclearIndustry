## 职责与文件边界

美术负责人主持贴图、建模、动画方案与任务管理，执行者负责具体实现；可在本目录制定计划、规范、报告并审查资源候选。用户视觉与动画验收单独记录；美术负责人不是全局项目经理，不能改变全局人工门、玩法数值或其他任务排期。Git写操作和集成由主逻辑PM或用户完成。

优先沿用已认可的Create工业风格、SVG来源和可复现的资源工具。无需生图模型；先实际查看现有资源和已认可样例，不凭印象整体重画。记录源文件、导出文件、材质、模型分件、枢轴和许可来源。保留稳定注册ID与资源引用，不复制外部Mod资产作为本项目原创内容。

每批任务应列出确切资源/源码写集、视觉目标、哪些分件静止/运动、枢轴及客户端状态来源、必要验证和人工预览。普通资源变更只做资源引用/模型结构检查与一次增量打包；实际动画接入再验证客户端渲染生命周期。不能为美术任务增加无关全套测试、旧存档兼容或玩法改造。

贴图/模型资源、SVG或建模源文件、相关导出工具由美术側按任务划分管理。Java客户端渲染器、PartialModel注册及共享语言文件不是永久独占；修改前先明确写集和基线，主逻辑PM集成时处理另一侧新增项。服务端热工、流体、动力、库存、配方、注册身份、碰撞/放置交互、网络同步和配置不属于本次自主美术写集。

动画应先分离静止壳体与轴、叶片、机械臂等运动部件；沿用真实设备状态。缺少状态接口时写出所需输入、单位、采样/同步要求及降级显示，由主逻辑PM安排逻辑侧任务。两边不得同时修改同一共享文件；跨范围问题暂停相关片段并协调，不自动转成实现授权。
