## 3. 数值合同

### 3.1 维度与坐标

- 表单使用外尺寸 `length × width × height`，单位为方块；默认 `5 × 5 × 5`。
- 有效堆芯横截面为 `(length - 2) × (width - 2)`，有效高度为 `height - 2`。三者均必须至少为 `1`；外尺寸最小为 `3 × 3 × 3`。
- 为避免浏览器一次模拟过大，首版 UI 上限为每边 `31`、总有效列数 `≤ 841`、有效高度 `≤ 29`。这是工具性能保护，不是游戏尺寸规则。
- 每个横截面位置只是一根垂直列，列类型只能是燃料列、控制棒列、空列之一；四向邻接仅使用北、南、东、西，绝不使用对角线。

### 3.2 三种列类型的任意组合布局

堆芯横截面是一个可逐格编辑的二维画布，不存在固定的三种布局限制。用户可在每个坐标放置下列任一列类型，并可拖动涂刷、框选填充、单格切换、清空画布及导入布局矩阵。

| ID | 列类型 | 计算语义 |
| :--- | :--- | :--- |
| `fuel` | 燃料列 | 持有燃料等价容量、完整度、缓存热量与列级发热/燃耗；仅与四向直接相邻的燃料列形成超频反馈簇；失效后可向四向有效燃料列或控制棒列传播余热。 |
| `control_rod` | 控制棒列 | 持有独立完整度、实际/目标插入深度和卡死状态；只抑制四向相邻的孤立燃料列，接收失效燃料的余热损伤但不继续传播。 |
| `empty` | 空列 | 不持有燃料、控制棒、完整度或余热；不发热、不冷却、不参与损伤，且完全切断燃料超频反馈、控制棒控制和余热传播。 |

空画布、无燃料画布和无控制棒画布都是合法的实验场景，模拟器应输出零发热或相应警告，绝不静默替换为其他布局。只有外尺寸、枚举值或总有效列数违反限制时才拒绝运行。布局矩阵必须以 `fuel`、`control_rod`、`empty` 保存，作为导入导出和回归测试的权威表示。

可提供“全燃料”“棋盘控制棒”“中心十字控制棒”三个一键示例预设以便比较，但它们仅负责填充画布，用户随后可以任意编辑；它们不是堆芯类型，也不是游戏内结构限制。

### 3.3 可配置输入项

表单必须分组、带单位、范围、默认值、重置按钮和非法值说明。输入分为：

| 分组 | 必须可设定的参数 |
| :--- | :--- |
| 几何与布局 | 长、宽、高；逐格燃料/控制棒/空列画布；可选示例预设；初始运行/停堆状态；每根控制棒的默认插入深度。 |
| 控制棒 | `controlResponseExponent`；每根控制棒 `0～100%` 目标/实际插入深度；一键全插、全拔、恢复默认。 |
| 发热与燃耗 | `baseHeatPerFuel`、`burnHoursPerBlock`（和 `baseBurnPerFuel` 二选一）、`fuelCapacityPerBlock`、`overclockHeatMultiplier`、`overclockBurnMultiplier`、`overclockFeedbackGain`、`overclockFeedbackExponent`、`totalHeatMultiplierCap`。 |
| 冷却剂端口 | 冷端口数量、热端口数量、单端口输入/输出流量上限、全堆总流量上限、`coolantAbsorptionHuPerMb`、本 tick 实际可用冷端输入与热端可接收量。 |
| 损伤与融毁 | `fuelColumnDamageHeatThreshold`、`fuelColumnDamageRate`、`fuelColumnDamageTransferRate`、`controlRodColumnFailureThreshold`、`meltdownTriggerFraction`、`meltdownCountdownTicks`、余热安全阈值。 |
| 时间与场景 | tick 步长（仅 `1`、`20`、`100`，内部仍逐 tick 结算）、运行 tick 数、暂停/继续、单步、重置、预设场景。 |

默认值必须与 `docs/reactor-local-control-revision-design.md` 的 P1 原型表一致：`1.0 HU/t`、`3 h`、`1.0 HU/mB`、每端口 `100 mB/t`、总流量 `200 mB/t`、损伤阈值 `0.25 HU/t`、损伤速率 `0.00125/(tick·HU/t)`、传播率 `0.25`、融毁阈值 `0.20`、融毁倒计时 `900 ticks`；不在文档中冻结的参数必须在 UI 标为“工具实验默认值”，并输出到导出的场景文件。

### 3.4 每 tick 固定结算顺序

求解器必须只依赖上一个 tick 快照，禁止因网格遍历顺序产生不同结果。每 tick 顺序固定为：

1. 读取 SCRAM/运行开关、实际控制棒深度和上 tick 燃料/完整度/余热快照。
2. 为孤立燃料列计算相邻控制棒的平均有效插入深度与 `controlledIntensity = (1 - meanDepth)^controlResponseExponent`。
3. 对相邻燃料列簇，按核心设计的单调有界迭代计算超频热/燃耗强度；最大 `256` 轮，变化小于 `1e-9` 视为收敛。超频簇不读取控制棒深度。
4. 对每个有效燃料列计算 `damageMultiplier = 1 + (1 - integrity)`、列级发热、燃耗和剩余燃料；完整度或燃料归零后自下一 tick 起不再产生新裂变热或燃耗。
5. 按冷端实际输入、热端实际输出容量、端口上限、全堆上限、内置冷却剂库存、可用发热和 `coolantAbsorptionHuPerMb` 的最小值结算总转换量。`coldIn` 与 `hotOut` 是外部端口实际流量，可因内部冷/热冷却剂库存而在同一 tick 不相等；账本必须满足 `coldAfter = coldBefore + coldIn - convertedMb`、`hotAfter = hotBefore + convertedMb - hotOut`，两者非负且总量不超过反应堆冷却剂容量。
6. 以确定性的比例分配冷却能力：优先按当 tick 各燃料列 `generatedHeat` 权重分配；权重为零时不分配。输出每列 `removedHeat`、`netHeatLoad`、余热缓存与总冷/热转换速率。
7. 仅对超过安全阈值的 `netHeatLoad` 扣除燃料列完整度；冷却足够时损伤为零，即使该列处于超频。
8. 以传播前快照，从完整度为零的燃料列按四向传播其当前残余热量。目标列可用的冷却先抵消传播热量；燃料目标承受完整度损伤，控制棒目标承受控制棒完整度损伤且不向外继续传播。不得保存独立传播标记。
9. 本 tick 实际被传播热量触达的有效燃料列比例达到 `meltdownTriggerFraction` 时建立融毁倒计时；倒计时只增加。SCRAM 且有效冷却可暂停，不能回退；所有燃料/控制棒列恢复到 `1.0` 才可重置。

燃料组件以“每列有效高度份等价燃料容量”建模：`fuelCapacity = fuelCapacityPerBlock × internalHeight`，而不是预先决定游戏内端口的 ItemStack 排布。页面必须将此项标为模拟抽象，并输出每列燃料组件等价剩余量、消耗率和预计耗尽 tick/秒/分钟。实际 P1 的物品事务仍以游戏实现任务为准。

## 4. 页面与输出合同

页面首次加载须显示默认 `5×5×5`、可编辑的堆芯画布和三个可选示例预设。改变尺寸、画布或任何参数时，只能在点击“应用并重置”后重建状态；运行中修改参数必须先暂停并给出提示，防止图表和状态混用。

### 4.1 必须显示的结果

- 总览：有效尺寸、燃料/控制棒列数量、当前 tick/游戏时间、状态（运行、SCRAM、倒计时、暂停倒计时、已融毁）、总 `HU/t`、总燃耗、总余热、冷却剂需求/实际输入/热输出、端口与总流量瓶颈。
- 堆芯网格：燃料列按当前 `HU/t` 或完整度着色；控制棒显示插入深度、完整度和卡死状态；可切换“发热、完整度、燃料剩余、净热负荷、余热、控制棒深度、传播触达”图层。
- 列详情：点击任一燃料列显示发热量、控制/超频/损伤倍率、组件等价剩余量、燃耗率、预计耗尽时间、冷却带走热量、净热负荷、完整度/损坏度和四向邻居；点击控制棒显示插入深度、完整度和卡死原因。
- 趋势：总发热、冷却转化、最高净热负荷、最低完整度、损坏/卡死列数、燃料耗尽列数和融毁倒计时进度的时间序列图；不允许用随机采样隐藏峰值。
- 警告：超频簇、冷端不足、热端堵塞、总流量受限、列完整度下降、控制棒卡死、达到融毁阈值、倒计时暂停及已融毁，均须说明造成它的具体列/端口/参数。

### 4.2 导入、导出和复现

- 导出当前场景 JSON：必须包括工具版本、输入配置、列类型矩阵、逐棒深度、初始状态、运行 ticks、最终快照与摘要。
- 导入 JSON 必须校验 schema/version，未知字段可忽略，缺失字段采用文档化默认值；不得执行文件中的脚本或 HTML。
- 导出 CSV：一行一个 tick 的总览，以及一行一列的最终快照；CSV 表头须带单位。
- 每次导出都写入计算规则版本和是否达到迭代收敛。未收敛时运行必须停止，并在报告中标为失败，不能输出伪稳定数据。

## 5. 原子任务卡

### SIMWEB-01：建立静态工具骨架与配置契约

**前置：** 无。
**唯一目标：** 建立 `tools/reactor-simulator/` 静态入口、默认配置、输入范围和 README。
**验收：** 离线静态服务器可打开；默认值与核心设计表逐项一致；无网络请求和第三方依赖。
**交付：** 文件树、默认配置对照表、打开方式。

### SIMWEB-02：实现尺寸、三种列类型和列级编辑模型

**前置：** SIMWEB-01。
**唯一目标：** 实现可验证的有效尺寸、燃料/控制棒/空列任意画布、四向邻接和逐根控制棒深度编辑。
**验收：** `5×5×5` 自定义混合画布的列数/坐标/邻接快照测试；空画布、无燃料、无控制棒均可得到确定性结果；最小尺寸、非法枚举和超上限尺寸被明确拒绝。
**交付：** 三种列类型图例、矩阵格式、坐标测试和错误提示截图。

### SIMWEB-03：实现纯数值求解器（发热、控制、超频、燃耗）

**前置：** SIMWEB-02。
**唯一目标：** 在无 DOM 模块中实现前四个结算步骤。
**验收：** 固定输入重复运行得到位级相同输出；测试覆盖孤立燃料、全插控制棒、全拔控制棒、超频簇、完整度反馈、燃料耗尽和高度同比关系。
**交付：** 公式说明、收敛报告和单元测试结果。

### SIMWEB-04：实现多端口冷却剂账本与列级热负荷

**前置：** SIMWEB-03。
**唯一目标：** 实现冷/热端口数量、端口/总流量限制、守恒转换和按发热权重的列级冷却分配。
**验收：** 无热、冷端不足、热端不足、单端口上限、总上限、多端口但总上限不变、冷/热内部库存与外部端口流量的守恒误差为零。
**交付：** 每 tick 冷/热库存账本测试和瓶颈显示说明。

### SIMWEB-05：实现损伤、传播、控制棒卡死和融毁状态机

**前置：** SIMWEB-04。
**唯一目标：** 实现结算步骤 7～9 及状态快照。
**验收：** 覆盖冷却足够的超频不损伤、热负荷越高损伤越快、对角不传播、控制棒终止传播、卡死深度保持、20% 阈值、倒计时暂停不回退、全列修复后重置。
**交付：** 状态机表、确定性传播测试和融毁场景 JSON。

### SIMWEB-06：实现可视化、时间控制和列详情

**前置：** SIMWEB-05。
**唯一目标：** 实现输入表单、网格层、列详情、趋势与警告，不修改求解器算法。
**验收：** 任意混合画布均可操作；每根控制棒深度可编辑；空列的阻断效果可见；所有“必须显示的结果”可见，键盘可达且颜色不作为唯一状态载体。
**交付：** 人工验收步骤、截图和已知 UI 限制。

### SIMWEB-07：实现导入导出、回归场景与交接报告

**前置：** SIMWEB-06。
**唯一目标：** 实现场景 JSON/CSV、导入校验和六个可重放回归场景。
**回归场景至少包括：** P1 默认 `5×5×5`、含空列隔离的自定义画布、含控制棒隔离的自定义画布、安全超频、冷端受限、热端受限、传播后暂停融毁。
**验收：** 导出后重新导入得到同一最终快照；无效 JSON 不改变当前场景；全部数值测试与浏览器人工验收通过。
**交付：** `build/reports/reactor-simulator/SIMWEB-final-handoff.md`、场景文件和测试日志；执行者停止修改，等待项目经理验收。
