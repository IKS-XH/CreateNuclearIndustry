## 2. 中文注释质量合同

### 2.1 必须使用中文说明的内容

- 每个手写生产代码类型的职责，以及它是否拥有权威状态。
- 公共或跨包调用入口的目的、重要参数、返回结果、副作用和拒绝条件。
- 服务端与客户端的职责边界，特别是网络包、滑块、Ponder 和显示适配。
- NeoForge 注册与生命周期入口、Create 行为接入点和方块实体 ticker 的调用时机。
- NBT 字段语义、版本兼容、不变量和加载失败策略。
- 热量使用 `HU`/`HU/t`、流体使用 `mB`/`mB/t`、深度与完整度使用 `[0,1]` 时，必须在相关公式或状态入口说明单位。
- 控制棒、SCRAM、冷却剂账本、燃耗、损伤传播和融毁状态机的非显然顺序与特殊分支。
- 测试夹具中不明显的结构坐标、边界值和回归意图。

### 2.2 不应添加的注释

- 对 import、花括号、普通 getter/setter、构造器赋值和明显条件进行逐行翻译。
- 只写“初始化变量”“调用方法”“返回结果”等不能补充语义的信息。
- 猜测尚未冻结的玩法、未来功能、性能结论或第三方 API 行为。
- 把注释当成禁用代码、临时备份或 TODO 堆积区。
- 为追求覆盖率给每一行机械添加注释。

### 2.3 语言与格式

- 注释、Javadoc、`TODO`/`FIXME` 说明一律使用简体中文和 UTF-8。
- Java 标识符、注册 ID、NBT 键、网络字段、API 类型名和单位可保留英文，并用反引号或原始拼写避免误译。
- Javadoc 首句直接说明职责；正文重点解释“为什么”和“不变量”，不复述方法签名。
- 触及已有英文注释时，将与本项目手写逻辑相关的部分改为准确中文。许可证、第三方源码、生成内容和必须原样保留的协议文本不翻译。

## 3. 绝对实现边界

本计划所有任务都必须满足：

- 只允许新增、删除或翻译注释和 Javadoc；不得改变可执行语句、声明、注解、修饰符、导入、包名、方法签名、常量、字符串、资源、配置、NBT、注册 ID 或测试断言。
- 不得进行重命名、重构、抽取方法、排序 import、全文件格式化或顺手修复缺陷。
- 发现注释无法在不改代码的前提下准确表达行为时，记录疑点并跳过该位置，等待项目经理决策。
- 任何行为改动都必须退回对应功能任务，不能混入注释专项。
- 执行者不得执行 Git 提交、回退、建分支、切换、合并、变基、清理或历史改写；不得修改核心文档和活动计划。

当前已验收 `HEAD` 基线共有 97 个 `src/main/java` 手写 Java 文件和 29 个 `src/test/java` 测试文件；工作区中尚未验收的活动功能代码不计入该数字。任务开始时必须重新盘点；后续功能任务新增的代码由其执行者按本计划第 7 节即时补注释，不等待存量专项返工。

## 4. 并行与文件所有权规则

- 注释任务不得与功能任务同时修改同一个文件。
- 接单前必须用只读 Git 检查记录未提交文件，并由项目经理给出本任务的精确文件清单。
- 若任务范围中的文件正在被 `P1-LOOP-*`、`P1-PONDER-*` 或其他功能任务修改，执行者必须跳过并报告，不得合并双方工作。
- 下列任务可在文件清单完全不重叠时并行；同一任务卡内部不得由多人分割同一个文件。
- 每张任务卡完成后只提交报告，由项目经理验收和提交，再派发依赖任务。

## 5. 单张任务的统一验收门

每张任务卡必须完成以下检查：

1. 开工前记录 `git status --short --branch`、任务文件清单和基线测试结果。
2. 逐文件复核差异，确认除注释、Javadoc 和空行外没有 Java 语义变化。
3. 运行 `git diff --check`。
4. 运行 `./gradlew.bat test --rerun-tasks --max-workers=1`。
5. 涉及 NeoForge 生命周期、方块实体、网络、Create、Ponder 或 GameTest 源码时，再运行 `./gradlew.bat runGameTestServer --rerun-tasks --max-workers=1`。
6. 报告实际修改文件、跳过文件、仍缺注释位置、测试数量和结果。

若测试基线在改动前失败，立即停止并报告。若改动后失败，只允许回退本任务自己的注释改动或报告；不得修改生产逻辑和测试断言来恢复通过。

## 7. 后续所有功能任务的永久规则

从本计划建立之日起，任何执行者新增或修改手写代码时，必须在同一任务内完成对应中文注释，不得留给 `P1-COMMENT-*` 任务兜底：

- 新增类型必须有中文职责说明。
- 新增公共/跨包入口和非显然状态转移必须有中文 Javadoc 或行内说明。
- 修改行为时必须同步更新原有注释，删除已经失真的说明。
- 交付报告必须增加“中文注释检查：通过/不适用（说明原因）”。
- 项目经理验收时把中文注释作为与测试、资源和兼容性同级的完成条件；不合格任务退回整改。
