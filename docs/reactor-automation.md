# 反应堆管理员现行合同

更新：2026-10-20。用户明确移除管理员应力余量闭环；现行范围为统一调棒、恒功率、GUI与保存续接。原设计/实施过程及既有人工结果保留在[归档](archive/2026-10-15/README.md)，当前结果见[STATUS](STATUS.md)。配置默认值只在[server-config](server-config.md)维护。

## 接入和控制权

反应堆侧壁合法位置安装`reactor_automation_port`，相邻烈焰人燃烧室任职管理员；接口是结构成员，不是第二个模拟所有者。没有管理员时原局部控制照常工作。仪表端口始终拥有权威热工/库存/事故状态，管理员只提交受验证的全堆统一目标。

控件放在燃烧室上：空手右击任职燃烧室打开GUI，手持有效燃料保原补料入口，扳手/机械臂保原行为。管理员运行时统一控制可动棒；SCRAM、卡死、结构失效等更高优先级边界不能由GUI/自动化绕过。逐棒和管理员交接须经过服务端安全基准，不能从客户端草稿直接获得运行许可。

## 三页GUI

| 页面 | 信息/操作 |
| --- | --- |
| 总览 | 结构/运行状态、模式及目标/实际/可达毛HU、实际/目标棒位、冷热共享库存、可用/枯竭/空燃料列、供能与核热自耗 |
| 堆芯 | 按真实截面显示燃料/控制棒/空列，选择查看燃料、完整度、积热、覆盖与卡死；网格只读，装换料仍通过世界端口 |
| 保护 | 结构、供能、冷却、覆盖、卡死和红石联锁及真实复位条件；保护阈值只读，不能在GUI关闭保护 |

模式/数值先形成草稿，“应用”经服务端原子校验后生效；启动独立。停堆在所有页可用，复位独立确认；Esc/关界面丢弃未提交编辑，不撤销已确认运行状态，也不暂停反应堆。服务端核距离、真实实例、结构代际和设置版本，旧多人提交不能覆盖新设置。

## 模式与调节

- 统一深度：以一个目标调节全堆可移动控制棒。
- 恒定发热：依据当前堆芯可达范围追踪玩家HU/t目标，显示平均值不延迟每tick保护。

默认每10tick调节，升功率提出最多1个百分点、降功率插入最多5个百分点。保护优先于任何目标：复用冷库存/热库存及逐列积热，不另实现流量安全测量、库存保持模式或锅炉/汽轮机遥测。管理员不再绑定应力表或依据动力网余量调棒；电站协调构想仍后置。

## 供能与燃料

冷启动先给燃烧室一个有效燃料。任职管理员可用反应堆真实核热维持普通燃烧，默认自耗1HU/t，维护先于冷却足额扣账，不凭显示值无限续燃、不重复支付，也不冒充事故冷却能力。

部分燃料列耗尽/为空时，只要仍有可用燃料就不因该原因整堆停机；重新计算可达功率和冷却需求。可用燃料全部耗尽才缺料保持；补料后仍按故障/复位规则恢复，不能自行提棒。未覆盖有效燃料、卡死、真实冷却不足、失联或红石急停的保护保持。

## 故障、联锁与保存续接

运行许可由任职燃烧室输出，按原方案经红石反相接仪表急停。故障保持要求人工复位，健康稳定窗口和当前安全检查须真实满足，不能由GUI隐藏或跳过。

正常保存重进保管理员模式/目标、逐棒实际与目标深度和调节进度。加载时暂缓本机结算，经当前结构、供能、冷却与红石检查及真实首费后直接续接，不先全插或要求再次启动。人工停堆、故障、急停保持停机；真实运行失联仍触发保护。

客户端只读取显示投影，界面常驻不拥有核心状态。一次GPU内存事故仍仅记录未复现，未归因，不把本合同当作该事故已修复证明。
