## 首轮审查记录

首轮结论为暂不通过。下面列出首轮阻断以及 R1 复核状态，保留失败经过。

1. **锅炉幕冷液罐 Java 坐标与模板不一致。**

   首轮 [HeatExchangerPonderScenes.java](src/main/java/com/iksxh/create_nuclear_industry/ponder/HeatExchangerPonderScenes.java) 的 `BOILER_COLD_TANK` 指向 `(6,0,1)`，但锅炉模板在 `(6,2,1)` 放冷液罐；因此冷液储罐 selection 和蓝色连线指向底板方块。R1 已将常量改成 `(6,2,1)`，连线与高亮现在指向真实罐位置；测试也检查 Java 常量与模板位置一致。首轮问题已关闭。

2. **独立供热幕没有呈现可辨识的 Create 锅炉。**

   首轮只有换热器上方的储罐。R1 加入 2×2 共同储罐组和西侧两台蒸汽机；方块状态为 Create 有效的 `face=wall,facing=west,waterlogged=false`，可辨识为侧接蒸汽机的储罐锅炉。锅炉冷却剂供热文案仍与独立热液流量规则相符。首轮问题已关闭。

3. **加工幕没有可观察到持续供热或加工结果。**

   首轮只静置罐量并展示空设备。R1 已在工作盆和空烧结炉阶段显示热液递减、等量冷液回流；再以临时物品实体展示生芯块、炉体亮起及烧结芯块产出，并展示耗尽停热与恢复循环。没有修改正式工艺或热账本。画面内容已补齐；但当前 Java 第 175 行与第 201 行均描述生芯块转为烧结芯块，重复说明较明显。建议按 PM 已拟定的最小改动删除重复段并同步调整 `text_3` 至 `text_5` 的编号及中英文资源，完成后只需复核文案顺序与一段一条。

4. **冷凝幕没有展示水源蒸发。**

   R1 已以 35–45 tick 的阶段显示雪块、冰、浮冰、水源和空气；蒸汽与回水库存按默认 1:1 分段变化，然后独立展示蓝冰持续冷凝。文字将雪块、冰或浮冰描述为各自可用冷源，没有暗示雪块逐步变成冰。水源耗尽为空气后的说明锚定在冷源方块原坐标，文字与管路高亮仍有目标；此空坐标锚点的屏幕可读性留待用户客户端检查。

5. **首轮锅炉隔层内部缺格，模板实际不能成型。**

   首轮生成器只放中央再加热段，隔层内部其余 8 格为空；现行 `BoilerStructure` 在 `y==partitionY` 时要求内部格均为 `HEAT_SECTION` 或 `CASING`，故不能称为合法锅炉。R1 已在 `y=2,x/z=6..8` 的 3×3 内部放置中心再加热段和外围 8 格外壳；剖面先加载完整结构，再暂隐前壁与这 8 格内壳，之后恢复。模板按 5×5×5 外壳、完整隔层及实际端口复核，问题已关闭。

## R1 结构、API 与行为核对

- 锅炉模板有效外壳为 `x/z=5..9,y=0..4`。底层中央换热器是当前结构算法允许的机器例外；底层非角点热口、隔层侧面冷口以及前壁上的控制/水/汽口均位于合法槽位并朝外。隔层 9 个内部格全部符合结构规则。剖面恢复时重新显示被隐藏的前壁与 8 格隔层外壳。
- Create 6.0.10-280 的 `steam_engine` 方块状态允许 R1 使用的墙装朝向；与随 Create JAR 提供的原生蒸汽机 Ponder 结构相符。2×2 储罐覆盖 `x=6..7,z=5..6,y=2`，两台蒸汽机分别与西侧罐壁接触，下方是两台同向换热器。
- 核对了实际 `FluidTankBlockEntity` API：单格罐的 `controller` 初始为空时，`isController()` 返回 true，`getControllerBE()` 返回自身，故 `setTankFluid` 不会因单格罐的默认 controller 为空而拿到 null。Ponder 1.0.82 的 `PonderLevel.onBEAdded` 会将 Create 的 `VirtualBlockEntity` 标为 virtual；Create 的 `setController` 在客户端只拒绝非 virtual BE，因此 R1 可把 2×2 四格绑定到实际存在的 `(6,2,5)` 共同控制罐，并设置 width=2、height=1。按这些真实 API，R1 的共享罐库存读写路径成立。
- 加工幕从顶部工作盆切换烧结炉前先将盆、搅拌器和轴设为空气，再放新方块；R1 物料/产物使用 Ponder 临时实体，不改正式工艺。换热器和烧结炉方块的 LIT 状态切换顺序与展示的供热、停热和恢复相配。客户端替换 BE 无崩溃仍需播放验收。
- 冷凝幕已包含空气状态及库存用尽、回水填满的变化，蓝冰阶段持续 70 tick 并展示等量变化。缺少的只是该顶部序列在首个 `showSection` 中的可见性。
- Java 标题与正文 fallback 和中文 JSON 同序同文，英语 JSON 对应同一语义；Processing 当前有重复的烧结转化说明，见上项。其余双语键数量与场景段落相符，无尾部空格。正文均经 `note` 显示并在下一段前额外等待 20 tick。静态检查不能代替客户端对缩放、裁切、遮挡、冷源可见性及空坐标字幕的检查。
- 核对从 `f650aa7` 的功能代码差异只涉及本批 Ponder 插件绑定和语言文件；新增 Ponder 场景、模板、生成器及合同测试都在原任务写集内。没有发现正式热工、流体能力、配置、注册、配方或旧教学改动。
