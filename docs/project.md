## 1. 产品定位

本模组为《机械动力》提供一套后期核能动力系统。玩家建设由 **反应堆、三模式核换热器、专用高压锅炉和超临界汽轮机** 组成的主机组，使用冷却、耐压输送和红石控制维持其运行。核换热器既能为 Create 原生设备供热，也能在冷源方块附近把普通蒸汽冷凝为水。

目标体验位于“硬核拟真”和“Create 式轻松自动化”之间：

- 保留热量、流量、压力、转速、余热与辐射等真实概念，但将其压缩为少量可读状态，不模拟中子截面、同位素丰度或复杂化学。
- 故障必须有明确原因、渐进预警和至少一种自动化解法；惩罚来自玩家忽视信号，而不是随机暴毙。
- 建造本身只是开始。稳定输出应力依赖供水、负载调节、废料处理与定期维护。
- 模组应优先奖励“看懂系统并搭出控制回路”，而不是奖励查表和堆叠方块。
- 默认难度为 **标准工业模式**；休闲和硬核差异通过配置预设实现，不分裂核心玩法。

### 1.1 体验目标

1. 玩家能在第一次事故前，从仪表、音效和 Ponder 教程中理解事故原因。
2. 手动操作可启动机组，但长期满功率运行需要 Create 自动化。
3. 大机组的优势来自效率、热惯性和稳定性，而不是没有上限的指数增长。

### 1.2 首发能量形态与范围边界

- **首发版本**的唯一终端能源是 **Create 旋转应力（SU）**。汽轮机通过传动轴直接向应力网络提供应力容量，不生产 FE、RF 或任何电能。
- “核电站”“发电”等词在首发版本中是现实原型或通俗称呼；玩法和 API 层面首先实现核热机械动力站。
- 首发版本不包含电机、发电机、输电、电网和跨能源转换。后续版本可通过独立、可选的能源兼容模块增加这些能力。
- 首发版本不因缺少电力系统而刻意压低输出。超大应力本身就是玩家进入原子能时代的核心奖励。
- 未来加入电力后，应力输出仍作为完整且长期受支持的玩法路线，不降级为过渡功能。

## 2. 核心玩法闭环

```text
铅/铀/锡矿处理 → 铀燃料制造 → 燃料组件 → 反应堆产热 → 热复合冷却剂 → 核换热器
复合冷却剂生产与补充 ─────────────────────────┘                      ├─→ 专用高压锅炉 → 超临界蒸汽 → 超临界汽轮机
                                                                       │                                      ├─→ 主轴输出旋转应力
                                                                       │                                      └─→ 蒸汽 → 核换热器冷凝模式 → 水
                                                                       │                                                              ↓
                                                                       │                                           补水/给水泵 ←──────┘
                                                                       └─→ Create 流体储罐锅炉 / Create 原生加热设备（超级加热）
                                                                                              └─→ 贴附式 Create 蒸汽引擎 → 旋转应力

枯竭铀燃料组件（首发直接为冷却态） → 安全封存 / 再处理 → 再生燃料

> 首发版本不实现热乏燃料与冷却乏燃料之间的转换，也不实现乏燃料池冷却玩法。燃料耗尽时直接形成冷却的枯竭燃料组件；`hot_spent_fuel_assembly` 仅作未来命名预留，首发不注册、不生成、不依赖。
```

### 2.1 启动流程

1. 用既有 Create 动力驱动冷却泵、给水泵和控制机构。核电站不能无外部动力“黑启动”。
2. 装载燃料组件，确认主冷却回路已充满。
3. 缓慢提起控制棒，使反应堆升温。
4. 锅炉达到工作温度后开启进汽阀，汽轮机逐步升速。
5. 接合主离合器并逐步连接应力负载，自动控制系统随后接管流量和功率。

### 2.2 稳态运行

玩家需要同时平衡五个量：

- **反应堆温度：** 由产热与冷却能力之差决定。
- **锅炉负载：** 由输入热量、给水量和换热面积决定。
- **蒸汽压力：** 蒸汽产生快于汽轮机消耗时上升。
- **汽轮机转速：** 进汽过多或外部应力负载突然消失时上升。
- **蒸汽回收：** 核换热器只有在配置扫描范围内检测到水、雪块、冰、浮冰或蓝冰等冷源时才把蒸汽转成水；无冷源或出水受阻时安全停机并保留输入。

仪表只显示当前值、趋势箭头和绿/黄/红区间；高级护目镜或显示链接可查看精确数值。

### 2.3 停机流程

插入全部控制棒后，裂变功率立即归零，但会保留逐渐衰减的 **余热**。主冷却回路必须继续运行一段时间。温度进入安全区、压力释放且汽轮机停转后，结构才允许安全拆卸。

## 3. 进度线与资源体系

首发物品的输入材料、加工设备与输出关系统一维护在 [recipes.md](./recipes.md) 中。本章只描述资源的玩法职责、风险与系统行为，不再重复具体合成或加工配方。

### 3.1 解锁阶段

| 阶段 | 前置进度 | 新内容 | 目的 |
| :--- | :--- | :--- | :--- |
| 勘探 | 黄铜时代 | 铅矿、铀矿、锡矿、辐射计、基础防护服 | 建立核工业材料基础，让辐射在建堆前可见、可防 |
| 燃料制造 | 精密构件 | 复合冷却剂、铀富集、烧结、燃料组件装配 | 用 Create 工序表达工业感 |
| 实验堆 | 稳定燃料供应 | 小型反应堆、一级冷却回路 | 低风险学习热平衡 |
| 商用机组 | 实验堆稳定运行 | 高压锅炉、超临界汽轮机、三模式核换热器 | 完成主轴应力输出与蒸汽回水闭环 |
| 高级核能 | 商用机组与稀有材料 | 强化管道、燃料再处理、极限机组 | 提高效率而非解锁必需玩法 |

### 3.2 新增矿物与材料分工

世界生成新增铅、铀、锡三种矿物，均提供普通石与深层板岩矿石、粗矿、粗矿块及对应加工产物。三种矿物的职责必须清楚，避免为了延长流程而增加一次性材料。

| 矿物 | 建议生成定位 | 主要用途 | 平衡原则 |
| :--- | :--- | :--- | :--- |
| 铅 | 中低层、中等矿脉、常见度低于铁 | 辐射屏蔽板、乏燃料桶、屏蔽玻璃、反应堆外壳夹层 | 单台机组消耗量大，但矿石不应稀有到迫使玩家长时间纯挖矿 |
| 铀 | 深层、小型稀有矿脉 | 核燃料、再生燃料与后续高级裂变研究 | 稀缺性主要限制早期建堆速度；燃料寿命长，正常运行不要求频繁采矿 |
| 锡 | 中上层、小至中型矿脉、常见度略低于铜 | 耐腐蚀焊料、密封环、泵轴承、仪表组件与燃料组件装配件 | 作为核工业通用辅材持续消耗，不充当不合理的高温燃料包壳 |

- 矿脉高度、大小、空气暴露率和每区块数量全部可配置；数据包可以关闭本模组矿物生成。
- NeoForge 1.21.1 使用 `c:*` 通用数据包标签实现跨模组材料兼容。本模组的铅、铀、锡及通用中间材料形态（粗矿、锭、粒、粉、板、线、棒和储存块）必须加入对应 `c:*` 标签，所有配方输入通过标签接受其他模组的等价材料；完整标签目录见 [配方文档的 NeoForge 通用标签目录](./recipes.md#23-neoforge-通用标签目录)。
- Create 特有的粉碎矿加入对应 `c:crushed_raw_materials/*` 标签，并同时加入 Create 的 `create:crushed_raw_materials` 集合标签。具有燃耗、富集度或辐射状态的核燃料与废物只使用本模组专用标签，不得伪装成普通铀材料绕过生产链。
- 检测到等价矿物时默认避免重复生成，并提供整合包覆盖选项；标签数据只追加条目，不覆盖其他模组定义。
- 铀矿物品和未屏蔽的铀加工品只产生低强度辐射；真正需要严格屏蔽的是运行后的燃料与高放废物，避免采矿阶段过度惩罚。

### 3.3 一回路复合冷却剂

压水式反应堆的一回路不直接使用普通水，而使用带有 Create 世界观色彩的虚构 **复合冷却剂**。其材料构成和加工方法统一记录在配方文档中；本玩法文档不宣称它对应真实核工业工质。

- 具体材料关系与加工设备见 [首发合成与加工关系表](./recipes.md#7-一回路复合冷却剂)。
- 复合冷却剂在完整的一回路中循环，正常运行不按 tick 消耗。成本主要来自首次灌注、扩建、泄漏补充和维护。
- 热、冷冷却剂是同一工质的不同状态，换热不会复制或销毁流体。只有泄漏、排放和维护造成净损耗。
- 普通水不能作为长期替代品；紧急注水可以短时带走余热，但会产生受污染废水、腐蚀与结垢，并使机组在清洗前无法恢复满功率。

### 3.4 核燃料制造流程

燃料链保留“选矿—富集—制芯—装配”的真实因果，但把复杂化学压缩为可读的 Create 工序，不要求玩家计算同位素比例或处理真实危险化学品。

- **富集离心机**是需要稳定转速的中期动力机器。转速不足只降低产率，超速则增加维护损耗，不加入需要玩家查表的级联计算。
- **贫化铀**不是垃圾，可用于高级屏蔽、配重和后续再生燃料配方，但不能直接当作普通新燃料使用。
- 包壳使用耐高温合金钢；锡用于封端焊料、密封和仪表零件，避免把低熔点纯锡设定成高温堆芯材料。
- 燃料组件的剩余燃料值由 Minecraft 原版 ItemStack 耐久度表示；组件没有 `temperatureC` 或组件级 `integrity` 字段。`decayHeatHu` 只作为未来回收资格标识预留，首发运行不使用；反应堆运行温度和燃料列完整度属于多方块结构的燃料列状态。
- 每一步均允许传送带、机械手、动力搅拌器、鼓风机和流体管线自动化；辐射步骤必须使用带屏蔽的机械臂或密闭机器才能无人值守。
- 完整的材料关系与设备顺序见 [核燃料制造](./recipes.md#8-核燃料制造)。

### 3.5 乏燃料封存与后续处理

从反应堆取出的燃料组件不能被销毁或直接回炉。首发燃料耗尽后直接形成冷却乏燃料组件，首发只提供屏蔽封存与干式贮存；热/冷转换、乏燃料池冷却和再处理属于后续阶段。

- **首发封存：** 冷却乏燃料组件由屏蔽装配台进行玻璃灌封，再装入铅屏蔽桶并放入干式贮存架。屏蔽降低外部剂量，但不删除放射性；桶体或贮存架损坏后风险恢复。
- **后置乏燃料池：** `spent_fuel_pool` 与 `spent_fuel_pool_port` 只作为未来兼容内容保留，首发不实现热/冷乏燃料转换、池水循环或冷却时间账本。
- **后置再处理：** 屏蔽拆解机和密闭再处理器从冷却乏燃料中回收部分燃料价值与包壳材料，并同步产生高放残渣/受污染部件；回收路线不能无损删除废物或形成无限闭环。
- **后置高放废物：** 高放残渣必须在屏蔽热室中固化并装入屏蔽容器，危险物流使用屏蔽机械臂、专用运输罐和比较器监控。
- 直接封存、再处理和再生燃料的材料关系见 [乏燃料与废物处理](./recipes.md#9-乏燃料与废物处理)。

所有矿物生成、燃料倍率、冷却时间和回收率均可配置，并为常见矿物模组与整合包脚本预留标签和配方接口。具体数量、流体量、加工时间、转速、应力消耗和副产物概率在原型平衡阶段统一确定。

## 4. 模拟模型与平衡规则

所有内部计算使用无量纲负载或游戏单位。MPa、℃等仅用于界面风味展示，避免伪精确和跨版本数值失控。热量使用 `HU/t`，流体使用 `mB/t`，输出使用 `SU`。等效蒸汽引擎数用于设计和界面展示，实际仍向 Create 网络注册应力容量。本章系数为调参方向，最终值应由原型测试确定。

以 18 级蒸汽引擎的 `294,912 SU` 为统一标尺：

| 机组级别 | 等效 18 级蒸汽引擎 | 目标总应力容量 | 定位 |
| :--- | ---: | ---: | :--- |
| 实验机组 | 10～30 台 | 约 295 万～885 万 SU | 教学、黑启动设施和中型工厂 |
| 标准商用机组 | 200～500 台 | 约 5,898 万～1.47 亿 SU | 原子能时代的主力动力源 |
| 大型机组 | 1,000～2,000 台 | 约 2.95 亿～5.90 亿 SU | 超大型基地或服务器工业区 |
| 极限机组 | 2,000～3,000 台 | 约 5.90 亿～8.85 亿 SU | 高成本、高维护的终局工程 |

功率增长应主要来自更大的有效燃料规模、蒸汽流量和更多汽轮机输出段，而不是无条件的指数公式。单位燃料效率可以随规模小幅提高，但应设置上限，防止最优解退化为一个无限大的多方块。

### 4.1 反应堆

#### 结构

- 首发实验反应堆固定成型尺寸为 **5×5×5**；可变面积和高度后置，首发不把结构尺寸做成配置项。所有尺寸都必须是完整长方体，未来规模化范围再另行设计。
- 顶部槽位对应内部燃料组件列或控制棒驱动器列；框架、接口和观察窗不得占用转角。控制棒驱动器是控制棒列唯一可放置方块，其下方内部有效高度保持空气并作为逻辑冷却剂通道。
- 反应堆首次成型或完全停机重组成型后，所有控制棒默认处于完全插入位置；控制棒目标深度只有在玩家拖动后才改变。
- 首发高度固定，不单独提供通过堆高增加冷却剂容量与热惯性的玩法；可变高度的容量、热惯性和燃料长度规则后置。
- 每个燃料列对应一个燃料组件；该燃料列顶部的 `reactor_refueling_port` 方块实体保存这个组件的唯一实体 `ItemStack`，仪表端口不得再持久化第二份组件或耐久副本。燃料列有效高度决定组件耐久度的基础消耗速度。有效高度为 1 格、满功率、不超频时，一个组件放热 3 小时耗尽；高度线性缩放，基础燃耗通过 `baseBurnPerFuel`/`burnHoursPerBlock` 配置项控制并由该锚点反推，不把每个燃料方块注册成独立组件。运行温度、燃耗小数余量和列完整度仍保存在仪表端口持有的结构模拟状态。
- 至少需要一个冷端接口、一个热端接口和唯一一个仪表端口；`reactor_control_port` 是可选的烈焰人管理员控制桥接，不参与成型必需条件。P1 允许多个冷端/热端汇总流量；每个合法端口受独立流量上限约束，但反应堆不设置全堆冷却剂流量上限。
- 所有玩家都可以用 Create 扳手普通右键 `reactor_instrument_port` 请求一次服务端结构重扫。重扫后通过快捷栏消息明确反馈“已成型”或本地化的未成型原因；成功反馈同时显示燃料列、控制棒列、空列、冷端和热端数量。该诊断只读，不修改反应堆运行 NBT、不启动模拟，也不允许客户端自行扫描结构。
- **重组成型是破坏性维护：** “完全停机”定义为没有有效裂变产热、没有燃料消耗、余热已降到安全区，且没有尚未处理的融毁倒计时；仅插入控制棒、仅暂停倒计时、仍存在有效裂变或余热未进入安全区时都不满足条件。只有完全停机时才允许拆除并重新成型。明确执行破坏性重置时，会清空仪表端口中的结构模拟 NBT，并逐一清空该结构换料端口保存的燃料组件；冷/热冷却剂、每个控制棒目标深度、燃料列缓存热量、燃耗小数余量、燃料列/控制棒列完整度和融毁进度同样永久丢失，不自动恢复或返还。在完全停机、允许维护的状态下，仅替换或重新放置仪表端口并让保留在原位的合法结构重新绑定，不等同于破坏性重置，不得清除换料端口中的组件。反应堆运行、融毁倒计时或暂停融毁倒计时期间拆除任意结构组件都会直接开始融毁动作，喷出热复合冷却剂和高放射性废物。

#### 产热与控制

```text
基础产热 = 有效燃料组件数 × 单组件热量 × 平均燃耗系数
裂变产热 = 基础产热 × 功率设定 × 安全上限
净升温   = 裂变产热 + 余热 - 冷却剂带走热量
损伤程度 D = 1 - clamp(fuelColumnIntegrity, 0, 1)
损伤产热倍率 = 1 + (fuelColumnDamageHeatMultiplier - 1) × D
损伤燃耗倍率 = 1 + (fuelColumnDamageBurnMultiplier - 1) × D
列发热 = 原本列发热 × 损伤产热倍率
列燃耗 = 原本列燃耗 × 损伤燃耗倍率
默认满损伤产热倍率 = 2.0；默认满损伤燃耗倍率 = 3.0
配置约束：两个值有限，且 1 < 产热终点倍率 < 燃耗终点倍率
```

- **功率设定**为 `0～100%`，由四向相邻控制棒插入深度决定；反馈超频倍率不能绕过控制棒抑制。某燃料列所有相邻控制棒的平均实际深度达到 100% 时，该列新生裂变热和燃耗归零；只有每个有效燃料列都具备这种控制覆盖时，全棒插入才构成全堆停堆。
- **SCRAM 可用性：** 只有堆芯中至少存在一个控制棒列时，`reactor_instrument_port` 的高电平请求才允许建立 SCRAM 状态。没有控制棒列的反应堆仍可成型和运行，但必须拒绝 SCRAM：不保存恢复深度、不改变裂变发热或燃耗、不显示“SCRAM 已执行”，也不能借无效 SCRAM 暂停融毁倒计时。若存在控制棒列但控制棒卡死，高电平请求仍被记录为 SCRAM，卡死棒保持原深度；完成插棒后只要仍有裂变产热，状态就必须明确显示“SCRAM 不完整/停堆失败”，不能伪装成裂变已经切断。已经卡死在完全插入位置且确实使裂变产热归零的棒不应仅因“卡死”标签被误报为失败。
- **安全上限**由控制棒列占全部活性槽位的比例决定。控制棒不会凭空增加功率，只允许更多燃料在高功率下稳定工作。
- 建议调参：无控制棒的结构最多安全运行在 40%；控制棒比例达到约 25% 时可安全运行至 100%。
- 停堆后生成余热：初始约为停机前功率的 10%，在数分钟内衰减。余热不消耗燃料，但仍需要冷却。
- **损伤反馈：** 对仍有燃料的燃料列，损伤程度线性提高产热与燃耗倍率，燃耗倍率增长更快。默认完整度为 70% 时产热 1.30 倍、燃耗 1.60 倍；完整度归零时产热 2.0 倍、燃耗 3.0 倍，两个终点可通过服务端配置修改。完整度归零本身不停止裂变发热、燃耗或失效传播；只要组件尚有耐久且未被控制棒正常压至零功率，该列仍按正常公式运行。组件耗尽后才停止该列裂变发热、燃耗和失效传播。
- **控制棒列损伤：** 控制棒列另有独立完整度。完整度归零后控制棒卡死，不能响应玩家滑块、SCRAM 或其他控制命令，但继续按卡死前实际插入比例降低相邻燃料列的反应速率；控制棒列不向外传播损伤。
- 冷却效率由冷却剂流量、进出口温差和有效换热面积共同决定；界面将其汇总为“冷却裕量”。冷却剂转化速度必须受可用发热、冷却剂输入流量、热端输出空间和每单位冷却剂吸热量共同限制，不能凭空把一个输入单位变成任意数量的热冷却剂。

#### 燃料布局奖励

相邻燃料列提供小幅增益，同时增加局部热点；相邻控制棒列降低热点。增益设置上限，确保玩家可以自由选择紧凑高功率布局或宽松稳定布局，而不必照抄唯一最优图。
详细规则见 [反应堆局部控制修订设计](./reactor-local-control-revision-design.md)。

#### 在线单列换料

首发反应堆不要求为了更换一列燃料而停运整座机组。现实压水堆通常停堆换料，但这里明确让拟真度服从 Create 式连续自动化：玩家先把目标燃料列隔离到零裂变产热，再通过安装在该列正上方、占据反应堆顶面的 **换料端口**逐列取出和装入燃料组件。其余合格燃料列可以继续运行，整堆温度、冷却剂、余热和输出账本不得因换料重置。

- 换料判定以单列为单位。只有两类燃料列允许端口交互：所有对该列生效的相邻控制棒均已完全插入，并且服务端计算的该列当前裂变产热为零；燃料已经耗尽并被动停止裂变。仅降低功率、部分插棒、只满插其中一部分相邻控制棒、执行全局功率设定为零但未满足局部隔离条件，均不允许换料。
- 换料端口必须位于燃料列的正上方；控制棒列上方仍使用 `control_rod_drive`，空列上方仍使用反应堆外壳。控制棒本体不注册为可放置方块，也不在控制棒列下方放置逐段方块；驱动器的方块实体负责渲染无碰撞箱模型动画并承载该棒的插入状态。每个换料端口方块实体只保存其正下方燃料列的一个完整 `ItemStack`，端口与下方局部列绑定，不允许从一个端口跨列访问库存或由仪表端口复制库存。
- 端口没有右键 GUI、菜单或公开槽位界面。玩家空手交互时只取出端口保存的燃料组件，手持有效新燃料组件时只向空端口装料；一次交互只完成一个动作。若旧组件尚未取出，端口拒绝插入新组件，防止交换过程中覆盖物品或删除状态。
- **未成型安全回收：** 换料端口已经保存燃料但当前没有有效结构绑定时，玩家仍应能空手取出该端口的完整燃料 `ItemStack`，避免实体物品被困在方块实体中；未成型状态不允许装入燃料，也不向 Create 动力机械臂、漏斗或通用物流开放。该回收不读取或改写仪表快照、不触发结构扫描，只原子清空端口本地物品。若端口因运行中、融毁倒计时中或暂停融毁倒计时中的危险拆堆而失效，服务端必须保持未成型取料锁定，不能用“先破坏结构再取燃料”绕过事故规则；锁定只可在重新绑定后由安全状态确认或后续事故/破坏性重置流程解除。
- 自动换料只接受 Create **动力机械臂**。端口对机械臂暴露同样的单列取出/插入语义，普通漏斗、漏斗矿车、传送带直接注入、漏斗式通配自动化和其他通用物品管道默认拒绝访问。多台动力机械臂可以分别服务不同端口，不额外制造不符合方块世界直觉的“全堆单操作锁”。
- 工程师护目镜浮窗是唯一详细信息入口，显示列坐标、端口内部组件的剩余耐久/最大耐久和剩余比例、当前裂变产热、控制棒隔离状态、换料许可及拒绝原因。未佩戴护目镜时只通过端口外观、音效和简短动作栏提示表达成功或拒绝。
- 当玩家佩戴工程师护目镜并将准星指向 `reactor_instrument_port` 时，第一批仪表浮窗显示不会随正常运行 tick 改变的结构摘要：成型尺寸、燃料列数量、控制棒列数量、冷端口数量、热端口数量和冷/热缓冲总容量。总容量明确等于 `coldInventoryCapacityMb + hotInventoryCapacityMb`，不是当前冷却剂存量；结构或服务器配置变化后允许更新。
- 当玩家佩戴工程师护目镜并将准星指向燃料列正上方的 `reactor_refueling_port` 时，护目镜浮窗必须额外显示端口内部当前组件的剩余耐久度、最大耐久度和剩余比例，以及该燃料列的完整度、派生损坏度和当前发热量（`HU/t`）。这是只读的主线信息功能，不打开 GUI、不执行换料，也不改变端口交互规则。
- 组件耐久直接读取换料端口保存并由服务端同步的 `ItemStack`；燃料列完整度由仪表端口结构状态保存为唯一权威值，损坏度为其派生显示值（两者不得各自保存形成分歧）。结构失效或端口暂未绑定时，只要端口仍保存组件，护目镜仍可显示这项本地组件耐久，并把列完整度、损坏度和发热量明确标为结构数据不可用；空端口显示“无燃料组件”，不得读取邻列或自行按方块数量猜测。
- 取出的未耗尽组件保留原版耐久度、全部数据组件和预留 `decayHeatHu` 标识；燃料列温度、燃耗小数余量与完整度留在反应堆结构状态，组件没有温度或完整度。燃料耗尽时，结算事务在同一个换料端口中把它原子替换为冷却的枯竭燃料组件。首发版本不实现热/冷乏燃料转换、乏燃料池冷却、回收工序或相关后续玩法；换料端口不得补满、复制或无声删除组件状态。
- 有效结构中的换料交互由服务端再次原子校验。若控制棒在机械臂动作期间被提起、结构失效、目标列重新产热或输出空间被占用，本次事务不改变燃料库存，也不吞入输入物品；唯一例外是前述只操作端口本地物品且通过危险锁校验的未成型人工回收。

#### 冷却剂发热与多端口流量

P1 的冷却剂转化只属于反应堆一回路：冷端接收 `compound_coolant`，反应堆按实际可结算发热吸收热量，并从热端输出 `hot_compound_coolant`。它不通过热量凭空生成冷却剂，也不把冷却剂转化与燃料消耗拆成两套互相独立的产出账本。

建议采用以下守恒关系：

```text
可转化冷却剂量 = min(
  冷端实际输入流量,
  热端实际输出容量,
  可用发热量 / 每单位冷却剂吸热量
)
未被带走的热量 = 反应堆发热 + 余热 - 实际吸收热量
```

其中“可用发热量”由所有燃料列当前 `HU/t` 汇总，并受控制棒、超频、燃料列损伤和余热影响；实际输入/输出受 Create 管网、泵、端口容量和背压影响。冷却剂流量不足时不应降低燃料消耗来掩盖事故，而应使温度、损伤和警报按配置继续发展。

P1 采用无全堆流量上限的多端口汇总方案。每个合法冷端和热端分别受 `coolantMaxFlowPerPort` 限制，默认均为 `128 mB/t`；N 个互不重复的冷端理论输入上限为 `N × 128 mB/t`，M 个互不重复的热端理论输出上限为 `M × 128 mB/t`。端口数量可以线性提高可用冷却剂吞吐量，但不会增加反应堆发热、燃料消耗、冷却剂库存或凭空产生换热量。

实际转化量仍取以下约束的最小值：所有合法冷端的当 tick 实际输入汇总、所有合法热端的当 tick 实际接收容量汇总、可用发热量除以 `coolantAbsorptionHuPerMb`、反应堆内部冷/热冷却剂库存与背压。无论端口数量如何，都必须至少保留一个冷端和一个热端；端口不能持有独立冷却剂库存，同一端口或同一连接重复扫描不能重复结算，热端堵塞必须回传到冷却裕量和损伤模型。每个物理端口在同一 tick 内的所有执行型流体事务共享一份配额，重复获取 capability 或重复调用不能绕过上限，模拟事务不消耗配额。

每座反应堆由唯一仪表端口持有一份共享冷缓冲和一份共享热缓冲，两者容量互相独立，默认均为 `1000 mB`，分别由服务器配置 `coldInventoryCapacityMb` 与 `hotInventoryCapacityMb` 调整；增加端口数量不会复制或扩大缓冲。服务器配置不提供 `coolantTotalFlowCap` 或任何等价的全堆流量上限。

P1 平衡默认值采用：`baseHeatPerFuel = 1.0 HU/t`、`coolantAbsorptionHuPerMb = 0.5 HU/mB`、`coolantMaxFlowPerPort = 128 mB/t`、`fuelColumnDamageRate = 0.0000005 / (tick·HU/t)`；损伤起算阈值 `0.25 HU/t`、超频反馈参数和其他既有默认值不变。固定 `5×5×5` 堆中，中心为空列、周围 8 个燃料列且组件完整时，默认反馈稳定后总发热约为 `99.875 HU/t`，理论冷却剂需求约为 `199.75 mB/t`：单组冷热端口不足，两组冷热端口的 `256 mB/t` 能覆盖需求。该场景是配置、模拟器和正式流体接入的共同回归锚点。

### 4.2 三模式核换热器与两类锅炉

核换热器具有三种互斥模式：热复合冷却剂输入时输出复合冷却剂并提供首发默认等效 18 个超级燃烧烈焰人燃烧室的热量；超临界蒸汽输入时输出普通 `steam` 并提供首发默认等效 9 个普通燃烧烈焰人燃烧室的热量；普通 `steam` 输入且周围存在冷源方块时输出水。18/9 是首发默认值，服务器配置文件允许在平衡或整合包中修改；首发只有一个可输送普通蒸汽流体，“乏蒸汽”只是汽轮机排汽的工艺称呼，不是第二个注册流体。

| 锅炉路线 | 可用热源 | 最高蒸汽品质 | 主要用途 |
| :--- | :--- | :--- | :--- |
| 专用高压锅炉 | 核级换热；普通烈焰人或蒸汽供热可辅助加热 | 只有核级热量覆盖的产汽份额可成为超临界蒸汽；其他热量只产生普通蒸汽 | 驱动超临界汽轮机并防止蒸汽热闭环 |
| Create 原版锅炉 | 原版烈焰人燃烧室或适配后的核换热器 | 按 Create 原生超级加热语义运行 | 直接驱动 Create 蒸汽引擎，作为实验堆、余热利用和过渡机组 |

专用高压锅炉不靠总热值推断蒸汽品质，而同时记录热量与不可叠加提升的热源品质。只有热复合冷却剂模式产生 `NUCLEAR_SUPERCRITICAL`，蒸汽供热与烈焰人只产生 `CONVENTIONAL_HEATED`。后者无论热值多高或连接多少台换热器都只能预热或产生普通蒸汽，不能把超临界蒸汽循环加热后再次生成超临界蒸汽。核热与普通热同时输入时，也只有核热实际覆盖的份额能成为超临界蒸汽。

锅炉不再只用 `热量/容积` 决定一切，而使用两个彼此独立、容易理解的状态：

```text
热负载 L = 输入热量 / 当前结构的额定换热能力
压力趋势 = 蒸汽产生量 - 汽轮机耗汽量 - 泄压量
```

| 热负载 L | 状态 | 效率 | 反馈与结果 |
| :--- | :--- | :--- | :--- |
| `< 0.20` | 预热/低温 | 30% | 只产生湿蒸汽，不能高效驱动汽轮机 |
| `0.20～0.75` | 额定区 | 90%～100% | 专用锅炉在核换热条件满足时稳定产生超临界蒸汽；其他热源只产生普通蒸汽 |
| `0.75～0.90` | 增压区 | 最高 110% | 阀门震动、维护损耗增加 |
| `0.90～1.00` | 危险区 | 不再增益 | 明确报警并积累锅炉损伤 |
| `> 1.00` | 过载区 | 快速下降 | 持续数秒后破裂，而非瞬间爆炸 |

- 给水不足会降低产汽并使温度上升；出汽受阻会提高压力。两者必须显示为不同警报。
- 安全阀可自动泄压，但会浪费蒸汽和水，不能替代正确设计。
- 专用高压锅炉的换热器数量决定额定热功率，锅炉容积主要决定缓冲时间；这一扩展规则不适用于 Create 原版流体储罐锅炉。
- Create 流体储罐锅炉通过公开的 `BoilerHeater.REGISTRY` 读取数值热量：核热模式首发默认返回 `18`，蒸汽供热模式首发默认返回 `9`；两个值均由服务器配置文件覆盖。动力搅拌盆等原生配方分别读取 `SEETHING/SUPERHEATED` 与普通燃烧 `HEATED`。Create 6.0.10 没有统一第三方热源 API，首发不主动兼容其他模组。
- 核换热器不向蒸汽引擎伪造流体输入或输出能力；蒸汽引擎仍必须贴在 Create 储罐锅炉上。
- 热复合冷却剂断供后，换热器按配置保留短时间余热；余热窗口内继续提供超级加热，窗口结束后直接停止供热，不降级为普通加热。重新供热会刷新余热窗口。
- 多个换热器可向 Create 锅炉累加数值热量，但配方热级最高仍为 `SUPERHEATED`；数量叠加绝不能把 `CONVENTIONAL_HEATED` 提升为核级热源。
- 核换热器只有在存在有效受热负载时才正常消耗加热工质。若因缓存或结算中途失去负载而已经转换工质，则先记录空载热冲击并预警，超过配置宽限才积累损坏；停机时不瞬间爆炸，也不损坏 Create 原版方块。
- 冷凝模式在周围没有冷源或出水受阻时完全停机，不消耗蒸汽、不产水且不积累空载损坏。冷源方块来自可扩展标签，默认包含水、雪块、冰、浮冰和蓝冰。
- 三种模式的流量、热值、余热、冷源扫描范围、冷凝率和损坏参数全部由服务器配置决定。

### 4.3 超临界汽轮机与蒸汽回收

```text
超临界汽轮机应力容量 = 有效超临界蒸汽流量 × 蒸汽品质 × 机组效率 × 输出系数
```

- 汽轮机由进汽段、高压段、低压段和轴承端组成，长度决定额定流量，不允许无限堆叠效率。
- 转子有惯性，升速和降速均需时间。外部负载突然消失时可能超速，玩家可使用调速阀、制动器或旁通阀保护机组。
- 低品质蒸汽会侵蚀叶片；长期超速会损坏轴承并降低效率，但会在灾难性破坏前持续报警。
- 超临界汽轮机消耗超临界蒸汽后排出同一个普通 `steam` 流体，不直接冷凝为水，也不允许再次结算 SU。
- 普通蒸汽可进入核换热器冷凝模式；检测到有效冷源并有出水容量时按配置转成水。该模式不消耗 Create 应力，首发不再注册独立冷凝器多方块。
- 普通蒸汽也可来自核换热器蒸汽供热模式；来源不同不创建第二种蒸汽流体或隐藏品质标签。
- Create 原版锅炉支线与超临界汽轮机主线彼此独立：原版储罐锅炉内部不生成可抽取的蒸汽流体，也不参与本模组普通蒸汽账本。
- 首发汽轮机只接入标准 Create 应力网络，不注册 FE/RF 能力，也不自带任何电力转换配方或接口。后续发电机组应作为汽轮机主轴的独立负载接入，而不是直接给汽轮机方块附加电力能力。
- 超大机组必须安装多个 **主轴输出端**。每个输出端只分配总应力容量的一部分，并接入独立或互联的应力网络，避免一个轴接口承载数亿 SU。
- 默认每个主轴输出端对应 25～50 台 18 级蒸汽引擎的容量；标准商用机组需要约 4～20 个输出端，大型机组需要更完整的动力分配大厅。
- 输出端数量只决定容量如何分发，不凭空增加总功率。多个端口连接到同一 Create 网络时必须避免重复注册总容量。
- 汽轮机转速仍遵循 Create 转速限制。高总功率表现为极高应力容量而非异常高 RPM，玩家需要齿轮箱、离合器和分区轴网完成动力配送。

### 4.4 耐压管道

| 等级 | 材质 | 用途 | 默认容错 |
| :--- | :--- | :--- | :--- |
| 1 级 | 合金钢 | 主冷却剂、普通蒸汽 | 超限时先泄漏和降效，适合实验堆与蒸汽回收/旁通支路 |
| 2 级 | 强化合金钢 | 超临界蒸汽 | 更高流量与耐压，适合标准机组 |
| 3 级 | 陶瓷内衬合金 | 极限温压与长距离干线 | 高造价、低损耗，但仍会在严重超限时损坏 |

管道网络只在端点或分支变化时重算容量；运行时维护汇总后的温度、压力和流量，不逐段模拟流体粒子。80% 阈值开始显示警告，100% 后先进入短暂泄漏状态，再发生破裂。

## 5. 自动化、信息与教学

### 5.1 可自动化接口

- `control_rod_drive` 不接受红石输入；所有玩家都可以通过指向驱动器时出现的 Create 风格拖动滑块逐棒调整插入深度，不设置身份、权限或所有权差异。拖动期间由客户端本地连续预览，网络响应不得移动玩家鼠标或用延迟旧值覆盖当前悬停值；松开提交后仍由服务端验证并写入权威目标深度，拒绝、SCRAM 或卡死时才用服务端值回滚显示。烈焰人反应堆管理员属于后置自动控制桥接。向 `reactor_instrument_port` 输入红石信号只执行紧急停堆（SCRAM），不改变正常功率设定。
- 阀门接受红石或转速调节，支持给水、进汽、旁通和泄压。
- 所有主机提供比较器输出；信号含义在方块提示中明确标注。
- 支持显示链接输出温度、冷却裕量、压力、转速、换热器模式、热源品质、冷凝流量、燃耗、损伤和辐射剂量。
- 核换热器提供当前模式、供热等级、余热、冷源、流体流量、空载热冲击和损伤信号。
- `reactor_instrument_port` 提供唯一外部 SCRAM 入口：红石高电平持续期间，反应堆保持 SCRAM，所有仍可移动的控制棒保持完全插入；第一次进入高电平时保存各棒停堆前的目标位置。红石降为低电平后，反应堆解除 SCRAM，并将各棒目标位置恢复为停堆前保存值；高电平期间玩家滑块不能覆盖 SCRAM 位置。该信号不直接改写燃料或删除余热；项目不再注册独立 SCRAM 功能方块，复杂阈值逻辑仍交给玩家的 Create 组件或管理员实现。

### 5.2 烈焰人反应堆管理员

玩家可以把 **烈焰人燃烧室**安装在反应堆管理台中，使其中的烈焰人成为具有鲜明 Create 风格的“反应堆管理员”。它不是拥有完美判断的人工智能，而是一套能读取仪表、通过服务端控制接口操作控制棒并输出红石命令的拟人化自动控制器。

#### 安装与工作条件

- 管理台必须绑定一座反应堆的控制端口、全部主轴输出端和至少一组温度、冷却裕量、蒸汽压力与汽轮机转速仪表；未绑定的控制棒不能被管理员操作。
- 燃烧室保持普通燃烧状态即可值班，不要求持续进入超级加热。燃料耗尽、管理台被破坏或关键仪表失联时，管理员停止调节，并通过安全红石线路向 `reactor_instrument_port` 发出 SCRAM 信号；默认安全行为是插入全部仍可动作的控制棒。
- 一座反应堆只能有一个主管理员。第二个管理台只能作为只读监视台，避免多个控制器争抢控制棒。玩家可以随时切换手动、负载跟随、恒定功率和停堆四种模式。

#### 负载跟随与燃料节约

管理员读取所有绑定主轴端口的 **已用应力/可用应力**，以移动平均值判断基地的真实负载，并统一调节所有控制棒的插入深度。

```text
目标反应堆功率 = 平滑后的实际应力负载 + 备用裕量 + 当前热力损耗
控制棒目标深度 = 由目标功率、当前温度与冷却裕量共同换算
```

- 默认保留约 `10%～20%` 的旋转应力与蒸汽裕量，具体比例可配置。负载降低时逐步插深控制棒，减少裂变功率与燃耗；负载升高时逐步提棒，恢复产热。
- 控制棒按可见的机械速度移动，并设置死区与最短调节间隔，避免负载小幅波动导致控制棒来回抖动。玩家可从管理台查看“当前负载、目标功率、备用裕量、调节原因”四项信息。
- 反应堆、锅炉和汽轮机存在热惯性，管理员不会让功率瞬间追平负载。飞轮、蓄汽空间或备用机组仍是应对突然大负载的必要工程设施。
- 燃耗与实际裂变功率相关，而不是只按燃料组件的装载时间计算；因此低负载时插深控制棒确实能节省核燃料，但停堆后的余热不会因此立即消失。

#### 初步事故处置

管理员按照“先用服务端控制接口降功率、再通过仪表端口红石输入停堆、最后呼叫外部系统”的顺序处理即将失衡的机组：

| 检测状态 | 管理员动作 | 仍需的外部保障 |
| :--- | :--- | :--- |
| 温度上升或冷却裕量偏低 | 分级插棒、暂停继续升功率并发出黄色警报 | 主冷却泵恢复流量 |
| 蒸汽压力持续升高 | 降低反应堆功率，输出锅炉旁通/泄压请求 | 可动作的阀门与排放通道 |
| 负载突然消失或汽轮机超速 | 快速插棒，输出关小进汽和制动请求 | 汽轮机调速器、旁通阀或制动器 |
| 任一核心指标进入红区 | 插入全部控制棒并触发 SCRAM 与应急冷却请求 | 独立备用泵和冷却水源 |
| 仪表失联、控制棒卡死或管理员失效 | 进入失效安全状态并拉响持续警报 | 安全红石线路向 `reactor_instrument_port` 输入 SCRAM 信号 |

- 管理员只能操作仍然完好的控制棒，并通过红石请求控制阀门、制动器和应急冷却；它不能凭空恢复冷却剂、供水、外部动力或损坏的部件。
- 管理员使用黄色预警阈值进行 **初步处理**；正常深度调整只通过管理员服务端接口或玩家浮动滑块完成，最终 SCRAM 由 `reactor_instrument_port` 的红石输入统一触发。管理员不能绕过该入口，也不能以自身逻辑替代玩家可见、可布线的安全信号。
- 处置成功后管理员不会自动忽略故障：机组保持降功率或停堆状态，直到指标稳定一段时间且玩家手动确认复位，防止在泄漏尚未修复时反复启动。
- 烈焰人的表情、火焰强度、动作和声音反映工作状态：平稳值班、忙碌调节、紧张预警与紧急停堆应能在不打开界面的情况下区分。

### 5.3 信息层级

1. **现场反馈：** 颜色、蒸汽、振动、声音和转速动画，不打开界面也能判断大致状态。
2. **基础仪表：** 当前值、趋势和安全区间，足以完成正常运行。
3. **工程视图：** 护目镜采用现场分层显示，避免把全部信息塞进一个过长窗口。指向仪表端口时显示成型尺寸、燃料列/控制棒列数量、冷热端口数量、冷/热缓冲总容量，以及运行中的冷/热库存、全堆发热量和冷却剂转化速率；指向燃料列顶部换料端口时显示该列燃料耐久、列完整度/损坏度和当前发热量；指向控制棒驱动器时显示该控制棒列的完整度。精确瓶颈与预计安全时间属于后续仪表扩展。
4. **Ponder 教程：** 分别演示启动、稳态控制、停堆、超压和余热事故。

### 5.4 Create Ponder 教学标准

每一个多方块结构、单方块设备、管道/阀门/端口和可主动使用物品都必须有 Create 风格的 Ponder 入口。Ponder 是玩家第一次接触内容时的可操作说明，不是静态物品说明或开发调试页面。

- 多方块结构必须演示从空地搭建、关键接口、正确输入输出、启动/停机和至少一个错误结构或安全场景。
- 单方块设备必须演示材料/流体输入、加工或状态变化、输出、Create 自动化连接和阻塞/失稳时的行为。
- 管道、阀门和端口必须演示流向、压力/温度等级、红石或转速交互，以及错误连接的后果；`reactor_instrument_port` 必须演示 Create 扳手成型诊断、静态结构摘要、动态全堆护目镜信息和红石 SCRAM，`reactor_refueling_port` 与 `control_rod_drive` 必须分别演示其绑定列的护目镜信息。
- 可主动使用的物品必须演示拿在手中、穿戴、装填或插入端口后的实际效果。纯材料和仅作为配方成分的物品在设备/配方场景中展示，不额外制造空洞入口。
- 每个注册 ID 都保留独立入口；相似对象可以复用场景，但必须保留各自的标题、触发物和用途说明。当前 P1 核心内容随固定实验堆切片交付，锅炉、汽轮机、生产线等后续内容随各自阶段交付。
- Ponder 只负责客户端教学和动画，不拥有燃耗、损伤、辐射、SCRAM 或换料状态；所有结果必须由服务端权威逻辑产生。

不同危险应使用不同声音：反应堆过热为低频连续警报，锅炉超压为急促排汽声，汽轮机超速为逐渐升高的尖啸。避免玩家只看到一个含义不明的“危险”提示。

## 6. 故障、维护与应急

### 6.1 统一损伤模型

反应堆、锅炉、超临界汽轮机和核换热器分别记录 `0～100%` 的损伤，不使用随机爆炸。当前 P1 实现反应堆燃料列的 `fuelColumnIntegrity` 和控制棒列的 `controlRodColumnIntegrity`；其他设备损伤属于后续阶段。燃料列完整度下降只由该列累计的有效热负荷结算：冷却剂足以带走该列热量时，即使该列处于超频状态也不会降低完整度；冷却充足只会停止继续损伤，不自动修复已有损伤。冷凝模式缺少冷源只停机，不造成损坏。

#### P1 燃料列损伤、传播与修复规则

- **状态分离与持久化：** `reactor_instrument_port` 是反应堆模拟状态的唯一所有者，保存每列 `fuelColumnIntegrity`、`controlRodColumnIntegrity`、冷/热冷却剂、缓存热量、燃耗小数余量、控制棒深度和 `meltdownProgress`；每个 `reactor_refueling_port` 则是其单列燃料组件实体 `ItemStack` 的唯一持久化所有者。仪表端口可以在正式 tick 中临时投影端口组件耐久供模拟计算，但不得保存或修改第二份组件副本。区块卸载和正常存档重载不得重置任一侧状态；仅替换仪表端口不得清除仍在原位的换料端口组件，只有完全停机后明确执行破坏性重组成型时才按规则同时清空二者。
- **逐列独立结算：** 每个燃料列单独计算实际发热、分配到的冷却吸热量、有效热负荷和完整度变化；不能先把全堆热量平均后只保存一个全堆损伤值。护目镜读取服务端已经结算的列级值，损坏度由 `1 - fuelColumnIntegrity` 派生。
- **唯一损伤因果：** 燃料列完整度下降只取决于该列累计的有效热负荷，而不是“超频”或“冷却不足”标签本身。建议将有效热负荷定义为该列在安全阈值以上、未被冷却剂带走的热量积分：冷却剂供应足以覆盖该列发热时，热负荷为零，超频不会直接损伤；当冷却不足时，发热越高，完整度下降越快。控制棒列不自行产生热损伤，只能作为四向传播的受损目标。
- **损伤对发热和燃耗的反馈：** 完整度钳制在 `0～1`，按第 4.1 节的两条线性曲线结算。默认产热倍率为 `1 + D`，燃耗倍率为 `1 + 2D`；服务端可配置满损伤终点，但必须保持 `1 < 产热终点 < 燃耗终点`。这允许受损列用更快耗尽燃料的代价换取瞬时产热，并保留“热负荷 → 完整度下降 → 发热增加 → 更高热负荷”的反馈。在相同非零基础功率且未触及产热上限时，单位燃料产热随损伤下降；满损伤默认只有完好状态的 `2/3`。`fuelColumnIntegrity = 0` 只表示列失效且不再继续降低，**不**因完整度归零而停热或停燃耗；仍有燃料且未被控制棒压至零裂变功率时，默认以 2.0 倍产热、3.0 倍燃耗继续运行。配置变化不得补充燃料、恢复完整度或重置事故进度。
- **归零与热量传播：** `fuelColumnIntegrity = 0` 后该列进入失效状态，并在组件尚有耐久时以本 tick 快照中的当前总热量（裂变发热加缓存余热）沿四向持续传播；完整度归零绝不是传播源关闭条件。组件耗尽后，该列不再作为失效传播源；已缓存余热只按常规余热/冷却账本消散，不再新建传播损伤。传播对象不是独立“损伤包”：每 tick 现场读取水平北、南、东、西相邻燃料列的热量，经过目标列有效冷却后，把剩余热量按同一传播系数施加给相邻燃料列或控制棒列；热量被冷却完全带走时传播为零。传播不保存历史标记，必须用完整快照计算，不能按遍历顺序放大，也不能因一列包含多根燃料棒而重复结算。
- **控制棒列归零：** `controlRodColumnIntegrity` 归零后控制棒卡死，不能响应玩家滑块、红石 SCRAM、恢复指令或管理员桥接；它仍保持卡死前的实际插入比例，并继续按该比例降低相邻燃料列反应速率。控制棒列接收的相邻热量只改变自身完整度，不再向外传播。
- **融毁阈值与进度：** 覆盖分母取传播前组件仍有耐久的全部有效燃料列；覆盖分子是“完整度归零且组件未耗尽的失效源列”与“本 tick 实际收到大于零未冷却传播热量的其他有效燃料列”的并集，同一列只计一次。该比例达到至少 `20%` 时，默认建立服务端权威的 `meltdownCountdown`；空列、控制棒列和组件已经耗尽的燃料列均不参与比例，也不依赖传播历史标记。倒计时进度必须单调前进，不能因普通控制、冷却或部分维修回退。
- **融毁计时处置：** 已建立的有效 SCRAM 和有效冷却可以暂停当前融毁倒计时；无控制棒列时被拒绝的 SCRAM 请求不满足暂停条件。暂停不能回退已累计的融毁进度、恢复已归零完整度或让仍受损的列被视为安全；危险条件再次成立时从原进度继续。只有所有燃料列和控制棒列完整度都修复到 `1.0` 时，才重置融毁状态和进度。完全停机后重新成型属于另一种明确的破坏性维护重置，也可以按结构规则清空融毁进度。
- **修复边界：** 冷却充足只停止新的损伤，不等于自动修复。受损燃料列使用 `steel_plate`（显示名“合金钢板”）直接右键其顶部换料端口修复；维修前该列必须停止放热，并遵循换料同样的局部隔离逻辑。每消耗一块合金钢板，恢复该燃料列中单个燃料棒方块额定完整度的 `25%`，换算为 `0.25 / internalHeight` 的列完整度，最后一次不足时只恢复到 `1.0`；维修不能补回燃料组件耐久、清除控制棒卡死或回退融毁进度。控制棒列使用同一合金钢板维修规则，但目标方块为其 `control_rod_drive`；两类入口都只修复所绑定的单列状态。`alloy_steel_plate` 不作为正式 ID 或别名注册。完全停机后允许拆除并重新成型，以清空整个多方块结构的内部 NBT；运行、融毁倒计时或暂停融毁倒计时中拆除任何结构组件立即执行融毁动作。

下表的损伤百分比指单个燃料列或控制棒列的局部损伤，不等同于全堆融毁触发比例；全堆融毁覆盖按未耗尽失效源与本 tick 未冷却传播目标的并集达到有效燃料列的 `20%` 计算。

| 损伤 | 状态 | 默认行为 | 可用处置 |
| :--- | :--- | :--- | :--- |
| 0～30% | 异常 | 发热轻微增加，开始显示警告 | 提高冷却余量，降低负载 |
| 30～60% | 严重 | 发热明显增加，损伤正反馈增强 | 降功率、停裂变、恢复有效冷却 |
| 60～90% | 紧急 | 失效列可能开始向其他燃料列传播损伤 | 立即 SCRAM、隔离故障列、应急冷却 |
| 90～100% | 失效传播 | 列完整度归零但仍按配置运行，默认产热 2.0 倍、燃耗 3.0 倍，并向其他燃料列传播；组件耗尽前达到条件即启动融毁计时 | 立即 SCRAM、持续冷却并隔离该列；若无法压至零功率，只能执行已冻结的融毁处置方案 |

从第一次红色警报到第一根燃料列归零，标准模式应至少留出 **20～60 秒**，具体时间随热负荷、冷却余量和发热正反馈变化。列归零后的传播速度和融毁倒计时另由配置控制；结构越大，传播路径越长，但累计事故后果也越大。

### 6.2 应急手段

- **SCRAM 紧急停堆：** 至少存在一个控制棒列时，立即插入所有可移动控制棒并尝试切断裂变热；无控制棒列时该手段不可用，插棒后仍有裂变产热时报告不完整停堆。SCRAM 无法消除余热，也不自动撤销已发生的燃料列损伤或融毁传播。
- **应急冷却：** 接入独立冷却水箱和备用泵，消耗大量水但可阻止损伤继续上升。
- **锅炉泄压/汽轮机旁通：** 牺牲蒸汽和效率换取安全。
- **Create 热源断开：** 关闭换热器热侧阀门或旁通一回路后，超级加热仍会在配置的短时余热窗口内持续；需要同时停止受热配方或为锅炉维持供水，直到余热归零。
- **换热器无负载：** 加热模式先停止工质转换；若缓存已经结算为空载热冲击，则在预警宽限内切断输入或恢复受热负载。
- **甩负荷保护：** 外部应力网络断开时自动关小进汽并启用制动器。大型机组可分组切断主轴输出端，避免一次切换整个基地负载。
- **手动拆除：** 只有完全停机时允许，并且明确执行破坏性重置时会同时清空各换料端口保存的燃料组件，以及仪表端口保存的冷/热冷却剂、控制棒深度、缓存热量、燃耗小数余量、列完整度和融毁状态。完全停机时单独替换仪表端口并重新绑定不属于该重置，不能顺带清除仍存在的端口库存。运行中拆除任意反应堆组件会立即进入融毁倒计时；即使之后补齐结构，也不能回退已累计的融毁进度。

后续锅炉、汽轮机和核换热器的低于 60% 损伤可在停机后用密封件、轴承或耐热板修复；更高损伤需要替换对应结构部件。P1 燃料列和控制棒列使用合金钢板的专用维修规则，不能直接套用设备维修材料；完整度下降、热量传播和融毁倒计时必须遵守本节规则。

### 6.3 事故后果

标准模式下的堆芯失效按以下顺序发生：局部高温与火灾 → 热复合冷却剂和高放射性废物喷出 → 少量结构破坏 → 污染区生成。默认不生成大面积流动熔岩，避免不可控地形更新和服务器卡顿。

- 污染强度随距离、屏蔽和时间衰减，主要效果为虚弱、饥饿和持续伤害；不直接套用高等级凋零作为唯一表现。
- 铅板、屏蔽混凝土和完整反应堆外壳可阻挡辐射传播。
- 玩家可用辐射计定位污染源，穿防护服作业，并通过移除熔毁残骸、封装废料和铺设去污材料主动治理。
- 污染不会永久存在。默认按已加载游戏时间衰减，服务器离线衰减设上限，防止改系统时间绕过机制。
- 地形破坏半径、方块污染、实体伤害和是否允许永久污染均可配置；服务器可按维度或领地禁用地形破坏。

### 6.4 日常维护

满功率、频繁热循环和长期超速会增加部件磨损。维护周期以数个游戏日计，不要求玩家每几分钟停机。检查口可在不停机时读取部件寿命；叶片和密封件必须在对应设备停机后更换。反应堆燃料遵循第 4.1 节的在线单列换料规则：目标列必须局部停止裂变，但不强制整座反应堆停机。

## 8. 视觉与声音规范

### 8.1 反应堆

- 控制棒驱动轴随设定上下滑动；观察窗显示冷却剂流动和契合 Minecraft 风格的蓝色脉冲光。

- 视窗内液位和气泡速度随状态变化；高压时安全阀震颤并排出白色蒸汽。
- 给水不足表现为干烧红光，出汽受阻表现为阀门喷汽，两种故障视觉上必须可区分。

- 使用 6～8 格长的分段多方块：进汽室、高压段、低压段、轴承端和应力轴接口。
- 叶轮动画与真实转速状态绑定；高转速采用动画模糊或简化模型，避免高频几何更新。
- 满负载是稳定低鸣，超速才出现尖啸和轴承火花，避免“正常工作看起来像即将爆炸”。

隐藏彩蛋、趣味玩法和隐藏进度统一维护在 [隐藏彩蛋与进度设计](./easter-eggs-and-advancements.md)。本策划案只保留总原则：它们不作为配方或科技阶段的前置条件，不奖励会影响平衡的物品、经验或应力，并允许服务器分别关闭功能型彩蛋、进度文字和客户端表演。

## 9. 技术边界与性能原则

- **服务端权威：** 热量、压力、燃耗、损伤和辐射全部由服务端计算；客户端只负责插值动画和界面。
- **模拟频率：** 正常机组每 5～10 tick 更新一次；危险倒计时可提高频率。非活动区块不进行完整模拟，重新加载时使用受限的时间差结算。
- **多方块缓存：** 仅在结构或管网发生变化时重新扫描，禁止每 tick 遍历整个结构。
- **世界修改：** 不在异步线程读写世界。事故扩散使用服务端任务队列，并限制每 tick 修改的方块数。
- **渲染：** 优先复用 Create 的实例化/动态渲染方式；只有确实需要骨骼动画时再引入 GeckoLib，避免为单个机组增加强依赖。
- **持久化：** 只保存机组状态、污染源和必要的管网摘要；数据必须包含版本号。旧版本迁移在第一版可玩切片完成后单独实现，不阻塞首发切片。
- **兼容性：** 自定义流体使用标准 NeoForge 流体处理能力、`c:*` 通用标签或本模组专用标签；耐压限制由本模组管道执行。普通管道接入危险流体时拒绝传输并给出可读提示，不直接无预警摧毁其他模组方块。
- **材料标签：** 所有可互换的矿石与加工材料通过 `c:*` 通用标签暴露，Create 粉碎产物同时使用 Create 对应标签。配方读取标签而非具体注册 ID；核燃料状态物与放射性废物使用隔离的本模组标签，避免错误通配。
- **多人安全：** 危险操作记录操作者；领地保护存在时尊重其爆炸和方块修改规则。提供管理员清理污染源与恢复故障结构的命令。
- **接口先行：** 反应堆只向统一热源接口提供热量与工质状态；汽轮机只向统一机械输出接口提供扭矩/应力能力；Create、FE 和未来能源系统通过适配层连接，不得进入核心热力学状态机。
- **内容注册解耦：** 配方、方块、流体、网络同步和菜单代码按“核心核工业内容”“Create 集成”“能源集成”分包，避免未来独立化时重写整个模组。
- **移动结构兼容：** 机组状态使用结构局部坐标和稳定结构 ID，不把世界坐标写入反应堆、管网或汽轮机的核心状态，为航空学等移动载具模组预留集成能力。

## 10. 开发范围与里程碑

### Phase 0：数值原型

- 用无渲染测试模型验证产热、流量、压力、转速与损伤状态机。
- 分别以 10、200、500、1,000 和 3,000 台 18 级蒸汽引擎为基准，测试材料成本、占地、燃料消耗与动力分配复杂度。
- 验证数亿 SU 下 Create 应力网络所用数值类型、同步精度、溢出边界和显示格式；若上游 API 使用低精度数值，则在接口层分片注册容量，禁止静默溢出或显示负数。
- 确定标准模式的预警时间、黑启动成本和满功率维护周期。

### Phase 1：固定实验堆核心切片

- 只实现固定 **5×5×5** 实验反应堆的可运行、正常停堆和 SCRAM；首发 P1 不实现可变面积或高度。
- 实现控制棒拖动滑块、燃料列降频/降功率、直接相邻燃料超频、逐列热负荷损伤与发热/燃耗反馈、控制棒列卡死、失效传播/融毁倒计时、关键合成物品维修、停机重组成型重置、冷却剂冷/热状态转化及其服务端状态显示。
- 当前执行顺序明确为功能优先：P1 功能闭环完成前不制作多方块连接纹理、正式 Blockbench 多边形模型、Flywheel 动画、粒子或音效。已注册内容继续保留可识别且引用有效的占位资源，正式视觉表现后置，不得反向阻塞结构、流体、控制和运行逻辑。
- 所有玩家拥有相同的交互能力，不加入权限、身份或所有权差异；烈焰人管理员、锅炉、汽轮机、完整燃料生产线和乏燃料封存不属于当前 P1。
- P1 只验收反应堆核心状态、冷却剂账本、控制棒交互/卡死、逐列热负荷损伤、可配置的损伤产热增益与更快增长的燃耗代价、失效传播/融毁倒计时、关键合成物品维修、停机重组成型重置和基础 Ponder；完整动力闭环与生存生产线属于后续阶段。

### Phase 2：生产、热端与自动化扩展

- 实现燃料生产线、核换热器、专用高压锅炉、超临界汽轮机、普通蒸汽闭环和冷凝回水；核换热器首发默认值为核热 18、蒸汽供热 9，并允许配置覆盖。
- 实现可变尺寸反应堆、锅炉和分段汽轮机，以及显示链接、比较器、仪表端口红石安全线路、烈焰人反应堆管理员和汽轮机调速。
- 完成标准工业模式的平衡和性能压力测试；P1 已冻结的反应堆状态语义不得被后续热端实现反向改变。

### Phase 3：风险与长期玩法

- 辐射、防护、污染治理、乏燃料再处理与再生燃料。
- 部件磨损、维护、三种管道等级及三套难度预设。
- 多人防破坏、管理员工具和整合包配置。

### Phase 4：美术与移植评估

- 完成汽轮机模型、状态动画、音效和粒子预算优化。
- 实现 [隐藏彩蛋与进度设计](./easter-eggs-and-advancements.md) 中列出的首发项目，并验证其不可用于主流 progression 或资源获利。
- 根据首发版本稳定性评估 Fabric 或其他 Minecraft 版本移植，不承诺与首发同步。

## 11. 远期演进路线

远期内容按依赖顺序逐层扩展。每一阶段都必须形成独立可玩的闭环，不以尚未实现的下一阶段作为当前阶段成立的前提。航空学兼容可在首发稳定后与阶段 A 并行开发；其余阶段按依赖顺序推进。具体版本号在首发稳定后再确定。

### 11.1 阶段 A：机械能—电力转换

增加大型发电机组，将汽轮机主轴的旋转应力转换为模组生态通用电力。

- 发电机是独立的多方块负载，必须真实消耗 Create 应力容量；转速、扭矩、线圈材料、冷却和发电机效率共同决定输出。
- NeoForge 版本以其标准 **Energy Storage 能力**为唯一实现接口，并在界面和文档中沿用生态通称 **FE**。RF 通常通过该能力兼容，不另造一套重复的 RF 网络。
- 首期只支持 `SU → FE` 单向转换。若未来加入电动机，`FE → SU` 必须使用独立效率和损耗，并检测闭环，保证任何转换循环的总效率始终小于 100%。
- 转换比、单机输出上限、待机损耗和线损可配置。界面同时显示输入应力、输出 FE/t 和实际效率。
- 发电机、电缆与储能不成为首发核反应堆的强制依赖；不安装能源模块时，应力玩法保持完整。

### 11.1A 航空学兼容：舰载核动力

增加对航空学（Aeronautics）移动载具体系的可选兼容，使标准、大型和极限机组能够安装在超大型飞船、空中母舰或移动工业平台上。该兼容不改变核动力的基础规律：载具移动不会重置温度、压力、燃耗、余热、损伤或辐射。

- **集成方式：** 航空学不作为核心硬依赖。兼容模块只在检测到目标模组时加载，并通过稳定结构 ID 将反应堆、锅炉、管网、汽轮机和主轴端口绑定到同一载具。
- **结构尺度：** 实验机组不推荐舰载化；标准机组适用于大型飞船，大型和极限机组面向空中母舰与移动基地。完整机组必须位于同一载具结构内，不允许跨世界结构和载具结构共享一个热力回路。
- **动力用途：** 主轴应力可以直接驱动航空学支持的螺旋桨、旋翼、升力风扇、传动机构和舰载工厂；未来 FE 发电模块也可为载具电气设备供能。
- **质量与配平：** 反应堆外壳、屏蔽层、冷却剂和汽轮机具有显著质量。玩家必须考虑重心、推力中心、结构强度与冗余，不允许核机组作为无质量的高功率方块。
- **载具状态：** 组装、解组、跨维度传送和区块卸载时冻结拓扑变更并安全序列化运行状态；重新载入后按受限时间差结算余热和燃耗，禁止复制燃料或清空损伤。
- **事故归属：** 泄漏、火灾、辐射和爆炸首先作用于载具局部坐标中的机舱与相邻结构。残骸脱离或污染物释放后，才转换为世界坐标实体/污染源。
- **安全联锁：** 载具解体、关键接口断裂或主轴网络分离时，兼容层必须向 `reactor_instrument_port` 输入 SCRAM 红石信号，同时关闭进汽并启动应急冷却；安全信号失效后才进入普通事故演进。
- **服务器配置：** 可单独限制舰载机组最大功率、事故破坏、跨维度运行和每艘载具可装机组数量，避免移动结构造成性能或领地破坏问题。

验收时必须覆盖载具静止、持续移动、旋转、跨区块、解组重组、意外断裂和服务器重启等情形，并确认总应力容量不会因坐标变换或结构重建而重复注册。

### 11.2 阶段 B：多种裂变反应堆

不同反应堆应改变工程取舍和事故类型，而不是只更换外观或提高倍率。所有反应堆向同一热源接口输出热量，从而复用锅炉、汽轮机、辐射和控制系统。

| 反应堆路线 | 核心优势 | 主要代价/风险 | 玩法定位 |
| :--- | :--- | :--- | :--- |
| 压水式反应堆 | 稳定、热惯性大、易理解 | 高压水回路、效率中等 | 默认教学与主力路线 |
| 沸水式反应堆 | 结构较少、响应较快 | 蒸汽回路受污染，维护更复杂 | 紧凑型高输出路线 |
| 钠冷快堆 | 高温、高燃料利用率、可处理部分废料 | 钠与水接触风险、控制更敏感 | 高级裂变与燃料闭环 |
| 熔盐反应堆 | 低压、高温、可被动排盐停堆 | 腐蚀、盐处理和启动成本 | 高安全上限的终局裂变路线 |
| 高温气冷堆 | 高品质热源、适合高效汽轮机 | 体积大、昂贵材料、气体循环要求高 | 大型稳定工业热源 |

首批扩展只选择其中一种高级堆型实现，依据其能否提供与压水堆明显不同的自动化难题决定，不一次性开发全部类型。

### 11.3 阶段 C：核聚变

聚变是裂变之后的新工业层级，不是更昂贵的同类反应堆。

- 候选首发模型为托卡马克：需要真空室、磁体、燃料注入、等离子体加热、氚增殖包层和高通量冷却。
- 点火前持续消耗大量 FE 或应力；只有等离子体达到温度、密度和约束时间条件后，反应才进入净能量输出状态。
- 聚变首先产出热量，再通过既有换热器、汽轮机和发电机转化，不直接凭空生成 FE。
- 失稳的主要后果是停堆、磁体猝灭、设备损坏和氚泄漏，不照搬裂变堆的长期堆芯熔毁。
- 聚变燃料链至少包含氘、氚和锂增殖，保持可自动化，但不模拟真实核物理的全部细节。

### 11.4 阶段 D：反物质科技

反物质属于超终局科技，核心价值是能量储存、超高密度燃料和极端工程挑战，而不是免费能源。

- 反物质生产消耗的总能量必须显著高于其后续可回收能量；它是昂贵的能量载体与科技门槛，不是永动机。
- 生产链需要粒子加速器、真空系统、低温系统、捕获装置和磁约束容器。
- 反物质反应装置将湮灭能转为热量或高能工质，再接入统一热源/能源输出系统。
- 失去约束时按库存量计算后果，并设置运输与单容器容量上限，避免一次故障无上限摧毁存档。
- 服务端可配置事故上限、地形破坏和禁用反物质内容。

### 11.5 阶段 E：独立模组化

最终产品拆分为“独立核心 + 可选集成”，使玩家无需安装 Create 也能游玩完整核工业内容。

```text
Nuclear Industry Core
├─ 热力学、流体、辐射、燃料、反应堆与机器框架
├─ 独立管道、泵、控制器、机械动力/电力基础设施
├─ FE 能源集成
└─ 可选兼容模块
   ├─ Create：SU 输入输出、Ponder、显示链接和配方兼容
   ├─ 航空学：移动结构、舰载应力与事故坐标转换
   ├─ 其他能源模组：电缆、储能和配方标签兼容
   └─ 整合包/脚本接口
```

- 独立化不是简单移除依赖。核心模组必须补齐 Create 当前提供的动力输入、传动、泵送、自动化加工、教程和可视化能力。
- Create 集成模块远期应继续提供原有体验与存档迁移，已有 Create 机组不能因独立化而直接失效；这不属于第一版可玩切片的旧存档迁移范围。
- 迁移分三步进行：先抽离纯模拟核心，再建立可替换的动力与物流接口，最后将 Create 从必需依赖改为可选集成。
- 在独立核心达到与 Create 版本相同的可玩完整度之前，不取消 Create 依赖。

### 11.6 远期架构约束

为避免未来推倒重写，首发实现即遵守以下边界：

- 核心状态不得直接引用 Create 的方块实体、应力网络或配方类型。
- 热源、工质输送、机械输出和电力输出使用版本化接口与数据对象。
- 各反应堆共享事故、辐射和维护框架，但拥有独立的控制状态机。
- 能量换算集中在适配层，并记录输入、输出与损耗，便于测试是否存在复制能源的闭环。
- 存档数据使用稳定 ID，不以具体模组方块注册名作为核心状态的唯一标识。

## 12. 阶段验收标准

### P1 核心切片验收

- 固定 **5×5×5** 实验反应堆能够成型、运行、正常停堆和接受高电平 SCRAM；低电平解除 SCRAM 后恢复停堆前控制棒目标位置。无控制棒列的合法布局必须拒绝 SCRAM 且不得暂停融毁计时；有棒但因控制棒卡死在未完全插入位置或仍有燃料列未被任何控制棒覆盖，导致插棒后仍存在裂变产热时，必须显示不完整停堆而不是成功状态。直接相邻燃料形成的反馈超频本身不得绕过完全插入的相邻控制棒。
- 所有玩家都能拖动控制棒深度滑块；红石不能调节 `control_rod_drive`，也不存在权限、身份或所有权限制。
- 工程师护目镜指向有效 `reactor_instrument_port` 时，能够显示成型尺寸、燃料列数、控制棒列数、冷端口数、热端口数和冷/热缓冲总容量；总容量不与当前流体存量混淆，无效结构不显示伪造的零值摘要。
- 燃料列能够被控制棒降频，能够按直接相邻规则产生有界超频；超频倍率与该列控制棒抑制强度相乘，部分插棒连续降功率，完全插棒使被覆盖列的新生裂变热和燃耗归零。每个燃料列独立保存完整度，损伤线性增加产热与燃耗倍率，燃耗倍率增长更快；完整度归零且组件未耗尽、未被控制棒停堆时，默认仍以 2.0 倍产热、3.0 倍燃耗运行并继续结算失效传播。两个终点倍率可配置且经联合校验；能够显示燃料耐久、列完整度/损坏度和当前 `HU/t` 发热量。
- 复合冷却剂能够在反应堆冷端输入、吸热转化并从热端输出；流量、热量、转换速度和损伤由服务端账本守恒。结构失效时既有端口必须立即停止读写；保留同一批冷/热端口和 Create 管道再次成型，或替换/重载唯一仪表端口后，端口必须自动解绑旧所有者、绑定当前唯一所有者并恢复管网输入输出，不要求玩家替换端口、拆装管道或重复成型。任何旧处理器引用都不得修改新结构账本。
- 每个燃料列按累计有效热负荷独立积累损伤；冷却足够时超频不降低完整度，热负荷越高下降越快，完整度归零后沿四向传播；未耗尽失效源与本 tick 未冷却传播目标的并集达到有效燃料列的默认 20% 时进入融毁倒计时，SCRAM/冷却可以暂停但不能回退进度。
- 控制棒列完整度归零后控制棒卡死，但保持原插入比例继续抑制相邻燃料列，且不向外传播损伤；受损燃料列可使用燃料棒制造链关键合成物品维修，完全停机后可通过重组成型清空全部内部 NBT，运行、融毁倒计时或暂停融毁倒计时中拆件立即执行融毁动作。
- P1 不验收燃料生存生产线、核换热器供热、锅炉、汽轮机、完整蒸汽闭环、烈焰人管理员、可变反应堆或乏燃料封存。

### 后续首发扩展验收

- 新玩家仅依靠 Ponder 和现场仪表，能在 30 分钟内完成实验堆启动与安全停机。
- 标准机组在自动控制正确时可持续运行至少 2 个游戏日，无需频繁手动干预。
- 标准商用机组稳定输出至少 200 台 18 级蒸汽引擎的等效应力，大型机组达到 1,000 台以上，并能通过多个主轴端口无重复地分配容量。
- 在不安装任何能源附属模组时，完整玩法闭环仍然成立；首发核心内容不得要求 FE、RF、电缆、电池或发电机接口。
- 任一灾难性故障前至少出现两种不同通道的预警（例如声音 + 仪表/粒子）。
- 切断负载、停止给水、停止冷却、堵塞排汽和换热器空载热冲击具有不同因果链和对应解法。
- 只有 `NUCLEAR_SUPERCRITICAL` 热量能让专用高压锅炉产生超临界蒸汽；普通热无论多高都只能产生普通蒸汽。
- 核换热器的核热/蒸汽供热模式首发默认分别等效 18 个超级燃烧/9 个普通燃烧烈焰人燃烧室；两个值可由服务器配置文件更改，冷凝模式缺少冷源时安全停机。
- 工程只注册一种普通 `steam` 流体；超临界汽轮机排汽、蒸汽供热模式输出和冷凝模式输入都使用它。
- “超临界蒸汽 → 蒸汽供热 → 高压锅炉”的闭环不得增加超临界蒸汽库存，也不得重复结算热量或应力。
- 烈焰人管理员能在负载变化时稳定调节全部已绑定控制棒，并在管理员断燃料、仪表失联或控制棒卡死时进入失效安全状态；外部安全线路可不依赖管理员，直接向 `reactor_instrument_port` 输入红石信号完成 SCRAM。
- 复合冷却剂、核燃料和乏燃料处理三条生产线均可使用 Create 组件实现全自动化；封存与再处理都不会无损删除物质或辐射风险。
- 在线换料只能通过燃料列正上方的换料端口进行；端口无 GUI，只允许人工或 Create 动力机械臂逐列操作，并且只接受全部相关控制棒完全隔离至零裂变产热或燃料耗尽被动停机的列。
- 河反应堆的输出低于或不高于对应 Create 常规水力设备，且不能与蒸汽输出叠加；其余彩蛋只产生隐藏进度与客户端表现。关闭彩蛋配置后不影响任何首发主线功能或既有存档。
- 标准模式事故会造成显著损失，但玩家可在合理时间内恢复基地并治理污染。
- 最大默认结构和 4 套同时运行机组不得造成明显持续 TPS 下降；具体性能预算在原型阶段冻结。

- 每项交给开发者的工作必须有需求来源、范围、依赖、文件责任、必读技能及实际路径、失败用例、自动化验证、游戏内验收和完成定义；统一任务入口为 [P1 Agent/开发者交接计划](./superpowers/plans/2026-08-18-agent-developer-execution-plan.md)，新任务字段使用治理协议的任务卡模板。
