# 机械动力：核工业——现行玩法设计

更新：2026-10-15。本文只记录当前机组规则；进度/人工门见[STATUS](STATUS.md)，未来范围见[路线图](implementation-roadmap.md)，具体数值统一见[配置](server-config.md)。原完整策划及被取代方案保存在[本次归档](archive/2026-10-15/README.md)。

## 1. 产品定位

Create的核工业附属模组：通过材料加工、堆芯布局、冷却与自动控制生产旋转应力。保留可读的热量、流量、燃耗、损伤和联锁，不模拟完整核物理。首发终端能源为Create应力SU，不输出FE/RF。

核心模拟由服务端权威结算，客户端只展示已同步信息。功能、自动验证、游戏观察与发布出口分别验收；尚未实现的事故/辐射不能作为现有玩法宣传。

## 2. 核心闭环

```text
矿物/材料 → 铀料浆 → 离心富集 → 芯块烧结 → 燃料组件装配
                                            ↓
冷复合冷却剂 → 反应堆 → 热复合冷却剂 → 换热器/高压锅炉
      ↑                                    ↓
      └──────────── 等体积冷液回流 ───────────┘
高压锅炉 → 超临界蒸汽 → 汽轮机 → Create应力
    ↑                    ↓
    └──── 水 ← 换热器冷凝 ← 普通蒸汽
```

燃料和冷却回路可手动启动、用Create物流扩产。工质、热量和燃料只扣一次，SIMULATE不收费；背压时拒收/等待，不能静默丢失或复制。

## 3. 材料与燃料

铅、锡、铀及钢材/工业零件由现行配方获取。冷复合冷却剂吸收核热后变等体积热液，换热后回流；正常一回路不持续消耗冷却剂。注册ID与实际配方分别看[内容清单](content-catalog.md)、[配方](recipes.md)。

每个燃料列持有一个组件，组件实体由顶端换料端口保存；列高度放大产热和燃耗，不额外增加组件库存。燃料耗尽形成冷却乏燃料，现阶段通过屏蔽装配台封装后置入干式贮存架；复杂再处理和热乏燃料冷却链未实现。

## 4. 机组规则

### 4.1 反应堆

- 长方体三边默认5～16，允许跨区块；棱边/角点保持基础外壳，功能口按合法侧面规则放置。每堆一个仪表端口作为结构锚点和唯一模拟所有者。
- 内部燃料列沿有效高度竖直贯通，顶部换料口；控制棒驱动器位于顶面，下方为空列，棒体是无碰撞的客户端模型。燃料/控制棒位置与数量可自定义。
- 四向相邻控制棒共同约束燃料，取实际插深平均；相邻燃料有界反馈超频。没有相邻控制棒的已装燃料不受调棒停堆控制，会按无抑制强度运行至耗尽；红石SCRAM不能凭空抑制它。
- 实际空列/控制棒空气格派生冷热共用容量，多口只增加吞吐、不增容量或核功率。总新生裂变热汇总限幅后向上取整；默认0.5HU/mB，100HU/t可转化200mB/t，维护自耗和余热按实际账本扣算。
- 冷/热物理口默认各2048mB/t，不设隐藏全堆总流量封顶；仍受外部管路、实际热量、库存与背压限制。缺失区块不强载，结构/事务失效安全撤销。
- 手持新组件可直接替换枯竭组件并返还原件；仍有耐久的组件不能直接快捷替换。正常装换料与维修维持原服务端安全判断。

算法及停堆边界见[反应堆技术合同](reactor-local-control-revision-design.md)。

### 4.2 核换热器

前侧出冷液、后侧入热液，同向直列共享工质库存，默认最多16台，各台热账本独立。支持：顶部Create锅炉供热、高压锅炉底层结构换热、工作盆/烧结炉持续供热、普通蒸汽冷凝。

顶部有工作盆或烧结炉即持续耗热，不检测工作状态；默认2HU/t、4mB热液/t转等量冷液，缺液或冷液堵塞立即停热，不用余热续烧。盆得到超级加热，烧结炉保持原工时与物流。

冷凝只接受普通蒸汽；正上方须水源/雪块/冰/浮冰/蓝冰。实际冷凝量消耗冷源，雪/冰/浮冰融水，水源蒸发，蓝冰不消耗；流水、雪层、含水方块无效。默认54mB/t、1:1回水。超临界汽输入/降级供热路线已经取消。

### 4.3 高压锅炉

main默认三边[5,11]；16³上限改动仍为独立未验候选。底层非边框格放换热器，中间再加热隔层把炉腔分为水区/汽区。热液口须与底层换热器同层，可占底边非角点；冷液口位于隔层侧面。有效热力回路数量取换热器/再加热段最小值。

水区/汽区容积分配水/汽容量，分别决定升温与压力变化惯性。普通汽和SC分别保存真实mB/HU，共用总汽容量与共同炉压；生产按新批次实际温压定种，已有库存不自动转换。

控制器只设置出汽压力下限0～100%，它不是目标炉压或安全阀阈值，也不强制生产普通汽。各汽口独立选择纯过滤：只取对应库存，不降级、混装或清除异种流体。已有合格SC可在低于生产压力门槛后按共同出汽下限排出。

冷/热口2048、给水/汽口4096mB/t，主动/被动/专用交易共享各物理口额度。汽口可主动接入合法工业管路，不要求外置泵；安全阀放汽会实际消耗工质和热量。

### 4.4 汽轮机

三档外形为3×5×3、5×8×5、7×11×7（宽×轴长×高）；仅消耗SC并等体积排普通汽。额定耗汽54/108/216mB/t，最高效率1.2/1.5/1.8；默认256RPM。

按40tick平均实际排汽量计算效率：低于额定30%只耗汽、不提供本机动力；到30%效率0.5倍，此后线性升至满流量倍率。仅保1tick极小周转，堵塞满后拒收、保残留。两端共享唯一应力容量，双端接出不会翻倍；红石/结构失效立即撤动力，断汽按窗口衰减，不清除同网其他动力源。

### 4.5 专用流体管网

原版Create铜管用于允许的冷液/普通汽运输；热液/SC使用专用管网，需要外部泵送时用工业泵；锅炉汽口可主动推入合法工业管，不要求外置泵。Create普通/创造罐仍可存储。两档专用管阀为强化钢/陶瓷内衬，默认8192/32768mB/t；唯一工业泵16384mB/t@256RPM、4096SU。

泵流量随实际RPM绝对值线性升高并封顶；路径/阀/端口/接收量共同限流，串泵不加额度。管段不存液，泵仅保最大1tick周转；阀支持0～100%开度和红石关闭。压力、泄漏与破裂尚未实现，不能把远期耐压设计当运行行为。

## 5. 自动化、显示与教学

反应堆自动化接口`reactor_automation_port`让相邻烈焰人燃烧室任职管理员，操作在燃烧室的三页GUI上。支持统一深度、恒定发热及绑定Create应力表的余量PI控制，冷却库存/积热保护优先。部分燃料列耗尽不停整堆，所有可用列耗尽才缺料保持；正常保存重进续接模式与棒位，人工停堆/故障/急停保持停机。详见[管理员合同](reactor-automation.md)。

其他设备不新增独立GUI。护目镜显示服务端状态，装换料/维修通过世界端口，物流用Create设施。八类基础思索已按批播放验收，只讲设备用法，不讲具体配方或重复基础知识。

## 6. 故障与维护

列积热超过阈值降低完整度；损伤增加产热和燃耗，燃耗增益必须高于产热增益。失效燃料向邻列传热，控制棒受热可卡死；修复和换料不能静默恢复燃料或删除已有热量。

融毁倒计时/危险拆除会发布服务端事件，具体爆炸、污染和辐射世界效果仍未接入。故障是确定的状态结算，不新增随机事故。默认参数、倍率与容量关系见[配置](server-config.md)，事件与不可控列边界见[技术合同](reactor-local-control-revision-design.md)。
