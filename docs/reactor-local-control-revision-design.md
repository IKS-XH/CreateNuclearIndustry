# P1.2 反应堆局部控制设计

**状态：** P1 控制、损伤传播、维修和多端口玩法已批准；P0 API 探针、数值原型和人工验收已通过，进入 P1 实现
**修订对象：** `2026-08-16-experimental-reactor-design.md` 中的结构核心、交互入口和统一控制模型

## 1. 方块职责修订

- 删除 `reactor_frame`。反应堆外壳 `reactor_casing` 是棱边、转角、顶面和底面的唯一基础结构方块。棱边和转角不能被观察窗或功能方块替换。
- `reactor_instrument_port` 是反应堆必装的核心功能方块、结构锚点和唯一权威模拟状态所有者。每个结构必须且只能安装一个。它保存列完整度、热量、燃耗小数余量、冷却剂、控制棒和事故状态，但不再保存燃料组件实体 `ItemStack`。结构变化会自动触发检测，第一版也允许玩家用扳手右键此方块请求立即重扫；这不是启动/停止按钮。向此方块输入红石信号会触发 SCRAM。反应堆不再注册独立的 `reactor_interlock` 方块。
- `reactor_control_port` 是可选外设，不参与成型必需条件，也不拥有反应堆状态。它只在相邻烈焰人燃烧室时提供自动控制桥接；没有该方块时反应堆仍可正常成型和工作。
- `reactor_instrument_port` 实现 Create 护目镜信息接口。玩家佩戴工程师护目镜并注视它时显示浮动信息，不需要右键交互，不打开菜单。第一批只显示结构尺寸、燃料列数、控制棒列数、冷端口数、热端口数和冷/热缓冲总容量。
- `reactor_refueling_port` 是其下方燃料列唯一燃料组件 `ItemStack` 的持久化所有者，同时也是该列的只读信息观察点。玩家佩戴工程师护目镜并注视该端口时，组件耐久直接来自端口内部物品；燃料列完整度/损坏度和当前发热量仍来自所属仪表接口的模拟状态。端口不得保存热量、完整度或其他第二份模拟状态。
- 冷端和热端只保存可重建的运行时绑定；换料端口除可重建绑定外，还保存一个不可由重扫清除的燃料组件 `ItemStack`。结构失效时必须立即解绑并使旧 capability/事务引用不可写，但不得因此清空换料端口物品；保留原端口重新成型，或仪表端口方块实体被替换、卸载后重建时，合法的新唯一模拟所有者必须能够安全接管陈旧绑定并使相邻 Create 管网自动重新发现端点。仍有效的另一座反应堆所有者不得被抢占，正常运行也不得为此每 tick 扫描整座结构。
- 每个 `control_rod_drive` 提供 Create 风格的独立拖动深度滑块，范围 `0～100%`。所有玩家都可以拖动滑块；不设置权限、身份、绑定玩家或所有权差异。拖动中的悬停值只在客户端连续预览，异步网络响应不得重定位物理鼠标或把旧预览值写回仍打开的面板；松开后的最终值由服务端验证并写入所属结构，提交失败、SCRAM、卡死或结构失效时才回滚到服务端权威值。烈焰人反应堆管理员属于后置自动控制桥接。驱动器不接受红石输入，红石只通过 `reactor_instrument_port` 触发 SCRAM。
- 控制棒不注册为可放置柱方块；`control_rod_drive` 是唯一相关方块。驱动器下方内部有效高度保持空气，控制棒由驱动器方块实体渲染为无碰撞箱模型动画，渲染不参与结构扫描和碰撞判定。

## 2. 自动成型与运行条件

反应堆 P1 固定为 **5×5×5** 成型尺寸，不实现可变面积或高度。第一版没有“组装”“启动”“停止”“功率设定”按钮。仪表接口自动检测合法结构；成型后的每根控制棒默认完全插入。反应堆模拟 NBT 由仪表端口持有，各燃料组件实体 `ItemStack` 由对应换料端口持有；两者共同构成持久化运行状态，但同一字段不得双写。运行状态只由以下两项决定：

1. 当前仍有可用核燃料；
2. 局部控制棒深度计算出的有效裂变强度是否大于零。

燃料耗尽或所有可控燃料的有效强度为零时，相关裂变停止，但未清除的余热继续结算。燃料列完整度归零不是裂变停止条件：组件未耗尽时仍按 2.0 倍损伤反馈运行并传播。SCRAM 可用性和状态按下式判定：

```text
scramAvailable = controlRodColumnCount > 0
scramRequested = reactor_instrument_port 接收到红石高电平
scramActive = scramRequested && scramAvailable
scramIncomplete = scramActive && currentFissionHeat > 0
```

只有 `scramActive` 从假变真时才保存控制棒的停堆前目标位置，并将所有仍可移动的控制棒插入到底；高电平持续期间锁定可移动棒的滑块。没有控制棒列时，高电平只产生 `SCRAM_UNAVAILABLE_NO_CONTROL_RODS` 拒绝原因，不保存恢复目标、不建立 SCRAM 状态、不改变发热/燃耗，也不能暂停融毁倒计时。若至少存在一个控制棒列，高电平仍可建立 SCRAM 请求状态，卡死棒保持原插入比例；插棒结算后若当前裂变产热仍大于零，则额外输出 `SCRAM_INCOMPLETE`/停堆失败警告。卡死在完全插入位置且已经使裂变产热归零的状态不因卡死标签单独判失败。红石降为低电平后解除已建立的 SCRAM，并把可恢复控制棒目标位置恢复为保存值；从未建立 SCRAM 的无棒布局没有恢复动作。直接相邻燃料仍可形成反馈超频，但反馈倍率必须受该列局部控制强度门控；当每个有效燃料列都被四向相邻且完全插入的可动控制棒覆盖时，SCRAM 必须把全堆新生裂变热和燃耗压至零。只有存在未被任何控制棒覆盖的有效燃料列，或控制棒卡死在未完全插入位置时，才允许报告 `SCRAM_INCOMPLETE`。

核心方块的结构破坏规则由服务端拦截：运行、融毁倒计时和暂停融毁倒计时三种状态都禁止拆除任何反应堆组件。若玩家强行拆除，服务端在方块移除前将 `meltdownProgress` 置为完成值并立即执行融毁动作，喷出热复合冷却剂和高放射性废物；不能依赖被拆掉的方块实体继续保存事故状态。

## 3. 局部邻接控制算法

活性区只考虑同一水平截面内的北、南、东、西四向邻接，不考虑对角线。列沿高度保持统一类型和统一控制设定。

对每个有效燃料列 `f`，取其四向直接相邻控制棒集合 `C(f)`。控制棒插入深度 `d ∈ [0,1]`，`0` 为完全拔出，`1` 为完全插入。每个控制棒列另有 `controlRodColumnIntegrity ∈ [0,1]`；完整度归零后该棒卡死，`effectiveDepth` 固定为卡死前实际深度，玩家滑块、SCRAM 和其他控制源都不能再改变它，但该深度继续参与相邻燃料列的反应速率计算：

```text
effectiveDepth(c) = controlRodColumnIntegrity(c) = 0 时固定为 jammedDepth(c)，否则为当前服务端实际深度 actualDepth(c)
meanDepth(f) = C(f) 为空时 0，否则 average(effectiveDepth(c), c ∈ C(f))
controlledIntensity(f) = (1 - meanDepth(f)) ^ controlResponseExponent
```

`controlResponseExponent` 是服务端配置项。多个控制棒共同影响同一燃料时取平均值，避免控制棒数量本身放大或缩小燃料额定功率。
控制棒列只接收四向相邻失效燃料列传播来的热量，不向其他列继续传播；它的卡死状态也不改变邻接规则。

## 4. 直接相邻燃料反馈超频

若燃料列 `f` 至少有一个水平四向直接相邻且未耗尽的燃料列，则它进入反馈超频簇。反馈只提供有界倍率，不得绕过第 3 节的控制棒抑制。迭代从每列的 `controlledIntensity` 开始，以同步轮次读取上一轮相邻燃料已经受控制棒门控的有效产热强度并迭代到稳定值：

```text
signal(f) = Σ effectiveHeatIntensity(n), n 为 f 的四向直接相邻有效燃料列
activation(f) = 1 - exp(-overclockFeedbackGain × signal(f)^overclockFeedbackExponent)
heatFeedbackMultiplier(f) = 1 + (overclockHeatMultiplier - 1) × activation(f)
burnFeedbackMultiplier(f) = 1 + (overclockBurnMultiplier - 1) × activation(f)
effectiveHeatIntensity(f) = controlledIntensity(f) × heatFeedbackMultiplier(f)
effectiveBurnIntensity(f) = controlledIntensity(f) × burnFeedbackMultiplier(f)
```

`overclockHeatMultiplier` 与 `overclockBurnMultiplier` 是硬上限而非固定结果。迭代使用上一轮完整快照，最大 256 轮，所有列变化不超过 `1e-9` 时收敛；映射单调且有界，从各列的 `controlledIntensity` 开始会得到确定的最小稳定解。反馈规则为：

- 相邻燃料越多，输入信号越大，超频强度非线性升高；
- 相邻燃料经过控制棒抑制后的有效强度越高，下一轮给邻居的反馈越强，因此连续燃料簇会形成有界正反馈；
- 控制棒和中空列没有燃料信号，会完全切断反馈簇；
- 没有相邻控制棒的燃料列取 `controlledIntensity = 1`，因此既有无棒反馈超频数值和中心空列八燃料平衡锚点不变；
- 部分插棒连续降低该列发热、燃耗及其提供给邻列的反馈信号；完全插棒使被覆盖列的有效发热和燃耗严格为零；
- 停止的燃料列不再向邻列提供反馈信号，但仍保留拓扑上的“处于反馈簇”标记，便于诊断布局；
- 孤立燃料仍严格按第 3 节公式控制。

## 5. 总产热与燃耗

设每个垂直燃料棒方块的额定产热和额定消耗分别为 `baseHeatPerFuel`、`baseBurnPerFuel`，结构内部高度为 `internalHeight`。局部邻接仍按整列在水平截面中只计算一次，但一整列的产热、燃耗和可装燃料库存均随内部高度线性增长：

```text
damageMultiplier(f) = 1 + (1 - clamp(fuelColumnIntegrity(f), 0, 1))
columnHeat(f) = baseHeatPerFuel × internalHeight × heatEquivalent(f) × damageMultiplier(f)
columnBurn(f) = baseBurnPerFuel × internalHeight × burnEquivalent(f) × damageMultiplier(f)
rawHeat = Σ columnHeat(f)
nominalInstalledHeat = baseHeatPerFuel × internalHeight × installedFuelColumnCount
heatCap = nominalInstalledHeat × totalHeatMultiplierCap
totalHeat = min(rawHeat, heatCap)

totalBurn = Σ columnBurn(f)
fuelCapacity(f) = fuelCapacityPerBlock × internalHeight
```

数值锚点：`internalHeight = 1`、满功率、无超频时，一个组件必须在 3 小时后耗尽。按 20 tick/秒换算，`baseBurnPerFuel` 的基准量级为 `1 / (3 × 3600 × 20)` 每格高度，再由实际强度、超频燃耗倍率和配置单位折算；该反推结果必须作为数值平衡验收记录。玩家可修改 `baseBurnPerFuel` 或等价的 `burnHoursPerBlock` 配置项。

孤立燃料的 `heatEquivalent` 与 `burnEquivalent` 均等于 `controlledIntensity`。超频燃料以同一个 `controlledIntensity` 分别乘配置化热反馈倍率和燃耗反馈倍率；完整度损伤再以同一 `damageMultiplier` 同比例作用于该列发热和燃耗。高度只放大每列包含的有效燃料棒方块数，不重复叠加超频倍率。总产热受 `totalHeatMultiplierCap` 截断；燃耗不随产热截断而回退，防止用低上限无成本承受危险相邻布局。同样装满且控制深度相同的不同高度反应堆，其总库存与燃耗速率同比增长，因此理论满载续航不因高度单独改变。

当某根燃料库存耗尽时，该列从下一 tick 起不再视为有效燃料，不再产热、燃耗、触发相邻超频或作为失效传播源；邻接关系随之局部重算。`fuelColumnIntegrity` 归零不采用该停止规则：只要组件尚有耐久，该列仍是有效燃料，继续按 2.0 倍损伤反馈产热、燃耗、参与相邻超频，并以当前总热量执行四向失效传播。

每个燃料列在仪表端口的服务端模拟状态中独立保存权威的 `fuelColumnIntegrity`，范围为 `0～1`。它随结构状态保存、区块卸载和存档重载往返，不写回燃料组件数据组件；对应换料端口保存的 `ItemStack` 只用原版耐久表示燃料值。护目镜显示完整度百分比，并将 `1 - fuelColumnIntegrity` 显示为损坏度；两者是同一列状态的正反表达，不分别持久化。

### 5.1 燃料组件所有权与结算事务

- 每个合法燃料列顶部换料端口持有一个完整 `ItemStack`，包括物品 ID、数量、耐久和全部数据组件。绑定坐标可重建，不得作为跨结构访问库存的依据持久化；普通结构失效、重扫、区块卸载或在完全停机维护中仅替换仪表端口都不能清空该物品。
- 正式服务端 tick 开始时，仪表端口按已缓存的列—端口映射读取各端口物品并构造只在本 tick 有效的燃料投影。该投影只用于纯模拟计算，不是第二份可独立保存或交互的库存；`fuelBurnRemainder` 等不足一个耐久点的燃耗余数仍属于仪表端口模拟状态。
- tick 只有在结构、端口绑定和物品身份再次校验成功后，才把结算出的整数耐久损耗或燃尽产物原子写回原换料端口，并同时提交新的模拟快照。任一端口缺失、物品被交互改变或结算失败时，本 tick 对物品与模拟快照都不得部分提交，避免复制、吞物品或燃耗与发热脱节。
- 玩家换料和后续 Create 动力机械臂必须调用同一单槽事务；不公开给普通漏斗和通用物品管道。取出时返回端口中的原始 `ItemStack`，装入时完整保存输入物品数据，燃尽时在同一端口中原子替换为 `cooled_spent_fuel_assembly`。
- 未成型或暂未绑定的换料端口不得把本地燃料永久困住：玩家空手时可以通过独立的服务端原子回收路径取出端口保存的精确 `ItemStack`。该路径只允许取出、不允许装入，不修改 `ReactorSnapshot`、不触发结构重扫，也不暴露通用 `ItemHandler` 或 Create 机械臂入口。
- 为防止绕过危险拆除规则，换料端口允许额外持久化一个最小的“未成型取料锁”访问状态；它不是热工或反应堆模拟副本。端口从有效结构解绑前，若所属反应堆正在运行、处于融毁倒计时或暂停融毁倒计时，必须锁定回收；未知旧状态默认从严锁定。锁定不能靠重复右键、卸载区块或重放方块解除，只能在端口重新绑定后由服务端确认安全状态，或由正式事故/破坏性重置流程处理。
- 从旧存档升级时，如果旧仪表端口快照仍含燃料组件而对应换料端口为空，应执行一次“移动而非复制”的迁移；端口已有物品时以端口为现行权威，不得覆盖或生成第二件物品，并记录可诊断的兼容处理结果。若改变现有 NBT 结构，必须提升格式版本并覆盖旧版迁移、重复加载和中断恢复测试。
- 完全停机后的破坏性重置必须显式枚举并清空所属换料端口物品；普通重绑和替换仪表端口不调用该清空路径。

### 5.2 P1 燃料列损伤、传播与修复规则

- 正常运行的损伤因果只有该列累计有效热负荷。超频只改变发热量，不作为独立损伤源；当冷却剂供应足以带走该列（包括完整度反馈后增加的）发热量时，即使超频也不降低完整度。
- 每个燃料列独立计算 `generatedHeat_i`、分配的 `removedHeat_i` 和有效热负荷 `netHeatLoad_i = max(0, generatedHeat_i - removedHeat_i)`。完整度下降由 `netHeatLoad_i` 在安全热负荷阈值以上的时间积分决定；热负荷越高，`fuelColumnIntegrity` 下降越快。不要使用全堆平均损伤替代逐列结算。
- 完整度损伤对仍有燃料的列采用固定线性反馈：`damageMultiplier_i = 1 + (1 - fuelColumnIntegrity_i)`，其中完整度钳制在 `0～1`，故倍率为 `1.0～2.0`；发热和燃耗同时乘以该倍率。完整度归零时倍率为 2.0，列失效但不会因此停止发热或燃耗；只有燃料组件耗尽，或正常控制将裂变功率压至零，才会使当 tick 裂变发热为零。冷却充足只停止完整度下降，不自动恢复完整度。
- `fuelColumnIntegrity_i = 0` 后，该列进入失效状态；只要组件未耗尽，它继续按正常发热/燃耗公式运行，并以传播前快照中的当前总热量（裂变发热加缓存余热）执行四向热量传播。组件耗尽时，同时终止该列的裂变发热、燃耗和失效传播；缓存余热只按常规账本消散，不再造成新传播损伤。每次 tick 将经目标列冷却后剩余的热量传给北、南、东、西相邻的有效燃料列或控制棒列；热量被冷却完全带走时传播为零。燃料列继续因热量受损，控制棒列只减少 `controlRodColumnIntegrity`，不把热量继续向外传播。传播不保存独立标记，不能因为一列有多根燃料棒而重复放大。
- 融毁覆盖分母取传播前组件仍有耐久的全部有效燃料列；分子取完整度归零且组件未耗尽的失效源列与本 tick 实际收到大于零未冷却传播热量的其他有效燃料列之并集，同一列只计一次。该比例达到至少 `20%` 时创建并保存 `meltdownCountdown`；空列、控制棒列和耗尽燃料均不参与比例，也不依赖传播历史标记。传播计算不得因遍历顺序、区块卸载或存档重载改变。
- 融毁倒计时的进度只允许增加。SCRAM 和有效冷却可以暂停当前倒计时，但不能回退进度、恢复归零完整度或让仍受损的列被视为安全；只有所有燃料列和控制棒列完整度都恢复到 `1.0` 时，才重置融毁状态和进度，危险条件再次成立时从原进度继续。
- 控制棒列完整度归零后控制棒卡死，保留卡死前实际插入深度，继续降低相邻燃料列反应速率，不接受滑块、SCRAM 或管理员调节，也不传播损伤。
- 损伤不扣除燃料组件耐久，换料端口不能补满完整度或清除热量传播。受损燃料列使用 `steel_plate`（显示名“合金钢板”）直接右键其 `reactor_refueling_port` 修复，且目标列必须停止放热；每块钢板修复 `0.25 / internalHeight` 的列完整度。控制棒列使用同一钢板右键其 `control_rod_drive` 修复。完全停机要求裂变、燃耗停止且余热进入安全区；之后可以拆除并重新成型，永久清空整个结构的内部 NBT。运行、融毁倒计时或暂停融毁倒计时期间拆除任何结构组件立即执行融毁动作。

## 6. 服务端配置项

第一版至少提供并验证以下有限非负配置：

- `controlResponseExponent`，默认 `1.0`；
- `baseHeatPerFuel`；
- `baseBurnPerFuel`；
- `burnHoursPerBlock`（如采用寿命配置表达，则与 `baseBurnPerFuel` 二选一，不能形成两个权威）；
- `overclockHeatMultiplier`，反馈产热硬上限，默认 `10.0`；
- `overclockBurnMultiplier`，反馈燃耗硬上限，默认 `10.0`；
- `overclockFeedbackGain`，默认 `0.15`；
- `overclockFeedbackExponent`，默认 `0.5`；
- `totalHeatMultiplierCap`，默认 `20.0`。
- `coolantAbsorptionHuPerMb`，每单位冷却剂可带走的热量；
- `coolantMaxFlowPerPort`，单个冷端/热端的基础流量上限；
- `fuelColumnDamageHeatThreshold` 和 `fuelColumnDamageRate`，燃料列有效热负荷损伤阈值与速率；损伤对发热/燃耗的倍率固定为 `2 - fuelColumnIntegrity`，不再配置两套不同反馈曲线；
- `fuelColumnDamageTransferRate`、`controlRodColumnFailureThreshold`、`meltdownTriggerFraction`（首发默认 `0.20`）和 `meltdownCountdownTicks`，失效列传播速率、控制棒卡死边界、融毁触达比例和倒计时长度；
- `fuelColumnRepairItem = steel_plate`，仅指定维修物品身份；显示名为“合金钢板”，每次维修固定消耗 1 块并恢复 `0.25 / internalHeight`，维修量和消耗量不作为可调配置。不得注册 `alloy_steel_plate` 别名。

P1 数值原型先使用以下可配置默认值；这些值用于验证玩法闭环，不代表最终平衡：

| 配置 | P1 原型默认值 | 说明 |
| :--- | :--- | :--- |
| `baseHeatPerFuel` | `1.0 HU/t` | 每个有效燃料棒方块的额定基础发热 |
| `burnHoursPerBlock` | `3 h` | 满功率、无超频、有效高度 1 的燃料寿命；与 `baseBurnPerFuel` 二选一 |
| `coolantAbsorptionHuPerMb` | `0.5 HU/mB` | 每单位冷却剂可带走的热量 |
| `coolantMaxFlowPerPort` | `128 mB/t` | 每个冷端或热端的独立流量上限 |
| `fuelColumnDamageHeatThreshold` | `0.25 HU/t` | 超过该净残余热量才开始降低完整度 |
| `fuelColumnDamageRate` | `0.0000005 / (tick·HU/t)` | 按阈值以上的净残余热量线性扣除完整度 |
| `fuelColumnDamageTransferRate` | `0.25` | 相邻失效燃料列当前残余热量的传播比例；燃料列与控制棒列相同 |
| `controlRodColumnFailureThreshold` | `0.0` | 控制棒列完整度归零时卡死 |
| `meltdownTriggerFraction` | `0.20` | 未耗尽失效源与本 tick 未冷却传播目标并集占有效燃料列的比例 |
| `meltdownCountdownTicks` | `900 ticks` | 45 秒融毁倒计时 |

反应堆不提供 `coolantTotalFlowCap` 或任何等价的全堆冷却剂流量配置。N 个互不重复的合法冷端和 M 个互不重复的合法热端分别提供 `N × coolantMaxFlowPerPort` 与 `M × coolantMaxFlowPerPort` 的理论上限；实际转换仍受两侧实际管网流量、可用发热、内部库存和热端背压共同限制。端口堆叠只增加可用吞吐量，不增加发热、燃耗或冷却剂库存，同一端口/连接不得重复计数。

正式流体库存仍以整数 `mB` 保存，但整数转化产生的不足 `1 mB` 热量余数不等于冷却能力不足。当冷库存、热端空间和有效吞吐足以覆盖全部热量时，该量化余数必须被守恒地缓存或累计，但不得降低任何列的完整度、作为失效传播源或触发融毁覆盖；只有超过理论冷却能力的真实未覆盖热负荷才按损伤阈值结算。不得通过静默删除热量、允许分数 `mB` 正式库存或简单提高损伤阈值规避该边界。

损伤倍率固定为 `2 - fuelColumnIntegrity`，不提供独立配置；合金钢板维修固定为每次消耗 1 块、恢复 `0.25 / internalHeight`，也不提供数值配置。其余反馈增益、超频热/燃耗硬上限和全堆产热倍率上限彼此独立。游戏实现仍以服务端配置为权威，原型测试后再调整默认值。

默认平衡回归锚点采用固定 `5×5×5` 结构、内部高度 3、中心空列和周围 8 个完整燃料列。每列有两个四向燃料邻居时，默认超频反馈稳定值约为 `4.161445`，全堆总发热约为 `99.87469 HU/t`，按 `0.5 HU/mB` 需要约 `199.74938 mB/t`：一组 `128 mB/t` 冷/热端口不能安全自持，两组端口合计 `256 mB/t` 可以覆盖需求；第三组端口的理论吞吐量必须能继续增加到 `384 mB/t`，不得被隐藏的 `200` 或 `256 mB/t` 全堆上限截断。

## 7. 信息显示

当准星指向 `reactor_instrument_port` 时，P1 第一批工程师护目镜浮动窗口只显示以下静态摘要：

- 已成型结构尺寸，按“宽 × 高 × 深”显示；当前固定实验堆为 `5 × 5 × 5`；
- 燃料列数量和控制棒列数量；
- 冷端口数量和热端口数量，按有效结构缓存中的唯一合法物理端口计数；
- 冷/热缓冲总容量，单位为 `mB`，严格等于 `coldInventoryCapacityMb + hotInventoryCapacityMb`，不是当前流体存量。

这些字段由服务端有效结构缓存和服务器配置派生，不在 `ReactorSnapshot` 中重复持久化；成型、结构重扫、方块实体加载或相关配置变化时更新，不因玩家持续观察而每 tick 扫描结构。结构无效时只显示明确的“未成型/数据不可用”，不得把缺失数据伪装成尺寸或计数为零。动态全堆库存、发热量和冷却剂转化速率已经按服务端最后一次成功 tick 接入仪表端口；逐列详情按现场归属显示在换料端口和控制棒驱动器。余热、总燃耗率、剩余燃料、倍率、瓶颈和预计安全时间仍属于后续仪表扩展。

当准星指向燃料列顶部的 `reactor_refueling_port` 时，浮窗增加该列局部信息：

- 端口内部组件的原版剩余耐久度、最大耐久度和剩余燃料比例；空端口显示“无燃料组件”；
- 该燃料列完整度与派生损坏度；
- 该列当前裂变发热量，单位为 `HU/t`，包含当前控制、超频和有效高度结算结果。

只有佩戴工程师护目镜才显示这些详细值；没有护目镜时不显示。组件耐久来自换料端口服务端同步的本地物品，即使端口暂未绑定或结构失效也可以显示；此时列完整度、损坏度和发热量必须明确显示为“结构数据不可用”。信息读取必须复用端口物品与结构缓存，不能因准星观察而每 tick 扫描整座反应堆，也不能在客户端自行推算耐久或热工数据。

每个控制棒浮动值框显示该棒的插入百分比。没有全堆统一深度滑块，也没有控制端口右键菜单。所有玩家都可以拖动逐棒目标深度，不得绕过同一服务端范围验证；拖动过程保持 Create 原版的本地连续手感，不按每个预览回包重写游标，最终提交或拒绝后再与服务端权威值一致。高电平 SCRAM 期间滑块只读，低电平解除后恢复 SCRAM 前保存的目标位置。控制棒驱动器不响应红石调节信号。

## 8. 反应堆 Ponder 教学合同

`experimental_reactor` 必须提供独立的 Create Ponder 入口，并至少包含以下连续场景：

1. **识别结构：** 从外壳、观察窗、冷/热端口和唯一 `reactor_instrument_port` 开始搭建；演示缺少仪表端口、重复仪表端口、冷/热端口错误时拒绝成型，并用工程师护目镜读取有效结构的尺寸、列数、冷热端口数、总流体容量、冷/热库存、全堆发热量和冷却剂转化速率。逐列详情不集中塞入仪表端口窗口。
2. **布置堆芯：** 放置燃料列、顶部 `reactor_refueling_port` 和 `control_rod_drive`；说明驱动器下方保持空列、控制棒不作为柱方块放置。
3. **正常运行：** 展示燃料组件装入、结构缓存生效、局部产热、余热和冷/热回路连接；不把示例动画当作服务端状态。
4. **局部控制：** P1 展示玩家使用驱动器浮动滑块调节逐棒深度、相邻控制棒独立深度、四向邻接和直接相邻燃料反馈；演示部分插棒连续压低反馈簇，以及完全插棒切断被覆盖燃料列的新生裂变热和燃耗。P2 再通过可选控制端口展示管理员服务端控制。
5. **SCRAM：** 向 `reactor_instrument_port` 输入并保持红石高电平，展示所有可动作控制棒插入、被控制棒覆盖的裂变产热切断和余热继续存在；撤去红石后展示控制棒恢复到 SCRAM 前位置。另展示无控制棒列时请求被拒绝且不能暂停融毁，以及存在未覆盖燃料列或控制棒卡死在未完全插入位置时的 `SCRAM_INCOMPLETE` 警告；明确 `reactor_control_port` 不是 SCRAM 状态所有者。
6. **损伤与应急：** 展示冷却不足导致逐列完整度下降、完整度降低导致发热/燃耗同比增加、燃料列归零后仍以 2.0 倍运行并持续沿四向传播至 20% 阈值，直至组件耗尽；展示控制棒列归零后卡死但仍按原插入比例抑制相邻燃料，且不继续传播。
7. **安全换料与信息：** 只有目标列裂变产热为零且相关控制棒完全插入，或燃料耗尽时才能换料；工程师护目镜指向换料端口时显示组件耐久、列完整度/损坏度和 `HU/t`，指向控制棒驱动器时显示其绑定控制棒列完整度；展示关键合成物品修复受损燃料列。
8. **破坏性重置：** 完全停机后拆除并重新成型，展示燃料、冷/热冷却剂、控制棒深度、缓存热量和所有列状态被清空；运行、融毁倒计时或暂停融毁倒计时中拆除任意组件则立即执行融毁动作，重装不能撤销事故。

Ponder 场景只能播放教学动画，不能直接写入燃料、控制棒或结构状态；所有允许/拒绝结果必须调用与实际交互相同的服务端规则。场景中的数值使用示意值或配置值，不能写死尚未通过平衡门的默认寿命、功率和阈值。
