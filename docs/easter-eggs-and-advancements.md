# 《机械动力：核工业》隐藏彩蛋与进度设计

**对应玩法文档：** [project.md](./project.md)  
**实施路线：** [implementation-roadmap.md](./implementation-roadmap.md)

本文集中记录不属于主科技树的趣味玩法、隐藏彩蛋和隐藏进度。这里的项目不会解锁配方或阶段，也不奖励物品、经验、应力容量或其他可影响平衡的资源。

## 1. 通用规则

- 隐藏进度只奖励实际完成触发条件的玩家；多人协作时，由服务器记录参与启动、控制或事故操作的玩家集合，并按各条规则授予。
- 同一进度只授予一次。重复触发可以保留局部音效或动画，但不反复广播全服消息。
- 功能型彩蛋、隐藏进度文字和客户端表演使用独立服务器配置开关；关闭后不得影响主线机组状态或既有存档。
- 彩蛋检测优先复用已有机组状态、结构缓存和事件，不允许为了进度每 tick 大范围扫描世界。
- 本文中的持续时间、功率上限、检测范围、辐射刻度和稳定运行窗口都必须由配置提供；实现算法不得写死平衡数值。
- 主线燃料状态按列管理：每个燃料列一个组件，燃料列有效高度影响基础消耗速度；彩蛋和进度只能读取服务器确认后的列级结果，不能自行按方块数量推导燃耗。
- 彩蛋和进度不得读取组件级温度或完整度；剩余燃料读取 ItemStack 耐久度，运行温度读取反应堆燃料列结果，`decayHeatHu` 在首发只作为预留回收资格标识。
- 工程师护目镜指向换料端口时显示燃料耐久、燃料列完整度/损坏度和当前发热量属于主线信息功能，不是彩蛋；彩蛋不得替代、覆盖或自行推导这些服务端列级数据。
- 进度与彩蛋不进入当前 P1 核心关键路径。可以在 G1 冻结参与者、燃料状态和事件名称后准备数据定义，但服务端触发器必须等对应运行事件稳定，最终实现与回归安排在 P4，不得反向阻塞 P1 核心或后续首发扩展。
- 主线控制棒的内容边界已经确定：不注册可放置的控制棒柱方块；只注册 `control_rod_drive` 驱动器方块，控制棒由驱动器渲染为无碰撞箱模型动画，下方保持空列。驱动器不接受红石调节，只允许玩家浮动滑块或烈焰人管理员改变深度；彩蛋或进度不得通过额外控制棒方块改变这一结构语义。
- 首发燃料耗尽直接形成 `COOLED_SPENT` 冷却乏燃料；不实现热/冷乏燃料转换、乏燃料池冷却或依赖这些事件的彩蛋。`HOT_SPENT` 仅为未来命名预留，隐藏进度不得假定它在首发运行中注册或生成。

## 2. 首发隐藏进度

### 2.1 “核电，轻而易举啊！”

玩家建立第一座稳定运行的核电站时授予。这里的“稳定运行”不是结构刚组装完成或汽轮机短暂转动，而是同一完整机组在配置规定的连续观察窗口内同时满足：

- 反应堆已装料并保持有效裂变功率；
- 冷却、给水、超临界汽轮机和换热器回水闭环均在工作；
- 机组对外提供正的应力输出；
- 反应堆、锅炉、超临界汽轮机和核换热器均未进入 `DANGER` 或 `TRIPPED`；
- 观察窗口内没有使用命令或创造模式直接注入燃料、冷却剂、蒸汽或回水。

通过合法换料端口进行的在线单列换料不视为创造模式注入，也不会自动清空稳定观察窗口；但观察窗口内机组仍须持续满足正裂变功率与正应力输出。换料只允许对全部相关控制棒完全隔离至零裂变产热或燃料耗尽被动停机的列进行，任何绕过端口或服务端安全判定的注入均使本次观察窗口失效。

进度 ID 建议为 `stable_nuclear_power_plant`。默认只授予完成启动或在观察窗口内操作过机组控制端口的玩家；具体稳定 tick 数由配置决定。

### 2.2 “坏了，坏了坏了。”

玩家参与控制的反应堆第一次进入不可逆的堆芯融毁状态时授予。普通过热、自动 SCRAM、可修复损伤或仅摧毁外围管道都不触发；必须由服务端反应堆状态机确认 `meltdown` 事件。

进度 ID 建议为 `first_reactor_meltdown`。授予对象为事故发生前配置时间窗口内启动反应堆、提高功率、解除联锁或操作关键控制端口的玩家；旁观者、后来进入区块者和仅参与清理者不获得。服务器关闭地形破坏时仍可触发，因为进度依据融毁状态而不是爆炸方块数量。

## 3. 趣味彩蛋与对应进度

### 3.1 “河反应堆”

玩家在没有通入蒸汽的情况下，将已组装的超临界汽轮机主体浸入流动水，并保持主轴输出端露出水面，水流会推动转子缓慢旋转并输出少量 Create 应力。首次成功运行时授予同名隐藏进度。

- 流动水必须接触配置规定数量的外壳或转子段；静止水、水箱和管道供水不触发。
- 输出使用整座结构的配置上限，不随汽轮机长度、水流方向或并排水流无限增长，默认不高于对应 Create 常规水力设备。
- 河反应堆不消耗核燃料、不产生蒸汽，也不计入“核电，轻而易举啊！”的稳定核电条件。
- 接入蒸汽后立即退出彩蛋状态，水流与蒸汽不能重复结算应力。

### 3.2 “高科技烧开水”

当反应堆通过核换热器为 Create 原版流体储罐锅炉提供超级加热，且该锅炉驱动贴附式 Create 蒸汽引擎时授予，副标题为“人类文明兜了一大圈”。

- 只播放一次短促水壶汽笛，不改变热级、锅炉效率或应力输出。
- 若烈焰人反应堆管理员已绑定机组，可在客户端短暂举起“所以还是烧水？”木牌。
- 一个有效核热模式换热器即可触发；额外换热器不是此进度的必要条件。

### 3.3 “3.6，不高也不低”

玩家首次使用手持辐射计测得读数跨过配置的 `3.6` 显示刻度时授予。这只是界面与文字彩蛋，不形成特殊安全区间。

- 辐射计继续显示真实读数和危险颜色，不锁死或截断更高剂量。
- 若读数继续快速上升，可追加“其实挺高的，快走”提示并播放一次盖革计数器爆发声。
- 该彩蛋不修改辐射伤害、防护、污染衰减或事故判定。

## 4. 配置项目

建议集中在服务端 `advancements` / `easterEggs` 配置段：

| 配置键 | 职责 |
| :--- | :--- |
| `advancements.enabled` | 是否允许授予隐藏进度 |
| `advancements.stablePlantTicks` | 稳定核电站所需连续运行时间 |
| `advancements.meltdownParticipantWindowTicks` | 融毁事故参与者追溯窗口 |
| `easterEggs.functionalEnabled` | 是否启用“河反应堆”等功能型彩蛋 |
| `easterEggs.clientPerformancesEnabled` | 是否启用木牌、特殊音效和动画 |
| `easterEggs.riverTurbineContactBlocks` | 河反应堆所需水流接触方块数 |
| `easterEggs.riverTurbineMaxSu` | 河反应堆整机输出上限 |
| `easterEggs.radiationMemeThreshold` | 辐射计彩蛋显示阈值 |

配置加载失败时使用集中定义并经过范围验证的默认值；存档只保存已授予进度与必要的连续运行/参与者状态，不保存配置副本。

## 5. 项目管理与实现边界

本文件由项目经理维护彩蛋的触发条件、非主线性质、配置开关和资源隔离；项目经理不实现触发器、客户端演出或进度 JSON。用户提出新的彩蛋时，先确认它不会改变主线资源、应力、燃料、事故和存档语义，再进入本文件与对应任务计划。

- 彩蛋不得抢占当前 P1 核心或后续首发扩展关键路径；只能在对应稳定事件已经存在、且能复用结构缓存和状态事件后排期。
- agent/开发者交付彩蛋时必须提供“关闭配置不影响主线”的负向测试，以及不增加资源/能量的验证证据；项目经理据此决定是否进入 P4 勾选项。
- 需求讨论、文档更新、任务拆分和 Git 交接统一遵循 [项目经理执行计划](./superpowers/plans/2026-08-17-project-manager-execution-plan.md)。

## 6. Ponder 与彩蛋的边界

- 多方块结构、单方块设备、管道/阀门/端口和可主动使用物品的 Ponder 属于主线教学，不属于隐藏彩蛋，也不得要求玩家先触发进度才能查看。
- Ponder 可以演示事故预警、SCRAM、屏蔽和错误操作，但演示只播放教学动画，不授予物品、经验、应力、燃料或安全状态，也不触发隐藏进度。
- 彩蛋场景可以引用 Ponder 已定义的结构和物品，但不得在 Ponder 中加入未注册的秘密方块、替代配方或改变主线输入输出的“教学捷径”。
- 若未来新增彩蛋内容也需要操作说明，应优先复用对应主线 Ponder 入口；只有不改变主线规则的隐藏表演才进入本文及 P4 任务。
